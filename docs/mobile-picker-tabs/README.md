# 모바일 게임 선택 패널 · 공용/플레이어 탭줄 수정 인계

작업일 2026-10-22. 작성: Claude(claude-opus-5-5). 범위는 두 UI뿐이다. 서버·shared·게임팩·명세·아트는 바꾸지 않았다.

## 바뀐 동작

### 1. 새 판 만들기 → 게임 선택
- **선택 버튼:** 밖에 따로 있던 "게임 찾기" 입력과 native select를 없애고 **"게임 선택" 버튼 하나**로 바꿨다. 버튼에는 지금 고른 게임 이름, 판본, 지원 수준이 보인다.
- **패널 열기:** 버튼을 누르면 같은 대화상자 안에 패널이 펼쳐진다.
  - 맨 위는 검색창이며 자동 포커스된다.
  - 바로 아래가 결과 목록이다. 각 항목에 이름, 판본, 지원 수준 배지, 선택 체크를 표시한다.
- **검색:**
  - 한국어 이름, 띄어쓰기 무시, 초성("ㅋㅌ"), 게임 ID, 판본으로 찾는다.
  - 카탈로그에서 카탄의 제목은 인쇄명 "CATAN"이라, 화면 검색에서만 "카탄/Catan" 별칭을 더했다. 이 별칭은 API로 보내지 않는다.
- **검색과 선택의 분리:** 검색은 목록만 좁힌다. 항목을 눌러야 선택이 바뀌고, 그때 패널이 닫히며 포커스가 버튼으로 돌아간다.
- **입력 초안 유지:** 기록 이름과 플레이어 입력은 검색·열기·닫기와 무관하게 유지된다.
- **결과 없음·지우기·닫기:**
  - 결과가 없으면 "‘…’와 맞는 게임이 없어요"와 "검색어 지우기"를 보여 준다.
  - 검색창 안의 × 버튼은 검색어를 지운다.
  - 패널 아래 "닫기 · (현재 게임) 유지" 버튼은 선택을 바꾸지 않고 패널만 닫는다. 버튼을 다시 누르면 패널이 다시 열린다.
- **키보드:**
  - Esc를 누르면 검색어를 먼저 지우고, 다시 누르면 패널만 닫는다. 대화상자 전체는 닫히지 않는다.
  - 검색창에서 Enter를 눌러도 **판이 만들어지지 않는다.** 결과가 하나뿐이면 그 게임을 고른다.
  - ↓/↑로 결과 사이를 이동한다.
- **대화상자 구조:** 중첩 모달을 만들지 않고 기존 대화상자 안에 펼쳤다. 그래서 포커스 가두기와 스크롤 잠금이 하나뿐이고 서로 충돌하지 않는다.
- **목록 높이:** `min(42dvh, 340px)` 안에서 따로 스크롤된다(`overscroll-behavior: contain`). 화면 키보드가 올라와도 검색창과 목록을 쓸 수 있도록 한 설계다.
- **터치 영역:** 버튼 64px, 항목 56px, 지우기·닫기 44px 이상.
- **API 계약:** 그대로다. 생성 요청은 고른 카탈로그 항목의 `gamePackId`와 고정 `gamePackVersion`만 보낸다(`createRequest`). 검색 문자열은 게임 ID로 보내지 않으며, 알 수 없는 ID는 거절한다.

### 2. 편집기 위 "공용 보드 / 플레이어" 탭줄
- **원인:**
  - `overflow-x:auto`만 지정하면 CSS 규칙상 `overflow-y`도 auto로 계산된다.
  - 각 탭 버튼의 `margin-bottom:-1px`와 3px 밑줄 때문에 내용이 1px 아래로 넘쳤다.
  - 그 결과 탭줄 안에 세로 스크롤 범위가 1px 생겨, 터치하면 탭줄이 위아래로 움직였다.
- **수정 내용** (`src/correction-workspace.css`):
  - `overflow-y:hidden`을 지정했다. 빌드 결과는 `overflow:auto hidden`이다.
  - 음수 여백과 밑줄 테두리를 없애고, 선택 밑줄을 `inset box-shadow`로 그렸다.
  - `overscroll-behavior-x: contain`을 지정했다.
  - 키보드 포커스 테두리는 잘리지 않도록 안쪽(`outline-offset:-3px`)에 그렸다.
- **세로 스크롤 보존:** 전역 `touchmove` 차단이나 `touch-action:none`은 쓰지 않았다. 탭줄에서 세로로 밀면 본문이 그대로 스크롤된다.
- **긴 이름:** 플레이어 이름이 길면 탭마다 `max-width:72vw` 안에서 말줄임으로 표시한다. 탭이 많아도 가로로 밀어 모두 닿을 수 있다.
- **선택 탭 위치:** 선택이 바뀌면 탭줄만 **가로로** 움직여 선택 탭을 보이게 한다. 페이지의 세로 위치는 건드리지 않는다.
- **유지한 동작:** 탭 누르기, 선택 표시, PIN 잠금 아이콘, 현재 차례 표시, 소유자 변경 전 저장(flush)은 기존 그대로다. 탭 버튼과 클릭 처리는 바꾸지 않았다.

- 실행 중인 프로세스: `/tmp/kb-mobile-preview.pid`에 적힌 PID(93034). 실제로 4398을 듣는 node 프로세스는 93056이다. 종료는 `kill $(cat /tmp/kb-mobile-preview.pid)`로 하고, 남으면 93056도 종료한다.

## 확인하지 못한 것 (정직한 한계)
- **실제 화면 확인 안 함:** 이 세션에는 CUA·브라우저 도구가 없다. 360/390/430/320/1440 화면 캡처, 실제 가로 넘침 측정, 탭줄의 computed 축 확인, 화면 키보드가 열린 상태의 동작은 **직접 보지 못했다.** 스크린샷은 없다.
- **실제 손가락 스와이프 미확인:** 실기기 터치는 확인하지 않았다. 원인과 수정은 CSS 규칙과 빌드 결과로만 확인했다.
- **화면 낭독기 미확인:** 실제 읽기는 확인하지 못했다. 구현한 접근성 표시는 아래와 같다.
  - 버튼: `aria-expanded`, `aria-controls`
  - 목록: `role=listbox`, `option` + `aria-selected`
  - 결과 수: `aria-live`
- **영어 이름 검색 한계:** 일반 118종의 영어 이름 검색은 지원하지 않는다. 카탈로그 DTO에 영어 이름이 없기 때문이다. 백엔드 변경 없이 넣으려면 게임별 아트 매핑 파일을 따로 받아야 한다.

감독 CUA 확인을 권하는 순서:
1. 390px 등에서 "새 보드" → 게임 선택 → "ㄹㅁ" 입력 → 루미큐브 탭
