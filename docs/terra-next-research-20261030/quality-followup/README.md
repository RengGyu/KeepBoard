# 품질 후속: 연결 완료와 판독 품질 완료를 나누기

2026-10-30 · Astra/max · 제품 변경/새 API 호출 0.

**현재 결과는 자동 복원을 충분히 맡길 품질이 아니다.** 50/109와 개별 회수128/235에 대한 우려는 정당하다. Terra 연결은 필요한 기반 작업이지만 품질 문제의 해결이나 서비스 완성을 뜻하지 않는다. 수동 정정 가능성을 이유로 이 격차를 작다고 표현하지 않는다.

조건을 정확히 하면 50/109는 **부분 crop 시험이 아니라, 전체 사진에 속성 안내 문장+Lanczos 확대를 함께 적용한 시험**이다. 이 차이는 낮은 품질을 변명하는 근거가 아니라 다음 실험의 변수를 정하기 위해 필요하다.

|---|---:|---|---|

개별 물체의 107개 미회수는 **Carcassonne 타일14 + Cascadia 타일21 + Ticket to Ride 열차72**다. 다른 여섯 게임의 이 부분 기준은 전부 대응됐다. 그러나 그 밖의 물체·속성을 다 읽었다는 뜻은 아니다.

원응답을 보면 Carcassonne의 큰 `tiles / quantity:null` 한 상자가 기준 타일14개를, Cascadia의 `habitat / quantity:null` 한 상자가21개를 포함한다. 열차72개도26개는 수량 있는 묶음 상자,46개는 quantity:null 상자 안에 있다. **이는 완전한 위치 미검출과 구별되는 ‘넓은 덩어리만 읽음’**이다. 이 중심 포함 계산은 원인 진단일 뿐 동일성 증명·정답 회수 점수·제품 규칙이 아니다. 묶음의 수량·구간을 정확히 보존한 경우에는 묶음도 유용할 수 있으나, 현재 열차 wire에는 색 두 필드만 있고14행은 수량도 null이라 개별 배치 복원을 대신했다고 볼 수 없다.

오독5의 세부는 Quacks 숫자 기준1→응답2 한 건, Sagrada 기준6→응답4 세 건·2→1 한 건이다. **고정 AI 부분 기준 대비**이며 사람이 인증한 정답은 아니다. 원사진3장(Quacks/Sagrada/Cascadia)을 직접 확인했지만 이 연구에서 해당 값을 새 정답으로 확정하거나 기준을 고치지 않았다. 글자 크기·반사·투명 주사위/옆면·모델 판독 중 어느 원인이 지배적인지는 **UNKNOWN**이다.

텍스트361필드는 별도다. 정확 문자열 일치162, 다른 관측 문자열33개는 기존 채점에서 `observed-unjudged`이며 모두 오답으로 세지 않는다. 반대로 문자열 표현 차이를 이유로 위5개 숫자 오독을 면제하지 않는다. 개별 대응은 reciprocal IoU 기준이고 quantity:null/0도 후보로 허용하므로128 자체가 완전한 개별 실물 정답률도 아니다.

## 최소 품질 패키지 — 우선순위가 달라져야 한다

### QG. 밀집 실물을 개별 관측으로 보충하고, 수량 모르는 묶음도 정직하게 연결

**대상:** Carcassonne·Cascadia·열차처럼 독립 물체를 큰 상자로 묶은 장면. 기존 사진의 읽을 수 있는 경계가 부분 사진에서 더 잘 전달되는지 확인한다. 사진별 기대 개수·좌표나 inventory로 나누지 않는다.

**코드 공백 VERIFIED:** `server/observationFusion.ts`의 `aggregateCandidates`/`manualAggregates`는 quantity>1만 묶음으로 취급한다. quantity:null에는 단일/묶음/미정이 섞여 있어 일괄 group으로 바꾸면 안 된다. 같은 source의 crop에서 개별 물체를 읽어도 이 null 큰 상자를 올바르게 정제했다고 보장할 수 없다. 이는 값 판독과 별개인 연결 문제다.

**작은 변경 계약 RECOMMENDATION:** Terra wire에 관측 주장 `physicalUnit: single | group | unknown`을 추가하는 후보를 만든다. 수량과 분리하고, group이어도 수량은 null일 수 있다. 기존 저장값·기존 응답은 이 표시가 없으면 unknown으로 취급한다. `quantity:null→1` 또는 `null→group` 강제 변환은 금지한다.

- 실제 추가될 Terra builder/decoder: 이 구분과 nullable 속성을 반환·검사한다. 별도 Terra wire version으로 두고 기존 Gemini 응답 형식은 유지한다. GT나 기대 수량을 주지 않는다. 단일 물체로 보이지 않는 것을 single로 강제하지 않는다.
- `shared/lightweightRecognition.ts`의 **receipt/wire 선택 메타데이터**에 ref별 구분을 보존한다. 기존 Observation/팩 판본을 대량 재발행하지 않는다. decoder가 raw item→observation ref 대응을 만든다.
- `server/observationFusion.ts`: 기존 quantity>1 또는 **명시 group 주장**일 때 기존 partial refinement 경로를 재사용한다. 같은 원본/owner/epoch/영역, 알려진 crop transform, 서로 다른 개별 child·유일한 부모 대응을 요구한다. `identity`/child 판별은 기존 quantity1 또는 충돌 없는 explicit single만 허용하고, 같은 source와 기하 대응 조건은 유지한다. single+quantity>1 같은 모순은 unit unknown으로 보류하되 원수량은 남긴다. single+quantity:null을 수량1로 채우지 않는다. unknown을 개별 동일성의 증거로 사용하지 않는다.
- 원문 부모·미관측 나머지·대안은 남기되, child를 편집 가능한 실물로 회수한 경우 큰 부모를 동시에 개별 실물로 중복 계수하지 않는다. `exhaustive:false`, 잔여 수량null 유지. 사용자 수정/삭제/배치한 부모는 자동 교체하지 않는다.

기존 `PhotoDialog`의 crop 선택·`prepareScanObservation` source transform을 사용한다. 새 촬영 마법사나 모든 프레임 재판독은 필요 없다. 먼저 **기존 선택된 부분 사진을 제대로 소비**한다. 자동 crop 추가 발행 정책은 이번 작은 패키지의 전제조건이 아니다.

**무과금 수용:** explicit group+quantity:null→동일 원본의 single child가 실제 편집 목록에 회수되는 합성 회귀; unknown-null은 추정 분할하지 않음; 인접 동일색·겹친 부모·crop 경계 잘림·빈 bbox·다른 source·수동값·순서 역전·재전달·저장 재열기에서 중복/소실 없음. 기존 실제 응답에는 새 marker가 없으므로 이를 연구자가 채워 개선 실적으로 세지 않는다. 물체 회수 이득은 후속 실제 요청에서만 판단한다.

### QN. 숫자 오독은 같은 물체의 가독성 시험으로 다루기

원문 숫자5개가 이미 틀렸으므로 normalizer가6/4·1/2를 룰에 맞춰 바꾸면 안 된다. 같은 원본에서 **물체 전체와 주변 맥락을 포함하는 영역**을 읽어 숫자·눈을 비교한다. 숫자만 잘라 주변 칸 인쇄나 주사위 옆면과의 구분을 없애지 않는다. 원본에 없는 선·점을 디지털 확대가 복구한다고 가정하지 않는다.

`server/scanObservation.ts`의 source/crop/target 경로와 `server/observationFusion.ts`의 속성별 provenance를 재사용한다. 기존에 틀린 것으로 알려진5개를 제품에서 특별 취급하지 않는다. 실제 사용자 선택 또는 관측 간 충돌을 근거로 보충하며 매 사진 자동 이중 호출을 만들지 않는다. 부분 사진이 원본과 다르면 `focused-provisional`의 **임시 선택/대안**이지 정답 인증이 아니다. 사용자 직접 값은 보존한다. 같은 값 두 번도 정답 증명은 아니다.

원본에서 글자가 해상도/반사로 사라졌다면 더 가까운 정지 사진이 필요한지 **선택 안내**하고, 모름·원사진·수동 수정·미배치로 저장 가능하게 둔다. 실제 더 나은 근접 사진이 없으면 이 경로의 품질은 UNKNOWN으로 남긴다.

### QS. required-schema는 출력 누락 방지로 범위를 제한

base9에는 허용 속성142행 생략이 있었지만 **보강9에는 생략0**이다. 따라서 기존 Q1의 종류별 nullable 필수 key는 baseline의 누락·형식 변동을 줄일 후보이며, **현재 남은59필드(오독5/모름5/미검출49)의 해결책으로 세면 안 된다.** 필수 key를 null로 채우는 것은 시각적 회수가 아니다. 구현 중인 Terra 코드에서 flat↔strict 변환을 같은 domain/unknown으로 유지하고, 숫자를 강제하거나 일부 종류를 없애지 않는다.

현재 `observationAssembly.ts`의 명시 face 복원은 이미 있으므로 재구현하지 않는다. 기존18응답의749개 관측 값 보존 검사는 계속 회귀 기준으로 쓰되 품질 합격으로 부르지 않는다.

## 다음 판별 시험: 최대4 요청 제안, 이번 실행0

현재 잔여 실패에 직접 답하기 위해 **앞선 Q1 schema 전용4회보다 아래4회를 우선하는 대체 제안**이다. 두 시험을 자동으로 연속 발행하지 않는다. 요청·유료 실행 권한은 이 연구에 없다.

**Cascadia와 Sagrada 각 한 장**: 같은 Terra 후보 계약으로 전체1회와 부분1회, 총4회·retry0. ROI는 각각 앞쪽 연결 타일 영역/앞쪽 주사위 판 영역을 **사진의 물리 경계로**, 새 출력 전에 고정한다. 정답 박스별 oracle crop·오독 위치만 골라내기·GT 개수 주입은 하지 않는다.

- 같은 model/effort/detail/output limit, 종류·속성 범위, wire를 유지한다. **외부 업스케일을 함께 바꾸지 않는다.** 원본/ROI bytes·좌표·SHA를 고정하고 원본까지의 변환을 기록한다. QG marker를 시험한다면 두 조건에 동일하게 적용한다.
- 비교 분모는 공통 ROI 안의 기존 부분 기준이다. 온전한 물체와 경계에 잘린 물체를 나눠 놓고 잘린 항목을 몰래 제외하지 않는다. ROI 고정 전후의 기준표는 고치지 않는다.
- 개별 child 회수/묶음 잔존, 숫자 정오/모름/누락, 잘못된 연결·중복, **최종 편집 가능한 객체·값**을 각각 센다. provenance나 unresolved에만 많이 남은 것은 회수 성공이 아니다.
- raw→decoded→fusion→저장 재열기를 보며 provider 시간·토큰과 정정 부담을 분리한다. crop1회가 추가되면 비용도 증가한다. 단일 쌍의 변동과 기존 개발 표본이라는 한계를 남긴다.
- crop이 다시 묶음만 내거나 숫자 오독을 줄이지 못하면 재시도 반복·추가 모델/전게임 crop 확장을 멈춘다. 형식 누락/경계 잘림/실제 가독 정보 부족 중 무엇인지 기록하고, 필요한 경우 실제 근접 사진 한 세트의 확보를 다음 요구로 남긴다. 임의 전체 합격률은 만들지 않는다.

**완료 표기를 분리한다:** ‘Terra 연결 완료’ / ‘이 개발 사진의 품질 변화 확인’ / ‘실사용 복원 가능성 미확인’. 연결 작업을 계속할 수 있지만 현재 품질이 충분하다는 표현은 하지 않는다.
