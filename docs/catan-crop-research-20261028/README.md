**권고: 현재 모델에서 ‘같은 관측 과제의 원본 대 크롭’을 먼저 비교한다.** 제한된 병렬 크롭은 유망하지만, 원본 좌표 복원·중복 처리·전체 문맥 보존까지 묶어 검토해야 한다. 문헌만으로 기본 인식 경로를 바꾸거나 보드게임 정확도 향상을 확정할 수 없다.

작업 카드의 **순차21.67초 / 병렬8.87초 / 원본 full-task45.67초는 REPORTED**이며 이번 연구에서 재측정하지 않았다. 앞의 두 값은 동시 실행의 가능성을 보여주지만, 마지막 값과는 클래스·canonical placement·수동 ROI 선택까지 달라 **크롭만의 효과는 미분리**다.

## KeepBoard 적용 판단 — INFERRED / RECOMMENDATION

- **크기와 겹침:** 원본에서 잘라야 입력에서 작은 숫자·말의 비중이 커진다. 이미 흐리거나 축소돼 사라진 획은 크롭으로 복구되지 않는다. 경계 물체가 다른 타일에서는 완전히 보이도록 여유 영역을 두되 큰 카드/보드가 잘릴 수 있다. 최적 overlap·타일 수는 미확인이다.
- **원본 좌표:** 원본 SHA/EXIF 방향/크기, crop 사각형, 리사이즈·패딩·회전을 기록한다. 무패딩 crop 정규화 좌표(u,v)는 원본 pixel에서 (x0+u×cropWidth, y0+v×cropHeight)다. 다른 변환은 기록된 역변환을 적용한다. 모델의 실제 좌표 오류는 이 수식이 고쳐주지 않는다. 사진 box와 게임 슬롯을 동일시하지 않는다.
- **중복:** 원본 공간에서 같은 물리 종류·레이어와 위치·속성의 일관성을 비교한다. 색/숫자가 같다는 이유만으로 합치지 않는다. 지형 위 숫자, 카드 위 말은 겹쳐도 서로 다른 물체다. 충돌한 값을 평균·다수결·재고에 맞춰 확정하지 말고 출처와 함께 남긴다.
- **전체 문맥:** 원본은 검토·복원의 기준으로 유지한다. crop 위치 메타데이터만으로 소유자나 연결 관계를 읽었다고 할 수 없다. API에 전체 thumbnail도 같이 주는 안은 문맥에 도움이 될 후보지만 반복 입력 비용이 생긴다. 우선 비교에 섞지 말고 별도 변수로 둔다.
- **실행:** 순차 시간은 대략 전처리+요청시간의 합+병합, 모두 동시에 수용될 때의 병렬 시간은 전처리+가장 느린 요청+병합이다. 큐·전송 경합·rate limit 때문에 실제는 더 길 수 있다. **병렬화는 벽시계 시간을 줄일 수 있지만 토큰을 자동 절약하지 않는다.** 겹침·반복 프롬프트·전체본의 입력과 모든 출력/추론 usage를 합산한다. API Batch 할인과 실시간 동시 호출도 별개다.

위는 논문에서 직접 검증한 게임판 설계가 아니라 S1–S8을 바탕으로 한 적용 제안이다. 지금 선택지는 ①원본 유지, ②제한된 겹침 크롭 병렬 판독, ③타일+overview를 한 요청에서 공동 판독이다. **②를 작게 비교하되 ③이나 새로운 모델 도입을 선행조건으로 만들지 않는 것**을 권한다. 숫자 판독 개선만으로 카드 정체성·소유·보드 관계·재개 성공까지 인정하지 않는다.

## 최소 후속 비교 제안 — 실행 0

**사진2장 × (원본1요청 + 크롭 순차4요청 + 같은 크롭 병렬4요청) = 최대18요청**, 실패 포함/retry0. 기존 사진1장과 다른 실제 Catan 상태·구도1장을 사용한다. 자동 확대 실험이나 HIGH/새 모델 비교는 포함하지 않는다. 실제 실행은 이 연구 권한에 포함되지 않는다.

1. **같은 과제 고정:** 세 군 모두 지형·숫자토큰·도로·마을·도시·도둑의 literal 종류/값/색/사진box만 요구한다. canonical 위치·소유·턴 추론은 모두 제외. 같은 endpoint/version/LOW/schema/출력 정책을 사용한다. full-task45.67초는 참고로만 남긴다.
2. **같은 원본/크롭 고정:** 원본에서2×2 사분면을 만들고 내부 경계를 원본 폭·높이의5%씩 확장하는 한 설정만 사전 고정한다. 이는 시험 시작값이지 최적값이 아니다. 순차·병렬군은 동일 이미지 bytes와 요청을 사용한다. GT를 보고 개별 토큰을 잘라주는 oracle ROI는 쓰지 않는다.
3. **정답 분리:** 추론 전에 원본 물체별 실제 box/종류/읽히는 값을 고정한다. 숫자토큰의 위치를 타일 중심점으로 대체하지 않는다. 흐림/가림은 unknown, 경계 물체는 별도 표시한다. 서로 겹친 크롭을 독립 사진 표본으로 세지 않는다.
4. **따로 측정:** 값 정답·누락·환각·중복·원본box 대응, 전처리/요청/병합/전체 wall, 총토큰/비용, 실제 수동 선택·정정·저장 시간을 각각 남긴다. 실패/출력 잘림을 정상 완료로 세지 않는다.
5. **해석/중단:** 원본↔순차크롭은 과제를 맞춘 ‘크롭 전략’ 비교이며, 추가 토큰·문맥 변화까지 포함한다. 순차↔병렬은 스케줄링 비교다. 두 사진 각1회로 p95나 보편적 속도배수를 주장하지 않는다. 오류·중복·정정 부담이 늘면 wall 단축만으로 채택하지 않는다.18회에서 종료하고 필요한 변수만 후속 제안한다.

현재 미확인: Flash 실제 이미지 budget/내부 타일 처리, 적정 크롭 크기·overlap, 수동 ROI의 기여, 전체 관계·저장복원 품질, 다른 게임 일반화. 입력/출력 요금 상한은 후속 실행 시 정확한 endpoint·토큰 한도에 맞춰 정해야 하며 여기서 임의 단가를 제시하지 않는다.

구조화 근거·조건·한계는 [research.json](research.json)에 담았다. ECC deep-research의 근거/추론 분리 원칙을 적용했고, 전용 검색 도구가 노출되지 않아 제공 web 도구를 사용했다. 제품·개인 원본·기존 보고서는 수정하지 않았다.
