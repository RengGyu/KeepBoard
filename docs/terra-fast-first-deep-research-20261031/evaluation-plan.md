# 추천을 지지하거나 기각할 최소 비교

**상태: 제안만 작성. 이번 연구의 신규 모델 호출·OCR 추론·설치 0.** 과거 유료 실험 승인을 이 계획의 실행 승인으로 간주하지 않는다.

## 1. 무엇을 결정할 것인가

1. 전용 로컬 판독이 폰에서 실제로 빨리 유용한 문자/위치 증거를 주는가?
2. 그 증거로 선택한 ROI가 whole-low의 최초 미검출과 known 오독을 회수하는가, 불필요한 high만 늘리는가?
3. 생성 좌표·반복 구조를 줄인 국소 task가 같은 복원 정보를 유지하면서 시간을 줄이는가?
4. 최종 human-corrected restoration까지 포함하면 whole-high와 현재 whole-low보다 나은 선택인가?

최초 비교는 하나의 아키텍처 패키지를 평가한다. OCR·ROI 선택·prompt 축약 중 어느 하나가 단독 원인이라고 주장하지 않는다. 원인이 더 필요할 때만 아래 후속 ablation을 별도 승인 범위로 요청한다.

## 2. 입력과 정답 고정

- 개발 자료: 기존 10게임/3사진은 회귀·threshold/adapter 개발에 사용하고 **개발셋**이라고 표시한다. 같은 원본의 crop은 독립 사진이 아니다.
- 독립 비교: **4개의 새로운 원본/서로 다른 정지 상태**를 최소 묶음으로 제안한다. 인쇄 숫자+기하(Catan), 반복 타일/말(Carcassonne), 숫자와 색의 별도 난점(Sagrada), 카드 문자/아이콘·더미(Splendor 또는 가용한 같은 범주 게임) 각1장이다. 기존 공개 corpus에서 실제 미노출 SHA가 확인되는 사진을 먼저 찾는다. 찾지 못하면 새 동일상태 촬영 자료가 필요하다고 명시한다.
- 새로운 4사진이라도 통계적 일반화 표본은 아니다. 판본·해상도·광학 가독성·전체판/개인영역·이전 실험 노출을 기록한다. 모델 출력 전에 사진·전체 평가영역·ROI selector 코드/버전·기준을 동결한다.
- 각 사진에서 **선언된 평가영역의 보이는 물체를 전수** 주석한다. one/surface-of-group/partially-occluded를 구분하고, 인쇄값·윗면 pip·글자·색·관계의 가독성을 따로 기록한다. 판 전체를 다 주석하지 못하면 `평가영역 내` 정밀도/재현율이라고 표시한다. 일부 1–4개 표본으로 전체판 정확도를 계산하지 않는다.
- 실제 사람의 독립 확인이 없으면 AI 부분 기준으로 표시한다. 애매한 값은 unknown이다. 같은 모델 답으로 정답을 만들지 않는다. hidden stack/hand/turn history는 사진 GT에서 제외하고 보존·질문 경로로 평가한다.

## 3. 먼저 무과금 로컬 시험

PaddleOCR.js small을 실제 브라우저에서 cold와 warm으로 실행한다. 설치/가중치 다운로드는 실행 카드의 범위로 명시한다. 최소 M1 데스크톱과 대상 휴대폰 1대를 구분하고, 모바일 부재 시 desktop만 verified로 둔다.

기록할 것:

- 실제 runtime/backend/버전, 모델 asset SHA, download bytes, 초기화/검출/판독/매핑 시간, 메모리 실패·워커 오류. 예열시간을 추론시간에서 숨기지 않는다.
- text polygon recall/precision, 빈 rec polygon 보존, 문자열·숫자 정오/unknown/누락, 6/9·회전·작은 인쇄값, 물체 경계와 text 경계의 혼동.
- 원본 픽셀 수와 crop 픽셀 수, 실제 업스케일 여부. 디지털 확대가 광학적으로 새 정보를 얻은 것처럼 설명하지 않는다.
- whole 의미 판독이 없을 때 놓치는 비문자 물체. 물체가 하나도 검출되지 않으면 빈 판이라고 확정하지 않는다.

모든 detector가 실패한 사진도 분석에서 제외하지 않는다. 로컬 지연이 길거나 OCR이 시각 정보를 잘못 연결하면 browser-first 기본안을 기각하거나 해당 종류에서만 보조로 제한한다. 임의 성공률을 만들어 합격시키지 않는다.

## 4. 이후 요청할 수 있는 제한된 유료 비교 카드 — 미실행

```text
TASK: 4개 동결 새 원본에서 whole-low, whole-high, 전용증거+선택 보강 비교.
MODEL: 동일 gpt-6.1-terra. 공개 모델/서비스 기본 설정 변경 없음.
CONDITIONS:
 A: 현행 whole-low 1회.
 B: 같은 whole / 같은 body에서 effort만 high 1회.
 C: 별도 whole-low 1회 + 출력 전 동결한 local selector로 ROI high 0–2회.
    C의 low body는 A와 동일. 국소 task/범위 차이는 명시하며 crop-only 인과를 주장하지 않음.
LIMIT: 총 최대20요청(4×(1+1+1+2)), 각claim1회, retry0.
       peak2, 계획요금 환산 총$5 이내를 제안. 실행 승인은 별도.
       비용은 입력/출력/cache 조건의 사전 예약과 실제 usage로 관리.
       6.1 Terra 이미지 token 상한이 공식표에 없으므로 $5를 실제 청구 보장으로 말하지 않음.
       사전 최대 예약이 넘으면 실행 전에 축소. 첫 transport실패면 즉시 중단.
INPUT: 동일원본/SHA/판본/owner/epoch. GT·정답수량·좌표를 요청에 넣지 않음.
OUTPUT: raw/receipt/최종편집값/호출이유/선택되지 않은 영역/실패 모두 보존.
DECISION: 필요한 복원 정보, known오독·미검출·잘못된연결, 총정정부담과 대기의 tradeoff.
```

C는 처음부터 근거가 있는 ROI를 base와 겹쳐 시작하고, low 이후에만 생긴 reason은 한 번의 잔여 예산에서 실행한다. 앞선 ROI와 같은 작업을 재발행하지 않는다. A/B/C 실행 순서는 게임마다 교차 배치하고, 한 번씩이므로 공급자 변동의 영향을 명시한다. C의 local 단계를 포함한 wall을 직접 재며, 과거 A와 D 시간을 더한 것으로 실측을 대체하지 않는다. high-only 출력이 길다고 임의로 짧은 cap을 줘 baseline을 잘리게 하지 않는다.

한 요청에 여러 사진을 넣는 안은 이 첫20회 안에 끼워 넣지 않는다. 먼저 유용한 ROI가 확인되면 같은 이미지·task를 가진 **개별 ROI 요청 vs 복수 이미지 요청**만 따로 비교한다. compact output 자체의 인과가 필요하면 고정 ROI의 full/compact 두 계약을 비교하는 최대8회(4쌍)를 별도 제안하며 자동으로 이어 실행하지 않는다.

## 5. 지표와 분모

| 구분 | 측정 | 잘못 해석하지 않을 것 |
|---|---|---|
| 물체 회수 | 평가영역 내 실제 single/surface별 recall·precision, group 표현을 별도 매칭 | group1행을 숨은 N개 정답으로 세지 않음. ROI밖을 ROI누락으로 세지 않음 |
| 속성 | 가독 숫자/문자/색/종류 각각 정답·오독·모름·물체누락·미판정 | 숫자 unknown을 맞힌 값에 포함하지 않음. 색 필드를 중복해 정확도 부풀리지 않음 |
| 위치 | 실제 footprint/지지점·source 변환·slot 대응 각각 | GTtile center 포함만으로 숫자 오독으로 판정하지 않음. OCR text box는 physical bbox와 별도 |
| 결합 | raw회수→editable회수, 중복·오연결·parent/group 경쟁·사용자값 손실 | unresolved에 보관된 수만 늘어난 것을 자동 복원 이득으로 보지 않음 |
| 라우팅 | 선택된 ROI에서 고친 문제 수, 빠뜨린 known오독·미검출, 불필요한 호출 | confidence높음/unknown적음을 정확함의 대용으로 사용하지 않음 |
| 대기 | capture/scan end→first overlay→first editable save→all terminal | 첫 token·첫 overlay·완성판을 같은 지표로 쓰지 않음 |
| 복원 | 실제 정정 동작·소요시간·정정 후 잔여오류; 가능하면 실물 정리 후 재배치 | 사람이 실제 수행하지 않으면 정정시간은 UNKNOWN. 디지털 모사만으로 실물 복원 완료 주장 금지 |
| 비용 | 실제 input/output/reasoning/cache usage, per-request·전체wall, 실패 요청, local download/CPU | 환산액과 청구서, 단일request와 batchwall, raw토큰과 reasoning 부분집합을 분리 |

수정 UI를 실제 사용한 사람에게 “필수 정정 완료”를 강제하지 않고 자연스러운 저장까지의 행동을 기록한다. 물리적으로 복원 불가능한 hidden 상태는 사진 판독 실패율에 섞지 않고 필요한 질문/실물 보존 경로가 살아 있는지 확인한다.

## 6. 오프라인 회귀와 판정

기존 실응답은 회귀로 사용한다. 순서 역전·동일응답 재전달·동일 원본 다른crop·동일겉모양 인접기물·다른 owner/epoch·사용자 값·사용자 삭제·null/0·group 분해 후 parent 재등장·저장재열기를 유지한다. 알려진 crop 충돌에서 정상 whole값을 픽셀 면적만으로 교체하지 않는지 확인한다. 모델 실험과 저장 회귀 결과는 따로 보고한다.

추천을 지지하는 증거는 **새 사진의 실제 복원 작업에서 더 빨리 유용한 편집 상태를 제공하면서 중요한 관측 손실·오연결·정정 부담을 늘리지 않는 것**이다. 숫자 합계만 좋아지고 최초 미검출이 늘거나, local 예열 때문에 첫 결과가 늦거나, high ROI가 거의 매번 필요하다면 기본안을 재검토한다. 소수 사진의 차이로 120게임 합격률·지속적인 p95 속도를 선언하지 않는다.

이 비교 후 사진을 보고 selector나 threshold를 고치면 그 사진은 개발셋으로 재분류한다. 새로운 독립 검증 없이 같은 네 사진의 개선을 일반화 성과로 보고하지 않는다.
