# 실제 게임사진 판독 실패 연구

2026-10-23 확인. **현재 실패는 한 원인으로 설명되지 않는다.** 숫자·종류·개체 누락은 모델 원응답에 이미 있으며, 사진상의 위치를 저장판의 칸으로 바꾸는 기능은 일부 계약에서 의도적으로 수동이다. 짧은 관측 프롬프트로 바꾼 신규 6회도 주요 속성을 일관되게 개선하지 못했다. **B 프롬프트 일괄 도입이나 모델 이름만 바꾸는 해결책은 권하지 않는다.** 당장은 선택 영역을 작게 읽고 쉽게 정정하는 흐름을 유지하며, 배치 연결을 별도 구현하고, 인식기는 다른 비전 모델 1개와 제한 비교하는 순서가 타당하다.

검토 대상은 [동결 소스 manifest](../game-state-linking/integration/source-manifest.json)의 `0255142408c9035805725fdb74c2a93b9679c81458acd18f2358c9240d8cfe7d`이다. 1,346파일 해시를 확인했다. 공유 소스 적용·외부 배포·현재 사용자 Catan 화면은 서로 다른 상태이므로 이 결과를 현재 운영 요청 전체의 진단으로 바꾸지 않는다. 이 연구의 제품·설정 수정과 직접 모델 호출은 모두 0이다.

**어디서 실패했는가 — VERIFIED, 제한된 4사진**

원본 바이트와 실제 gateway/provider 요청을 재구성하여 저장 해시와 대조했다. 네 응답 모두 HTTP 200·완료 JSON이며, provider 최종 JSON과 raw가 같다. 그 뒤 정규화·앱 사용 가능 값까지 추적했다. 원본을 직접 보고 기존 사전 GT를 변경 없이 사용했다. [전송·보존 근거](evidence.json), [속성 대조 및 한계](semantic-audit.json).

**새 A/B 6회가 구분해 준 것**

A는 기존 앱 프롬프트, B는 게임명·보이는 개체·색/인쇄값·사진 박스만 요구한다. 이미지·모델·high·detail high·출력 상한 32,768은 같다. B에는 GT·정답 수량·게임 slot·소유자·턴 추론을 넣지 않았다. 프롬프트 길이뿐 아니라 과제와 출력 형식을 함께 바꾼 비교다. 신규 세 게임의 A 요청 바이트는 앞선 4회 실험의 해당 요청과도 동일했다.

| 게임 | A → B 응답 완료 | 핵심 속성 | 별도 관측 |
|---|---|---|---|
| Catan | 114.90 → 122.03초 | 행 대응 지형 17/19 → 14/19, 숫자 14/18 → 14/18 | B가 도로 20·마을 5·도시 2를 더 반환했지만 전체 개체 대응 미확정. 도둑은 양쪽 누락 |
| Splendor | 112.71 → 113.95초 | 시장 점수·보너스와 귀족 점수가 양쪽 모두 null | 코스터 토큰 오인 A4→B0. 일부 토큰 색 대응은 개선. 주요 카드 값 해결은 아님 |
| Sagrada | 68.99 → 32.62초 | 색 17/17 양쪽, 눈 8/17 → 7/17 | B는 빈 노란 인쇄 칸을 주사위 1개로 추가(value null). 이번 A/B 박스는 실제 주사위 17개 중심 모두 대응 |

Catan의 **엄격한 박스 중심 대응**은 별도다. 지형 정답 A13/B12(각 16개 대응), 숫자 정답 A4/B5(5/7개 대응)로 낮다. 이를 위 행 대응 점수와 섞지 않았다. Sagrada의 앞선 요청에서 나온 약 45px 어긋남은 이번 동일 A 요청에서 재현되지 않았다. 고정 y 보정으로 해결하면 안 된다. 같은 입력에서도 결과가 달라지므로 한 번의 출력이나 한 모델의 자신감으로 안정성을 보증하지 않는다.

6회 모두 요청·GT·raw 해시와 provider→raw 일치를 직접 검증했고, 별도 집계 코드로 strict 대응을 재계산해 worker 집계와 차이 0이었다. 원본/overlay도 직접 보았다. [독립 A/B 근거](ab-review.json), [실행 원기록](../photo-observation-ab/README.md). 각 조건 1회이고 A에만 캐시 적중이 있었다. 순서·캐시·서버 큐 효과는 분리할 수 없다. B는 앱 계약이 아니며 저장 성공을 시험하지 않았다. 승인된 신규 6회는 소진됐고 추가 호출은 없다.

**시간·비용과 실행환경**

앞선 4회는 65.46–123.46초이고, 측정된 gateway 전체 시간의 99.981–99.994%가 provider 왕복이다. 정규화는 1.45–5.77ms였다. 출력 78,449토큰 중 추론 60,605토큰이며 요청별 출력의 73.6–83.3%다. 출력 비용이 보수적 peak 계산의 약 96.5%를 차지한다. **입력 프롬프트만 짧게 하면 빨라진다는 근거는 없다.** 신규 Catan B는 입력 4,075→716토큰으로 줄어도 출력 21,346→23,857토큰과 시간이 늘었다.

신규 6회 입력 11,471 / 출력 111,219 / 추론 90,708토큰. 전입력을 cache miss로 잡은 peak 환산은 **$0.1369041**, 보고된 cache hit를 적용한 peak 환산은 $0.134382756다. 실제 청구서·시간대 할인·세금은 확인하지 않았다. 기존 4회는 같은 방식으로 $0.0975879다. [공식 가격](https://api-docs.deepseek.com/quick_start/pricing/)과 [요청별 수치](ab-review.json)를 분리해서 사용한다.

이 시간은 휴대폰 촬영부터 운영 UI 반영까지의 시간이 아니다. provider 내부 큐·첫 토큰·순수 추론 시간, 실제 Vercel/터널/휴대폰 업로드는 미측정이다. 백그라운드 job·재접속은 기다리는 경험을 개선하지만 이 숫자 오독이나 upstream 대기 자체를 고치지 않는다. 스트리밍을 적용해도 완료 전 JSON을 확정하거나 추론 내용을 사용자에게 보여주지 않는다. [Responses API](https://api-docs.deepseek.com/guides/responses_api/).

[MMVP 논문](https://arxiv.org/html/2401.06209v2), [BlindTest 논문](https://arxiv.org/html/2407.06581v6).

**120게임에 미치는 범위**

[game-impact.json](game-impact.json)은 정확한 120 ID·판본/출처 연결·실제 읽기 경로와 수동 필드를 기계 추출했다. Catan/Rummikub native 2, Splendor 전용 1, typed 117이다. typed 117종의 구성물 분류 418개, 필드 1,800개 중 visible 1,295/manual 505개다. 117종 모두 수동 필드를 포함하고, 92종에는 숫자/기호 필드가 있다. 첨부 명세 기반 115종과 공식 부분 대조 2종을 전부 공식 검증으로 올리지 않았다.

- 공통: 같은 비전 경로의 작은 기호·누락·박스 오차 가능성과 nullable 값 처리, 사진과 판 좌표 분리는 전파된다. **전파되는 것은 구조적 위험이지 실측 오답률이 아니다.**
- 격자/공간 게임: Sagrada cell, Carcassonne gridX/gridY·연결처럼 관측 가능한 배치와 현재 manual 상태의 차이를 먼저 다뤄야 한다.
- 카드·타일: Splendor 점수/보너스/비용, Rummikub 색·숫자·그룹, SCOUT 인쇄 위/아래 값과 activeEnd·손패 순서처럼 관찰값과 플레이 상태를 구분한다.
- 505개 manual을 통째로 visible로 바꾸지 않는다. 소유자·비밀패·턴 이력은 사진에서 확정할 수 없는 것이 많다. 4사진과 신규 3쌍으로 나머지 게임의 정확도는 UNKNOWN이다.

| 5. 근접 사진/ROI·회전 정규화 비교 | 좁은 영역의 실제 세부가 늘어나는지 확인. 원본의 잃은 픽셀은 확대해도 복원 안 됨 | 대상 선택·추가 사진이면 처리량 증가. 영역별 무제한 fan-out 금지 | 작은 실험 가능. 디지털 crop과 실제 근접 촬영을 구별 |
| 후순위. 전용 OCR/주사위 검출·학습 | 특정 모양/숫자에 유리할 가능성. 별도 실물 학습/검증 자료 필요 | 로컬 추론 가능성은 있으나 하드웨어·실측 없음 | 큼. 처음부터 120종별 detector/카드 사전을 만들지 않음 |

기존 다른 3사진의 원본/ROI 6회에서는 Splendor가 35.20→11.40초로 빨라졌지만 비교 속성 정답이 10→9로 줄었고, Sagrada 눈 오독은 남았다. 따라서 ROI 자동 일괄 적용의 근거가 아니다. 이 수치는 [기존 실행 기록](../game-state-linking/evaluation/README.md)을 확인한 것이며 이번 4사진과 같은 자료라고 합치지 않았다.

배치 연결은 사진의 기준 평면과 방향을 먼저 확인해야 한다. 사각 격자의 모서리 4점을 사용자가 빠르게 확인하고 사진→판 변환을 후보로 제시하는 것이 작은 시작이다. 높이 있는 말·가림·움직인 판은 평면 변환만으로 해결되지 않는다. Sagrada의 과거 45px 오차를 상수로 고치거나 사진 bbox를 곧바로 canonical slot으로 간주하지 않는다. [OpenCV 평면 변환 근거](https://docs.opencv.org/4.13.0/d9/dab/tutorial_homography.html).

구현 경계는 다음 정도로 제한한다. `generic.ts`/`scenePrompt.ts`/`rummikubPrompt.ts`에서 관측 과제를 만들고, `gameReadouts.ts`와 별도 순수 어댑터에서 앱 ID·요청 근거·수동값을 채운다. 관측 레코드는 `photo SHA + crop transform + class + literal observed attributes + bbox + unknown`을 유지한다. 사진-frame 기반 배치 후보는 수동 placement와 구분해 `shared/readouts`/`GameBoardRecord`/`SceneWorkspace`에 연결한다. 공개사진의 소유자 추론, null→0, 수량→비용, 게임 재고로 누락 채우기는 하지 않는다. 기존 owner/epoch·명시 적용 경계를 유지한다.

자료는 대형 규칙 사전보다 **판본이 맞는 실제 사진과 읽을 수 있는 속성/영역**이 필요하다. 타일/주사위/카드/선 연결 등 형상별로 시작하고, 같은 사진의 crop을 학습용과 검증용으로 나눠 독립 사진처럼 계산하지 않는다. 촬영자·물리 판 상태별로 분리한 미사용 사진에서 확인한다. AI 출력에 맞춰 GT나 규칙 기반 자동 정답을 바꾸지 않는다.

**모델 선택: 확인된 능력과 미확인을 분리**

선정 기준은 **① 작은 인쇄값·밀집 개체·공간 대응을 시험할 충분한 이미지 처리 능력 ② 독립 모델 계열과 공식 이미지/구조화 출력 지원 ③ 실제 계정 접근 및 요청 계약 ④ 정확도와 함께 측정할 지연·비용** 순이다. 저렴함이나 Flash/Sol 같은 이름으로 선택·배제하지 않는다. 공식 일반 능력 소개만으로 주사위 눈·카드 비용이 더 정확하다고 결론 내리지 않는다.

다음 진단의 우선 후보는 **GPT-6 Astra**다. 강한 독립 모델을 비교해 현재 인식기 계열의 한계를 가려 보려는 선택이며, 이미지 입력과 해상도 처리, Responses/구조화 출력이 공식 문서에 있고 기존 Responses 어댑터를 활용해 전송 형식 변경을 작게 유지할 수 있다. 작은 글자·정밀 공간 판단의 한계도 공식 문서가 명시하므로 개선은 미검증이다. 해상도 지원이 품질을 보증하지 않으며, 현재 작은 원본에서 사라진 정보를 복원해 주는 것도 아니다. **다음 최소 실험 — 제안만, 승인/실행 0**

새 키가 허용되면 **Splendor/Sagrada 고정 2사진 × 현재 Flash/GPT-6 Astra = 최대 4요청(실패 포함), retry 0**을 먼저 제안한다. GPT 접근이 안 되고 Gemini 4 Argon 접근이 가능하면 후보만 사전에 바꾸어 같은 비교를 한다. 둘 다 실행하는 카드가 아니다. B 관측 과제와 원본 SHA·사전 GT·unknown·출력 32,768 상한을 고정한다. provider별 적법한 high 설정과 실제 모델/effort·이미지 detail·usage를 기록하며, 같은 high 이름이 같은 연산량이라는 주장은 하지 않는다. 후보의 출력 좌표 형식은 미리 고정한 어댑터만 적용한다. 제품 적용/운영 alias 교체는 분리한다.

- 분모: Sagrada 실제 17개 색/눈과 추가 허위 개체; Splendor 시장 보너스 12·고신뢰 점수 10·귀족 점수 3. 중간 점수 2는 보조, 완전 비용 GT는 없음. 박스 대응 불명을 정답/오답에 억지로 넣지 않고 분모에 남긴다.
- 성공 판단: 알려진 속성의 **정답 수가 늘고 오독·허위 개체가 늘지 않는지** 게임별로 확인한다. null을 많이 채운 것 자체는 성공이 아니다. 한 게임만 좋아지면 전체 교체하지 않는다. 응답 유효성·raw 정확도·앱 저장 가능성은 별도 결과다.
- 시간/비용: 업로드 준비·provider 왕복·가능하면 첫 토큰·JSON 처리·정규화·후보 반영을 따로 기록. input/output/reasoning/cache와 실패 비용도 포함. 같은 요청을 실패 후 자동 재발행하지 않는다.
- 예산 제안: 입력/출력 각각 32,768 이내라는 전제하에 DeepSeek 2회+GPT-6 Astra 2회는 `2×32768×(0.30+1.20+10+50)/1e6=$4.030464`, 별도 승인 상한 $4.10. Gemini 4 Argon 대안이면 현재 가격으로 $0.884736, 상한 $0.90다. **품질 진단 모델을 먼저 고른 뒤 비용을 승인하는 순서**이며 낮은 비용만으로 대안으로 낮추지 않는다. 계획 상한에는 입력 토큰 사전 보수 계산/제공자 확인과 출력 hard cap이 필요하다. 예상 실제 청구액이나 승인된 예산이 아니다.
- 개선이 나오면 튜닝에 쓰지 않은 다른 실제 사진으로 최소 확인한다. 이번 두 사진은 이미 여러 번 본 진단 표본이라 일반화 증거가 아니다. 개선이 없으면 prompt를 계속 늘리거나 반복 호출하지 말고 입력 근접도/반사/회전 또는 좁은 전용 검출을 다음 한 변수로 선택한다.

새 provider를 쓰지 않기로 하면 기존 키에서 한 읽기 구획의 원본/ROI만 같은 과제로 최대 2회 비교하는 대안이 있다. 공급자 전처리·문맥도 달라지므로 해상도만의 효과라고 부르지 않는다. 이 역시 별도 승인 전 실행하지 않는다. **현재 조건으로 가장 확실히 가능한 제품 개선은 원본 대조·부분 정정과 사진→판 배치 연결이며, 자동 숫자 인식 개선은 아직 검증해야 할 목표다.**
