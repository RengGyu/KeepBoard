# KeepBoard 구현 인계

결과: 카탄 기준 모바일 대응 웹 앱. 촬영 → 게임팩 요구사항 → 필요한 질문/보관 → 저장본 → 재개 흐름을 연결했다. 구현솔·구현솔2·잡무루나의 기존 세션을 사용했고 아스트라·클로드는 호출하지 않았다.

## 구현 범위

- 카메라 미리보기의 안정된 화면 자동 촬영과 중복 장면 건너뛰기, 사진 가져오기.
- 원본 확대·영역 잘라내기·재분석. 크롭은 원래 촬영 시점과 출처를 이어받는다.
- 카탄 게임팩 v1.1.0: 상태 38개, 요구사항 19개, 도출 규칙 14개, 보관 템플릿 8개.
- 공용/플레이어별 상태·질문·메모와 참여 링크. 각 참여자의 화면 단계는 독립적이다.
- 기존 근거 확인/새 촬영/질문/실물 보관/저장 중 다음 행동 안내.
- 원본이 없는 숨은 사실, 처리 중인 효과와 완료/남은 하위 처리 기록.
- 손패 입력 대신 실제 묶음 보관, 이번 턴 구매 카드 분리, 덱 순서 유지.
- 디스크 저장, 원본을 포함한 JSON 내보내기·가져오기, 고정된 게임팩과 스냅샷.
- 저장본으로 재개 시 차례·턴·원본·메모·묶음 복구. 보드의 의미 있는 상태 비교.
- Gemini/OpenAI 이미지 분석과 규칙 원문 기반 게임팩 생성 연결. 설정 없이 예시/수동 흐름 사용.

## 근거

- VERIFIED: TypeScript·프로덕션 빌드, 테스트 19개.
- VERIFIED: 브라우저에서 예시 생성, 질문 답변, 세 플레이어와 공용 보관 위치, 14개 묶음 기록, 스냅샷 저장, 재접속·재개 브리핑, 새 기사 카드의 동일 턴 제한 표시.
- VERIFIED: 이미지 API의 요청 형식과 근거 연결은 로컬 응답 서버로 확인했다.
- UNKNOWN: 실제 API 키가 없어 실제 모델의 실물 사진 판독·게임팩 생성 결과는 실행하지 않았다. 실제 휴대폰 카메라 동작도 별도로 확인해야 한다.

## 읽을 코드 세 곳

### 1. `gamepacks/catan.ts` — `catanPack`

- 중요성: 게임별 차이를 선언형 자료로 표현하는 위치.
- 이전: 규칙과 상태·질문 정의가 없었음.
- 이후: 상태·조건·질문·도출·보관 의존성을 같은 팩에 둠.
- 핵심: `preservationId`가 있으면 내용을 전부 입력하는 대신 해당 묶음 보관으로 요구사항을 해결할 수 있음.
- 실패 사례: 팩에 필요한 상태가 없으면 실행기가 그 게임의 누락을 자동으로 알아낼 수 없음.

### 2. `server/engine.ts` — `recompute`

- 중요성: 사실 → 조건 → 누락 → 도출 → 다음 행동을 계산하는 공통 실행기.
- 이전: 실행기 없음.
- 이후: 답을 바꾸면 오래된 도출값이 사라지고 필요한 질문이 다시 계산됨.
- 핵심: 같은 게임 턴은 앱 재접속으로 바뀌지 않음. 보관 여부는 이미 기록한 실제 수량을 덮어쓰지 않음.
- 실패 사례: 조건의 입력이 미확인이면 분기를 확정하지 못하므로 질문으로 남음.

### 3. `server/index.ts` — `/commit`, `/resume`

- 중요성: 저장 요청과 실제 저장본, 현재 초안과 재개 기준을 연결하는 위치.
- 이전: 저장·재개 경로 없음.
- 이후: 실제 스냅샷을 만들고, 재개는 최신 저장본의 내용과 턴을 복구함.
- 핵심: 복원 사진은 새 촬영 시점에 속해야 하며, 예전 원본을 자른 것만으로 현재 관측이 되지 않음.
- 실패 사례: 실제 모델 키가 없으면 판독을 만들지 않고 수동/예시 경로로 남음.

흐름: **사진·답변·묶음 → 팩 조건과 실행기 → 저장본 → 같은 턴의 재개 안내**.
