# 경량 결과 전체 검토와 카탄 대체 판정

**현재 경량 A 결과로 기존 카탄 방식을 전면 대체할 수 없다.** 사진에 보이는 지형·숫자 외 물체도 상당수 찾았지만, 항구 두 종류가 틀렸고, 건물 유형/항구 접점/기계적으로 사용할 자리 연결을 확정하지 못했다. 현재 범용 편집기 미구현과 소유자·그룹·교환 공백도 실제 코드 probe로 확인했다. 사진 후보 초안으로는 유용하지만, 카탄 기능을 유지하려면 공통 사진 UI와 최소 C 확장이 모두 필요하다.

이는 최초 사전 기준표를 수정한 점수가 아니다. **동결 기준표는 그대로** 두고, 사용자 추가 요청에 따라 공개 원본 전체를 다시 확대해 **사후 사람 검토**를 별도 기록했다. 초기 “최소 정정 3개”는 철회된 상태다. 아래 항구 오류 2개는 전수 crop 검토로 새로 확인한 다른 근거이며, 철회한 양/밀 오인 주장과 다르다. 기존 카탄 arm의 응답은 없어 직접 정확도 우열은 여전히 미확정이다.

## 항구 9개와 대표 오류

| 출력 ID / 위치 | 사진에서 직접 검토한 종류 | 모델 | 비율 판정 |
|---|---|---|---|
| harbor-1 / 왼위 | 일반 | 일반3:1 | 일치 |
| harbor-2 / 위 | 양 기호 | 양2:1 | 일치 |
| **harbor-3 / 오른위** | **회색 광석 기호** | **일반3:1** | 종류 불일치. 아주 작은 비율 글자는 확정하지 않음 |
| harbor-4 / 오른쪽 | 일반 | 일반3:1 | 일치; 부두 한 끝은 빨간 건물에 일부 가림 |
| harbor-5 / 오른아래 | 벽돌 | 벽돌2:1 | 일치 |
| harbor-6 / 아래오른쪽 | 일반 | 일반3:1 | 일치 |
| harbor-7 / 아래 | 노란 묶음 밀 다발 | 밀2:1 | 일치. 사전 양 기준 오류를 명시적으로 정정한 사후 판독 |
| **harbor-8 / 아래왼쪽** | **일반3:1 표시, 광석 기호 없음** | **광석2:1** | **종류·비율 불일치** |
| harbor-9 / 왼아래 | 통나무 | 나무2:1 | 일치 |

`harbor-3`과 `harbor-8`을 모델이 서로 바꿔 읽었을 가능성은 있지만, 그것을 실제 생성 원인으로 확정하지 않는다. 독립적으로 확인한 최소 수정은 **항구 종류 2곳, 그중 비율도 1곳**이다. 위 광석 비율은 규칙상 2:1이어야 한다는 지식을 사진 판독 결과로 대신하지 않았다.

모든 항구에서 주변 부두 쌍을 검토했다. 8곳은 주변 원본에 두 부두가 보이고, 오른쪽 한 곳은 건물로 일부 가린다. **모델 출력에는 해안 edge·두 vertex·연결 참조가 하나도 없으므로 9쌍 모두 기계적 접점 확인 불가**다. 이미지의 부두/접점처럼 보이는 픽셀을 카탄 canonical 슬롯으로 추정 변환하지 않았다. 항구에 접근하는 건물 소유자와 교역비율을 이 A 출력으로 계산하면 안 된다.

## 물체·영역·관계 검토

- **도로 두 불확실 항목:** `blue-road-2`는 높은 파란 건물 일부인지 별도 세로 도로인지, `white-road-3`은 밝은 경계선인지 솟은 흰 도로인지 보류한다. 다른 16개 도로는 실물과 색이 보인다. 18개 모두 주변 타일 경계를 기록했으며, 불확실 두 항목의 경계 관계는 실물 독립성 확인 전 조건부다.
- **마을/도시 14개:** 건물 존재·색·대략 교차점과 주변 지형은 확인했으나, 이 세트에서 큰 조형/세로 돌출부가 어느 유형인지 확실한 기준 사진이 없다. AI의 도시/마을 라벨을 정답으로 되돌려 쓰지 않았다. 소유 설치물 점수/재고를 확정할 수 없는 중요한 미확인이다.
- **원본 연결:** 67/67이 실제 제공 photo ID와 유효 영역을 참조한다. 65개는 해당 물체/항구 표시/카드가 영역에 보이고, 도로 두 개는 색 있는 부분은 보이되 독립 대상 여부가 미확인이다. 이 수치는 완전한 물체 윤곽 분리 정확도가 아니다.
- **다른 대상 혼입:** 지형 crop 19개에는 타일 경계의 다른 말/도로 조각이 함께 보인다. 오른쪽 항구 crop에는 빨간 건물 일부, 아래왼쪽 건설비 crop에는 다른 카드 일부가 있어 **다른 물체/조각 포함은 최소 21개**다. 문맥 crop으로는 유용하지만 독립 부품만 잘라낸 정밀 segmentation 결과로 쓰면 안 된다. 다른 영역도 회전/사진 가장자리 때문에 완전한 개체 경계 보장은 없다.
- **면/부착:** 공개 카드 앞면은 보이지만 `face` 필드는 전부 없다. 숫자는 각 타일 `number`로 한 번씩 기록되어 중복 수량은 없으나 `attachedToId` 관계는 없다. 다른 공개 카드가 실제로 부착됐다는 확정 증거는 없어 임의 관계를 만들지 않았다.
- **방향/숨은 상태:** 별도 방향/덱 순서/보유 수명/차례/비공개 카드 내용은 미관측이다. 이 사진 한 장으로 확인 불가능하며 성공 항목에 세지 않았다.

## 현재 코드에서 의미가 보존되는가

`full-contract-probe.mts`가 실제 67개 출력을 현재 helper/Store에 넣었다. 결과와 최초 예상이 달랐던 항목도 직접 실행 결과로 고쳤다.

| 경로 | 직접 실행 결과 |
|---|---|
| 실험 중간형 `label`/`notes`를 그대로 v2 정규화 | ID 67/숫자18/수량/색/영역은 유지. 이름 label 67개·notes 67개는 기존 키가 아니어서 없어짐 |
| 기존 `note`로 label/notes를 연결한 최소 오프라인 adapter | 이름67·관계 메모·구조화 number18·근거/소유색/수량/영역 유지. 임시 Store 저장/재읽기 및 스냅샷 동등 |
| 일반 unknown 소유자 일괄 변경 | no-op 재현. 공통 편집 분기 수정 필요 |
| 두 일반 부품 다중 삭제 | 2개 삭제, 원래 장면은 유지. 실제 다중선택 UI는 이번에 구현/검증하지 않음 |
| 일반 unknown 두 개를 같은 edge로 이동 | 둘 다 moved, 같은 자리에 겹침. 도로 교환이 아님 |
| 카드 6장 그룹 | 이름이 달라도 part-8/같은 owner로 한 그룹에 묶임. 개별 카드 선택 보존 필요 |
| 이 출력의 항구 접근/교역 | 실제 harbor kind/edge가 없어 접근0, 정확 비율 complete=false. 은행 기본4를 항구 없음 확정으로 오해하면 안 됨 |
| 별도 합성 Catan C 장면 | typed road 두 개 원자적 교환, 실제 해안 endpoint의 집 접근, 목재2/다른자원4 helper 통과. 이 자리들은 사람이 합성한 것이며 사진에서 추론한 것이 아님 |

숫자 18개는 현재 정규화에서 **사라지지 않는다**. 다만 unknown용 현재 UI가 `usesNumber`로 전용 숫자 입력을 숨기므로 데이터 유지와 쉬운 숫자 편집은 다르다. 최초 adapter가 숫자를 note만으로 내보내던 부분도 오프라인에서 구조화 number를 함께 보존하도록 보완했다. 제품의 범용 온보딩을 구현한 것은 아니다.

## 기능 대체 최종 분류

| 기능 | 분류 | 유지하려면 정확히 필요한 것 / 확인 범위 |
|---|---|---|
| 원본/세션/스냅샷/개인메모/고정 팩 저장 엔진 | **그대로 대체 가능인 공통 기반** | 기존 Store 기능 재사용, 실제 출력 v2+합성 개인 상태 roundtrip 확인. 전체 UI 동등 뜻은 아님 |
| 공용 기록 1개 + 개인 사진/보유/메모 | **공통 UI 추가 필요** | public/owner 필드 각1개 계약 통과. 실제 PhotoSceneEditor/개인 카탈로그 분기 필요 |
| 사진에서 쉬운 이름·수량·숫자·색 정정 | **공통 UI 추가 필요** | label/notes→note adapter, 팔레트 이름 표시, unknown 소유자 편집, 숫자 표시/편집 |
| 3열 묶음/개별 카드/다중선택/undo | **공통 UI 추가 필요** | 카드·타일 개별 ID/이름 기준 그룹, 사진 선택 UI와 기존 불변 편집 transaction 연결. 다중삭제 helper만 직접 확인 |
| 깨끗한 카탄 그림판·타일/말 슬롯·즉시 추가/교환 | **카탄 최소 확장 필요** | 실제 terrain/road/settlement/city 등 typed kind, 자원 variant, 확인된 canonical hex/edge/vertex. crop 좌표를 슬롯으로 대신 쓰지 않음 |
| 항구 접근/2·3·4 교역/중단 기록 | **카탄 최소 확장 필요** | harbor kind/resource/ratio, 정확 해안변 양 끝, 건물 subtype/owner/vertex, coverage. 현재 A에는 필수 구조 없음 |
| 자원·개발카드 종류별 보유/숨은 승점/보유수명 | **카탄 최소 확장 필요** | 기존 C 개인 필드/전용 수량 폼/조건 유지. 숫자2개와 사진 카드목록으로 대체 불가 |
| 이번 사진의 도로 전수 독립성/건물 subtype/항구 접점 | **현재 미검증** | 모호 도로2, 건물14 유형, 접점9쌍. 원본 해상도/물체 기준 부족 |
| 기존 방식 대비 정확도·성공까지 속도 | **현재 실패 또는 미검증** | 기존 arm 파싱 전 원문 미보존·실패. 추가 API 금지로 재측정 없음 |

작은 C 확장은 새 전체 규칙엔진이 아니다. **typed 구성물/확정 슬롯/항구 접점/기존 개인 필드에 잇는 adapter와 기존 C 모듈 유지**가 최소다. 이것 없이 A 출력만 현재 카탄 UI에 밀어 넣으면 소유 편집 실패·카드 합쳐짐·도로 겹침·항구 계산 부재가 생긴다.

## 필요한 추가 사진과 남은 한계

원래 카메라 해상도의 전체판, 오른위 광석 항구의 작은 비율/양 부두와 오른쪽 가려진 접점, 파랑 세로 부품/흰 경계의 근접 정면, 그리고 이 실물 세트의 확실한 마을/도시 하나씩을 비교할 사진이 필요하다. 없는 정보를 현재 crop 확대나 게임의 기대 구성 개수로 채우지 않았다.

최소 확정 수정은 항구 2곳이다. 추가로 도로2/건물 유형14/항구 연결9쌍은 확인·연결해야 C 기능이 된다. 이것을 UI 클릭수나 수정 시간으로 바꾸어 말하지 않는다. 실제 UI 수정 시간은 미측정이다.

## 실행 근거

```sh
node --import tsx docs/lightweight-catan-trial/full-review.mts
node --import tsx docs/lightweight-catan-trial/export-v2.mts
node --import tsx docs/lightweight-catan-trial/full-contract-probe.mts
```

최종 세 명령 **exit 0**. 계약 probe의 첫 예상 중 “number가 없어질 것”, “unknown 이동이 거절될 것”은 실행에서 틀렸고 실제 **숫자18 유지 / 이동은 허용하지만 겹침**으로 고쳐 기록했다. 파서 후속 전체 테스트 **138/138**, typecheck/build **exit 0**은 [원인 진단 문서](parser-diagnosis.md)에 있다. 실기기/현재 범용 사진 UI/실제 AI 추가 호출/배포는 하지 않았다.
