# 기능 동등성: 사진 기본 A와 카탄 확장 C

**판정 기준:** A는 사진 위 기록이며 카탄 평면 그림판과 동등하지 않다. 이번 임시 하네스는 일반 프롬프트/입력 검증/저장만 구현했다. 아래의 “재사용 가능”은 새 UI가 이미 작동한다는 뜻이 아니다.

| 현재 카탄 기능 | A에서 유지할 수 있는 기반 / 오프라인 확인 | C 또는 추가 구현 | 이번 확인 경계 |
|---|---|---|---|
| 공용 보드 하나 | 공용 `components.observed` 한 필드 | 사진 대표보기/전환 PhotoSceneEditor 분기 | 팩 한 필드 확인, UI 미구현 |
| 개인 보유·개인 사진·메모 | owner별 필드 하나, Session.notes, 기존 Evidence | 일반 개인 카탈로그/소유자 필터 | 합성 개인메모 저장 유지. 실제 개인 사진 미사용 |
| 사진 정정·원본 crop | evidenceId+region+수량+관측색 | crop 선택/경계 정정/후보 수락 UI | 출력 좌표/근거 형식 검사. 실제 정정 시간 미측정 |
| 동종 묶음·3열 목록 | 수량/색 데이터 재사용 | 사진 모드 그룹 규칙; 다른 카드 ID 보존 | 모바일 UI 미실행 |
| 다중선택·undo | 기존 transaction 설계 재사용 가능 | 일반 unknown/token 소유자 편집 경로 필요 | 이번 하네스는 편집 UI/undo 미구현 |
| 자리 선택 즉시 추가 | 사진 영역 없는 목록 추가는 A 가능 | 정해진 hex/edge/vertex 추가는 C | A에 canonical 슬롯 없음 |
| 자리 이동·원자 교환 | A에서 사진 crop 수정은 이동과 다른 행위 | 카탄 topology+sceneMoves 유지 C | A 단독 미지원 |
| 지형/숫자/도로/건물의 평면 그림 | A는 실제 사진/crop 그대로 보여줌 | 기존 ComponentArt+SceneEditor C | A 단독 동등하지 않음 |
| 항구 인식 | 읽히는 아이콘/비율을 이름·메모로 기록 가능 | 해안변/양 접점·독립층·교환 C | 사진 정보만 공통 비교; 접점 미지원 |
| 항구 기반 4/3/2 교역비율·중단기록 | 일반 메모는 가능 | CatanSummary/항구 소유 계산·전달 기록 C | 숫자 두 항목으로 대체 불가 |
| 자원·개발카드·숨은 승점 전용 입력 | 선택 숫자/개인 카탈로그 기반 | 종류별 전용 수량 폼/조건/보유수명은 C | 경량 2카운터는 기존 전문 폼 동등 아님 |
| 소유색과 플레이어 연결 | 관측색, ownerId 보존 가능 | photo 모드 공통 색 연결 UI/일괄 정정 | 일반 정규화는 미확인 owner null 유지 |
| 차례·선택 맥락 | 선택 currentPlayer, notes | Catan turn phase/기사·7/개발카드 조건 C | 사진에서 차례 추정 금지 |
| 명시 저장·그대로 재열기·원본 유지 | Store/Session/Snapshot 공통 | 새 모드 생성 API·UI 분기만 연결 | 양쪽 임시 Store roundtrip 확인 |
| 저장본/개인정보/팩 버전 호환 | 별도 팩 ID, 당시 gamePack 고정 | 기존 카탄을 A로 자동 이주하지 않음 | 실제 사용자 저장본 접근·변환 없음 |

**필요 수정 묶음(시간 미측정):** (1) `capture` 타입/프로필 생성 API와 게임 생성 진입, (2) 사진 편집·일반 카탈로그·숫자 입력 UI, (3) 일반 프롬프트/정규화/중복·범위 분기, (4) 일반 소유자·그룹 편집, (5) 저장/재열기 연결. 카탄 C 모듈은 유지해야 위 전용 기능이 남는다. 새 게임별 코드나 기하 DSL을 이번에 만들지 않았다.
