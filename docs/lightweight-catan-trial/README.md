# 경량 카탄 비교 실험

후속 진단: [기존 카탄 arm 응답 실패 분석](parser-diagnosis.md). 아래의 “제품 변경 0”은 최초 두 호출 비교 당시 기준이며, 후속 요청에서 응답 판독의 최소 수정과 합성 회귀를 추가했다.

**전체 결과 후속 평가:** [67개 타겟·9항구·기능 대체 전수 검토](full-review.md). 최초 제한 표본 평가보다 이 전수 검토의 현재 판정/불확실 구분을 우선한다. 사전 동결 파일은 변경하지 않았다.

2026-10-21. **결론: 작은 사진 프로필 A만으로 현재 카탄 기능 전부를 제공하지는 못한다.** 카탄 그림판·자리 교환·항구 접점/교역·전용 보유자산 기능은 기존 C 확장을 유지해야 한다. 공통 사진 기록/저장 기반 재사용은 오프라인에서 확인했지만, 새 범용 UI는 이번에 구현하지 않았다.

**실사진 비교는 부분 완료다.** 동일 사진·설정 모델로 각 1회, 총 2회 호출했다. 기존 카탄 방식은 HTTP 200 이후 앱 응답 읽기에 실패했고 경량 방식만 유효한 JSON을 받았다. 따라서 정확도 차이나 속도 개선을 확정할 수 없다. 추가 호출·재시도·제품 도입·배포는 하지 않았다.

## 실험 조건과 공정성

- 사진: [기존 공개 연구사진](../../assets/research/catan-new-photo/catan-korean-progress.jpg), **850×637 JPEG / 239,177B**, SHA-256 `261f47f2ed891417ae83f7816c695e161ccdaa7d9cfe3c10ec9381303a2c8560`.
- [사전 사람 기준표](ground-truth.json)를 원본/확대 crop 직접 관찰로 작성하고 해시를 고정한 후 호출했다. 기존 AI 결과를 정답으로 쓰지 않았다. 지형 19개, 숫자 18개, 선택한 확실 구성물 30개, 확실한 항구 4개를 기록했다. 전체 물체의 완전한 정답표는 아니다.
- 기존 방식: 현재 `catanPack` + `observationPrompt` + `requestJSON` + `normalizeObservations`. 기존 카탄 전용 구조 그대로다.
- 경량 방식: [8개 버튼·숫자 2항목 프로필](profile.json) → 기존 연구 컴파일러 → **별도 일반 사진 프롬프트와 일반 입력 검사**. 기존 카탄 프롬프트에 경량 팩만 끼워 넣지 않았다. 19칸/공식 지형목록/슬롯/항구 접점/규칙을 경량 프롬프트에 주입하지 않았다. 사진에 카탄이 보이고 제목/버튼을 주었으므로 모델 사전지식까지 배제한 실험은 아니다.
- 설정 제공자/모델: **Gemini / `gemini-4-argon`**. 기존 앱 설정은 프로그램 내부에서만 사용했고 키를 열람·로그·복사하지 않았다. 제공자가 실제 사용한 세부 모델 버전은 별도 수집하지 않았다.
- 같은 모델·원본 bytes·순서·MIME·JSON 응답 형식. 기존 transport의 generationConfig는 양쪽 `responseMimeType: application/json`, 온도/추론/최대출력 옵션은 양쪽 모두 미지정이다. 모델·옵션·사진을 경량화 목적으로 바꾸지 않았다. 프롬프트를 지운 request body 해시도 동일했다.
- 실행 순서: 카탄 → 경량. 순서 무작위화·반복·네트워크 변동 측정은 없다. [호출 이력](call-ledger.json)은 정확히 두 시도이며, 하네스는 이미 이력이 있으면 추가 live 실행을 거절한다.

## 시간과 출력

| 측정 | 기존 카탄 1회 | 경량 1회 |
|---|---:|---:|
| 프롬프트/사진 base64 배열 준비 | 0.153ms | 0.221ms |
| HTTP 요청부터 응답 JSON 읽기까지 | **67.046초** | **64.270초** |
| 앱 requestJSON 완료/파싱 포함 | 실패, 완료시간 없음 | 64.273초 |
| 정규화 | 실행 못 함 | 0.172ms |
| 프롬프트 UTF-8 | 17,090B | 2,490B |
| HTTP request body | 337,511B | 321,741B |
| provider response JSON 전체 | 25,977B | 23,427B |
| provider 보고 input tokens | 5,043 (이미지 1,064 포함) | 1,748 (이미지 1,064 포함) |
| provider 보고 output tokens | 7,752 | 7,067 |
| 파싱된 raw JSON 크기 | 확보 못 함 | 19,500B |
| 유효한 결과 | 없음 | 구성물 67개 |

HTTP 시간은 네트워크·서버/모델 대기·응답 수신과 JSON 읽기를 합한 시간이다. **모델 순수 추론 시간이 아니다.** 전처리 값은 모듈 로드/설정 읽기/최초 사진 파일 읽기를 제외한다. 출력 토큰은 제공자 보고값이지 직접 검산한 값이 아니다. 경량 total tokens 8,906에는 제공자가 보고한 thoughts 91도 있다.

시간 차이는 약 2.78초지만 기존 방식은 유효 결과가 없어 성공까지 시간의 비교가 아니다. 한 번씩의 순차 측정으로 평균·개선율·다른 사진/모델 성능을 일반화하지 않는다. 작은 입력이 작아진 것은 확인했으며, 출력은 여전히 개별 물체를 열거해 컸다.

**기존 방식 실패의 한계:** HTTP 200/usage는 받았지만 앱 `requestJSON`이 raw JSON을 반환하지 못했다. 초기 하네스가 파서 이전 제공자 텍스트를 보존하지 않아 malformed JSON/비어 있거나 예상과 다른 텍스트 경로를 구분할 수 없다. [실패 기록](catan.timing.json)만 남았다. 원인이나 기존 방식 인식 품질을 추측하지 않는다. 실패 텍스트 확보를 위한 추가 호출도 하지 않았다.

## 경량 인식: 사람이 고정한 항목만 평가

[원출력](lightweight.raw.json), [대응표/평가](evaluation.json). 모델이 정답을 채점하지 않았다. 사람 기준의 사진 좌표와 출력 물체를 명시적으로 대응했다.

| 항목 | 경량 관찰 | 해석 |
|---|---:|---|
| 지형 종류 | 19/19 | 고정한 지형 모두 일치 |
| 읽을 수 있는 숫자 | 18/18 | 사막 숫자 없음도 일치; 독립 토큰으로 중복 생성하지 않음 |
| 지형 crop의 사람 중심점 포함 | 19/19 | 원본 영역 연결 확인. 정밀 segmentation/IoU 정확도는 아님 |
| 사전 구성물 30개 대응 | 29/30 | 아래의 사람 기준 오류 1개 포함, 모델 누락 1개로 해석 금지 |
| 대응 구성물 crop 중심점 포함 | 29/29 | 건물은 마을/도시 합친 범주로 평가 |
| 대응 플레이어 색/ID | 28/28 | 도둑의 검정/회색 재질은 색 평가 제외 |
| 동결 항구 라벨과 일치 | 3/4 | 아래 항구의 사람 기준 오류 가능성 때문에 정확도 점수로 사용 금지 |
| 확실 항구 비율 | 4/4 | 접점/해안 슬롯 정확도는 A 미지원으로 미평가 |
| 전체 출력의 원본 근거 ID | 67/67 | 같은 실제 제공 사진 참조. 모든 물체가 실제라는 뜻은 아님 |

**정정 수는 확정하지 못했다.** 출력 후 원본 확대에서 다음 재검토 항목을 발견했다. 실제 UI 조작/소요 시간은 미측정이다.

1. `harbor-7`: 모델은 아래 2:1 항구를 “밀”, 사전 기준은 “양”으로 기록했다. 추가 확대에서 노란 묶음 모양은 밀 다발로 보이므로 사람 기준 오류 가능성이 높다. 이를 모델 오류로 세지 않는다.
2. `blue-road-2`: `blue-city-2`의 높은 세로 부분을 별도 도로로 중복 기록했을 가능성이 있다. 한 장의 사진에서 독립 부품인지 완전히 확정하지 못해 수량 수락 전 확인 대상이다.
3. `white-road-3`: 처음에는 흰 경계선을 말로 잘못 읽은 듯했으나 추가 확대에서는 실제 솟은 도로일 가능성도 보인다. 확정 오인으로 세지 않는다.

초기 진행보고의 “최소 정정 3개” 판단은 철회했다. 동결 기준표를 AI 결과에 맞춰 바꾸지 않았으며, 불확실성을 오류로 승격하지 않았다. 모호한 도시/마을 구분·다른 항구 5개·작은 흰 구성물·총 물체 precision/recall은 미평가다. 보드 밖 공개 카드 6개도 반환됐으며 공통 보드 지표에서 제외했다. 각도 여러 장/카드 은닉/개인 손패/차례 정확도는 이 한 장으로 검증하지 않았다.

**사람 기준 자체의 오류/불확실성:** 사전 `white-road-2`(532,365)를 흰 도로로 기록했으나 출력 후 확대 검토에서는 타일 경계/인접 흰 건물 일부로 보인다. 동결 정답은 수정하지 않고 평가에 이 사실을 남겼다. 그러므로 29/30을 모델의 실제 누락률로 사용하면 안 된다. 검토 후 확실한 29개에서는 29개가 대응하지만, 이는 사후 정제한 탐색 지표이며 전체 정확도 주장은 아니다. 아래 항구도 사전 양 분류가 불안정하므로 3/4를 실제 항구 정확도로 쓰지 않는다. 확실한 다른 3항구는 모두 일치한다.

## 팩·작성량·저장과 기능 범위

| | 기존 카탄 | 경량 |
|---|---:|---:|
| compact 팩 JSON | 52,828B | 2,722B |
| 필드 / 요구사항 / 도출규칙 / 보관정의 | 57 / 25 / 17 / 8 | 5 / 0 / 0 / 0 |
| 게임별 직접 쓴 입력 | 기존 전문 팩 전체 | 프로필 535B, 부품 8행·숫자 2행·손패 구역 |
| 프로필 컴파일 | 기존 import, 따로 미측정 | 0.323ms, 한 번 |
| 임시 Store 사진 쓰기 | 1.016ms | 0.725ms |
| 같은 합성 상태 metadata 쓰기 | 1.387ms | 0.440ms |
| 같은 합성 상태 metadata 읽기 | 0.535ms | 0.193ms |
| 저장 metadata 파일 | 94,544B | 10,359B |

Store 값은 공개 사진을 임시 업로드 파일로 저장하고 **같은 합성 공용/개인/메모/스냅샷 상태**를 쓰고 읽은 한 번의 로컬 파일 측정이다. 양쪽 사진 bytes는 그대로 유지되고 팩은 세션에 고정됐다. 브라우저 저장 시간·서버 전체 API 시간·디스크 평균 성능을 뜻하지 않는다. `offline.json`의 초기 inline-dataURL fixture 저장 및 `lightweight.timing.json`의 raw-reader 저장은 다른 표현이므로 이 표의 파일 저장과 섞지 않는다. UI 정정·프로필 작성 소요 시간은 계측하지 않았다.

[기능별 A/C 표](feature-parity.md)를 기준으로:

- **공통 기반 확인:** public 1개/owner 장면 1개 정의, 근거/crop/모름 수량/이름/소유색, 공개 근거로 숨은 owner 필드 차단, 당시 팩·합성 개인 기록·스냅샷·원본의 임시 Store 보존.
- **실험에서만 만든 것:** 일반 사진 프롬프트, 일반 출력 검사, 기존 v2에 이름/읽은 숫자를 `note`로 보존하는 오프라인 adapter. 카탄 슬롯 정규화에 경량 출력을 억지 통과시키지 않았다. [v2 변환 결과](lightweight.scene-v2.json)는 슬롯이 모두 unplaced이며 카탄 그림판이 아니다.
- **제품 추가 구현 필요:** 사진 편집/일반 카탈로그/숫자 입력 UI, 생성 API/모드 분기, 일반 색 정정/묶음 처리. 실제 probe에서 범용 팩에도 현재 카탄 19칸 프롬프트가 붙고, unknown 소유자 변경은 no-op이며, 다른 이름 카드가 같은 그룹에 합쳐지는 공백 3개를 재현했다.
- **카탄 전용 C 유지 필요:** 평면 그림판/아트·정확 슬롯·즉시 자리 추가/교환·거리 등 규칙·항구 양 접점/교역비율·종류별 자원/개발 카드·보유수명/중단 조건. 작은 A 프로필이나 사진 표시만으로 대체하지 못한다.

이번 추가 파일은 실험 스크립트 4개와 데이터/문서뿐이다. 제품에 설치한 코드 0개, 제품 구현/마이그레이션 시간은 미측정이다. 필요한 실제 수정 묶음은 기능 표에 적었고 구현 일수는 추정하지 않았다.

## 재현과 검증 결과

프로젝트 루트에서 아래 **오프라인** 명령만 재실행한다. 외부 API가 호출되지 않는다.

```sh
node --import tsx docs/lightweight-catan-trial/harness.mts --offline
node --import tsx docs/lightweight-catan-trial/probe.mts
node --import tsx docs/lightweight-catan-trial/evaluate.mts
node --import tsx docs/lightweight-catan-trial/export-v2.mts
./node_modules/.bin/tsc --noEmit --allowImportingTsExtensions --module esnext --moduleResolution bundler --target es2023 --esModuleInterop --strict --skipLibCheck docs/lightweight-catan-trial/harness.mts docs/lightweight-catan-trial/probe.mts docs/lightweight-catan-trial/evaluate.mts docs/lightweight-catan-trial/export-v2.mts
```

직접 실행 exit: 위 5개 최종 **모두 0**. 실제 `harness.mts --live`는 **2**(기존 arm 실패, 경량 성공). 처음 별도 NodeNext tsc 실행은 프로젝트의 확장자 없는 import와 하네스 인덱스 타입 오류로 exit 2였고, 하네스 타입 cast를 고친 뒤 프로젝트와 같은 bundler 모드로 검사해 exit 0이다. 제품 파일은 고치지 않았다. 이 사후 수정은 타입 cast 한 줄뿐이며 live 동작 변경은 없다.

live 실행은 기존 소스의 private settings/requestJSON 함수 **export 가시성만 바꾼 임시 모듈**을 만들어 사용했다. 전송 코드를 재작성하지 않았다. 앱 설정 파일/키는 복사하지 않았고, 실제 세션·사진·설정 값 본문을 도구 출력으로 읽지 않았다. 이 폴더의 prompt/session은 전부 공개 사진과 합성 입력이다.

실제 API 예산은 이미 2/2를 소비했다. 기록을 지우거나 다른 폴더에서 live를 다시 실행하지 않는다. 실패한 baseline을 새 승인 없이 재측정하지 않는다. 이번은 제품 변경이 없어 전체 제품 test/build·실기기·브라우저 동등 UX 검증은 하지 않았다.
