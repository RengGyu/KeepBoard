## 일반 계약 결함과 최소 수정

실제 후보 소실/확정 경로는 UI 담당 구현솔 소유다. 이를 서버에서 우회하거나 현재 기록을 수정하지 않았다.

별도의 합성 재현에서는 `normalizeObservations`가 입력 사진 배열 전체에 ID가 존재하는지만 검사했다. 호출자가 혼합 사진 배열을 주면 공용 `table.scene` assertion이 개인 사진 ID만으로도 만들어졌고, 개인 `rack.scene`이 공용/다른 소유자 사진 ID를 근거로 삼을 수도 있었다. 정상 실제 analyze 경로는 소유자별 배치를 나누므로 이번 실물 사진에서 실제 비공개 유출이 발생했다는 증거는 아니다. 프롬프트와 정규화 계약을 일치시키는 좁은 수정이다.

- 수정: `server/ai/index.ts`의 루미큐브 AI 정규화만 대상 영역별 `scope / ownerId`로 근거 사진을 거른다. 공용은 소유자 없는 public만, 개인은 해당 소유자의 player 사진만 허용한다. 허가된 assertion 근거가 없으면 후보를 만들지 않는다.
- 회귀: `tests/rummikub-runtime-integration.test.ts`에 혼합 근거 배열 테스트 1개. 처음에는 `공용 assertion은 개인 사진만 인용할 수 없음`에서 실제1/기대0으로 실패했고, 수정 뒤 통과했다. 공용→개인 AI 추론 금지, 다른 소유자 제외, 유효한 개인 인쇄색 green 유지도 확인한다.
- 수동 받침대 정정은 공용 사진을 근거로 삼을 수 있는 기존 정책을 유지한다. `rummikubSourceEvidence`나 공유 모델/프롬프트는 이번 작업에서 변경하지 않았다. 다른 게임 경로도 바꾸지 않았다.
- 사진의 특정 숫자/묶음 정답을 프롬프트에 추가하지 않았다. 현재 사용자 보드·후보·저장본·원본 사진에 쓰기 요청을 하지 않았다.
