# 오류 사진 3건: 전체 사진과 같은 원본 부분 크롭 비교

2026-10-29. **부분 판독에는 이득이 있었으나 현재 제품 결합에는 그 이득이 충분히 반영되지 않았다.** 제품 변경·배포 없이 기존 prepareScanObservation → analyzeScanUnit → projectScanResults를 사용했다. 3게임 각 원본1+부분1=6실호출, 재시도0, 최대5동시. 실제 다른 각도 사진을 합친 시험은 아니다.

## 사진 확보와 한계

기존 후보 사진과 공개 검색을 제한적으로 확인했다. 캐스캐디아 [전체 사진](https://boardgamegeek.com/image/9812767)과 [같은 테이블의 다른 사진](https://boardgamegeek.com/image/9812768)은 타일·토큰 배치가 달랐다. 후자를 동일 상태의 보충 관측으로 합치지 않았다. 이 범위에서 오류 사진과 동일 상태인 다른 각도 사진을 확인하지 못했다. 모든 인터넷에 그런 사진이 없다는 뜻은 아니다.

대신 오류 유형이 서로 다른 캐스캐디아(묶음), 사그라다(눈값), 스플렌더 듀얼(빈 응답)을 사전에 고르고 같은 원본의 목표 영역을 손으로 정해 크롭했다. 확대 생성·새 시점 합성·업스케일은 하지 않았다. 원본에 없던 정보를 새로 확보한 근접 촬영 효과는 검증하지 않았다. 자동 크롭 범위 선택 기능도 이번 범위가 아니다.

## 판독 자체의 비교

같은 모델·프롬프트·허용 종류/속성·LOW/HIGH/32768 설정을 유지했다. 원본 요청 본문은 이전 20게임 시험의 해당 요청과 byte SHA가 같다. 크롭은 이미지/MIME/좌표 변환만 달라졌다. 기존 사전 동결 AI 참조를 수정하지 않고 썼다.

| 사례 | 원본 단독 새 응답 | 부분 크롭 새 응답 | 실제 제품 결합 후 |
|---|---:|---:|---:|
| 캐스캐디아 개별 물체 | 16/39 | 39/39 | 18/39 |
| 사그라다 틀+주사위 | 21/21 | 21/21 | 21/21 |
| 사그라다 판독 가능한 눈값 | 1/19 | 15/19 | 1/19 |
| 스플렌더 듀얼 개별 토큰 | 0/25 | 25/25 | 0/25 |

개별 물체 대조는 원본 좌표로 환산한 같은 종류·수량1 박스의 일대일 대응이다. 최대 합 IoU 매칭 후보를 확인했고, 채택된 원본 IoU 최저는 캐스캐디아0.52/사그라다0.71, 크롭은 각각0.57/0.71/스플렌더0.45였다. 해당 참조 물체의 위치 대응을 원사진 및 크롭과 함께 확인했다. 새 출력에 맞춰 참조를 바꾸지 않았다. 전체 사진의 미주석 물체까지 평가한 정밀도/전체 게임 정확도가 아니다.

스플렌더 듀얼의 색 표기는 엄격 문자열 비교22/25이며, 나머지3은 사전 yellow 대 출력 gold의 표현 차이다. 토큰별 실제 카드/기능의 모든 속성이 맞았다는 뜻으로 25/25 물체 수치를 사용하지 않는다. 사그라다의 4개 눈값 차이도 여전히 남는다. 이들은 AI 시각 기준과의 대응이며 사람 검증 정답은 아니다.

## 결합에서 확인한 병목

- **캐스캐디아:** 원본의 큰 habitat 그룹 박스가 개별 크롭 타일과 겹친다. 코드가 같은 실물인지 확정하지 못해 크롭 타일21개를 미해결로 남긴다. 원본 값은 유지하고 동물 일부만 보충된다. 결과30행이라는 총 개수는 참조39개의 회수율이 아니다(다른 개인판/공급 관측 포함).
- **사그라다:** 같은 주사위의 눈값과 색 서술이 충돌한다. 크롭의 `yellow translucent`와 원본의 `yellow` 같은 서술 차이도 conflict가 된다. 기존 anchor 값을 바꾸지 않는 규칙 때문에 잘못 읽은 원본 눈값도 자동으로 교체되지 않는다. 더 나은 사진의 값을 임의로 정답으로 선택해 덮어쓰지는 않았다.
- **스플렌더 듀얼:** 원본은 다시 빈 응답이었다. 크롭의 토큰25개는 모두 각각 다른 토큰이지만, 예측 사각 박스가 인접 토큰 박스와 조금씩 겹친다. 현재 crop-only 보충의 `overlaps` 검사는 **같은 크롭에서 반환한 인접 물체도** 겹침 후보로 포함한다. 25개 모두 양의 면적 겹침을 가진 이웃이 있어 새 물체 자동 추가가 막혔다. links25개가 unlinked, unresolved그룹1개/관측25개로 남았다. 코드 근거: [projectScanResults](../../server/scanObservation.ts:74)의 crop-only `overlaps` 검사와 [possibleScanRelations](../../shared/scanObservation.ts:38).

이는 크롭 API가 실패한 것이 아니라 **실제 최신 조립 코드에 저장된 응답을 넣었을 때 나타난 결과**다. 손실 방지 장치가 자동 반영을 과도하게 막는 사례를 확인한 것이다. 이 보고서에서 해결 코드를 추가하거나 일반적인 동일성 규칙을 설계하지 않았다.

## 보존·순서·중복 전달 검사

- 실제 원관측136개 전부 최종 편집 후보의 참조 또는 미해결 그룹에 있다. raw에만 남아 아무 참조도 없는 관측0.
- 원본 후보51개(캐스캐디아28+사그라다23)는 기존 ID와 알려진 값을 모두 보존했다. 충돌을 숨기고 값을 조용히 덮어쓰지 않았다.
- 완료 순서 역전, 같은 단위 재전달에도 최종 값·결합·receipt가 같았다. JSON 저장/재열기 동등성도 통과했다.
- 이 저장 검사는 JSON roundtrip이며 실제 HTTP 저장 API나 운영 DB/모바일 업로드를 재검증한 것은 아니다.

## 변동·속도·토큰

사그라다 원본은 이전에 눈값을 unknown으로 반환했으나 이번 같은 본문에서는 값을 반환했고 1/19만 고정 기준에 대응했다. 조건별1회이므로 재현성이나 안정적인 향상률을 확정할 수 없다. **이전의 ‘찾은 물체 값90.3%’를 모든 사진/실행의 보장으로 해석해서는 안 된다.**

| 게임 | 원본 provider 초 | 크롭 provider 초 |
|---|---:|---:|
| 캐스캐디아 | 17.491 | 36.393 |
| 사그라다 | 22.004 | 21.153 |
| 스플렌더 듀얼 | 3.376 | 19.443 |

6회 전부200/STOP·제품 단위 completed. 입력9,949·출력16,817·total26,766토큰. 사고 토큰은 이6회에서 미보고다. 두 장으로 정보량을 늘리는 만큼 추가 호출·토큰은 발생한다. 전체 사진 판독보다 무조건 빠르다는 결과는 아니다. 앱 업로드·카메라 미리보기·실제 다른 각도 스캔 시간은 미측정이다.

## 현재 결론

**작은 범위에서 부분 판독의 효용은 확인했다. 자동 결합까지 성공했다고 볼 수는 없다.** 범위를 더 늘리기 전, 같은 크롭 안 인접 물체를 중복 가능 물체로 취급하는 경계와 큰 그룹 대 개별 관측의 처리부터 좁게 검토하는 것이 적절하다. 서로 다른 시점의 사진을 자동으로 섞는 기능이나 새 모델·대규모 데이터팩 확대는 이번에 추가하지 않았다.
