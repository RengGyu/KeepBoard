# 스캔 장면 조립과 부품 수정 간소화

2026-10-21. 실제 개인 세션·사진·모델 응답은 읽지 않고 코드와 합성 응답으로 확인했다.

## 원인 구분

- **REPORTED:** 사용자가 사진 분석 뒤 그림판 13개를 보았다고 보고했다.
- **VERIFIED:** 현재 `SessionWorkspace → SceneWorkspace → SceneEditor`는 선택한 소유 영역에 편집기 하나를 렌더링한다. 기본 카탄의 공용 장면 필드는 `board.layout`, `components.observed` 두 개다. `SCENE_KINDS`에는 13종이 있지만 이 숫자를 사용자 현상의 원인으로 단정할 근거는 없다.
- **VERIFIED:** 모델이 한 사진의 부품들을 같은 필드의 여러 장면 assertion으로 반환하면, 기존 `normalizeObservations`의 중복 필드 교체가 앞의 장면을 버리고 마지막 장면만 남겼다. 전체 장면과 부분 장면도 서로 다른 후보 필드로 남았다. 이는 재현한 결함이며, 실제 사용자가 본 13개 그림판과 동일 원인인지는 **UNCLEAR**다.

## 변경

- 같은 분석 결과 안의 같은 소유자·촬영 시점 장면을 한 후보로 조립한다. 카탄의 전체/부분 공용 관측은 유효한 전체 장면이 있을 때 그 판에 연결한다. 부분 사진을 모았다는 이유만으로 전체 판으로 승격하지 않는다.
- 좌표·층·소유·알려진 속성이 같은 반복 관측만 중복에서 제외한다. 위치 없는 비슷한 카드는 함부로 합치지 않는다. 상충하는 좌표 관측은 편집 가능하게 보존한다. ID 충돌은 다시 부여하고 연결 대상도 함께 매핑한다. 대표 crop과 모든 근거 사진 참조를 보존한다.
- 기존 accepted 상태/스냅샷은 조립 입력에 넣지 않는다. 다른 소유자·촬영 시점·별도 사용자 정의 장면 필드는 합치지 않는다. 모델 지시에도 한 소유 영역의 부품들을 한 `components` 배열로 반환하도록 명시했다.
- 기본 화면은 새 후보가 이전 저장 판보다 늦으면 새 결과를 먼저 표시한다. 사용자의 명시적 필드 선택과 수정 중인 초안은 유지한다.
- 보드 부품 추가는 기본 옵션 기준 **5탭 → 3탭**: `추가 → 종류 → 자리`. `자리 선택`과 `여기에 추가`를 제거했다. 옵션은 바로 바꿀 수 있고 종류별 마지막 추가 값을 재사용한다. 자리 탭은 기존 이동 검사에 연결하며 한 번의 undo로 취소한다. 보드 밖 추가도 유지한다.
- 소유색은 이름과 실제 색칩으로 선택한다. 관측색 메모를 소유자 정보로 바꾸지 않는다.
- 목록/개인 카탈로그는 종류·변형·소유자별 수량 묶음이며 모바일에서도 3열이다. 묶음 선택 후 번호/위치로 실제 구성물을 고친다. `null` 수량을 0으로 계산하지 않는다.
- 지형 내장 숫자와 독립 토큰이 같은 칸의 같은 숫자를 나타내면 목록에서 한 번 센다. 원본 저장 데이터는 바꾸지 않고 모든 실제 ID를 유지한다. 독립 숫자 두 개 자체는 임의로 하나로 줄이지 않는다. 내장 숫자의 단일/다중 삭제는 숫자만 지우고 지형·사진 출처를 남긴다.
