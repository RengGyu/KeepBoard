# 최신 빠른 스캔 실제 API 시험

2026-10-29, 최신 미배포 소스를 별도 로컬 HTTP 앱으로 실행했다. 이전 비교와 SHA가 같은 사용자 카탄 사진 1장과 고정 부분 사진 4장, 한 작업을 실제 Gemini 3.8 Flash LOW/HIGH/32768로 읽었다. 모의 응답이 아니며 provider 5회, peak 5, retry 0, 모두 HTTP200/STOP이었다. 제품·프롬프트·모델·게임팩 변경과 배포는 0이다.

30초 목표는 미달이다. 전체 사진 요청이 끝날 때까지 기다리는 시간이 지배적이다. 이번 1회로 안정적인 속도 개선율은 산출하지 않는다. 저장소는 로컬이므로 업로드 0.121초를 Vercel/Supabase·모바일 업로드 시간으로 사용하면 안 된다. 실제 Vercel Workflow의 메모리/실행 한도도 검증하지 않았다.

## 기능과 품질

- manifest 후 5사진 병렬 전송, Evidence 등록 session write 1회, 고유 이미지 read 5회.
- 원사진 anchor 관측 49/49가 최종 구성물 참조로 연결됐고, 원문 영수증 5개를 보관했다.
- 최종 그림은 60개 구성물이며 이는 물리 정답 수가 아니다. 도로 5개 중 4개 배치/1개 미배치, 건물 11개 중 8개 배치/3개 미배치, 항구 6개 모두 미배치다. 미배치 후보의 실제 중복 가능성이 남는다.
- 이전 독립 시각표의 명확한 숫자 16곳은 위치별 값 16/16 일치. 불명확·가려진 숫자는 제외했다. 게임 전체 정확도·도로/건물 정밀도는 산출하지 않았다.
- 직접 원사진과 렌더 화면을 비교하면 상단 산/숲 아래 경계에 있는 파란 건물이 상단 해안 r1c1.NE로 놓이는 위치 오류가 보인다.
- r1c1의 숫자 3이 지형 속성과 독립 숫자 토큰 양쪽에 남는다. 화면의 단일 숫자 표시와 별개로 내부 표현 정리가 완전하지 않다.
- 저장 후 snapshot의 그림·영수증은 deepEqual이다. native Chrome 390×844에서 실제 완료된 보드와 마지막 저장 표시를 확인했다.

## 검사 도구 정정

첫 실행은 **제품 job 완료 후** 감독 집계 코드가 componentRefs 사전을 배열로 다뤄 중단됐다. `finish-save.mts`에서 같은 job의 참조를 올바르게 조회하고 저장 검사만 이어 했다. 새 provider 요청은 없었다. 따라서 중단 없이 업로드부터 저장까지 한 번에 잰 전체 시간은 없다. job 완료 시간과 저장 시간을 별도 측정값으로 보고한다. 상세 사실은 `result.json`, `checks.json`에 보존했다.

실제 원응답과 입력은 사용자 Library/Application Support 아래 private 연구 폴더에 저장했으며 키·사진 데이터는 문서에 싣지 않았다. 원본 손실을 피하기 위해 이번 입력 bytes를 private 연구 폴더에 복사했다. 자체 preview 서버만 종료한다.

판정: 병렬 실행·원문 보존·저장 경로는 실제 API에서 동작. 30초 및 완전한 자동 배치 목표는 미달. 이번 시험은 배포를 수행하거나 속도·품질 문제를 해결한 것으로 간주하지 않는다.
