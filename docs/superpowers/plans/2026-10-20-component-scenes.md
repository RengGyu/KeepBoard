# Component Scenes Implementation Plan

**Goal:** 실제 사진의 구성물을 부드럽지만 구별 가능한 공통 그림으로 표현하고, 카탄 위치에 맞춰 직접 수정·저장한다.

**Architecture:** 기존 assertion.value에 정형 ComponentScene을 저장한다. 사진 근거와 표시용 그림은 분리하고, 게임팩의 presentation/placement 명세로 공통 편집기를 연다. 전체 판과 부분/구성물 나열을 구분한다.

**Tech Stack:** 기존 React, TypeScript, SVG, Express. 새 의존성 없음.

**Spec:** 사용자 승인: 친근하고 깔끔한 약간 둥근 그림, 구성물별 상세 입력, JSON 양식, 변/꼭짓점/칸에 맞춘 카탄 드래그 조정과 기존 기능 연결.

## Global Constraints

- 실제 사진 원본은 변경하지 않는다.
- 보이지 않는 상태나 위치를 기본값으로 채우지 않는다.
- 아스트라 호출 없이 구현솔·클로드로 진행한다.
- 플레이 규칙 엔진을 새로 만들지 않는다.

## Tasks

- [x] 구현솔: ComponentArt SVG 템플릿과 그림 양식표.
- [x] 클로드: ComponentScene JSON 계약,19칸/54꼭짓점/72변, 상세 편집기·이동·로컬 되돌리기, 계약 테스트.
- [x] 감독: 게임팩·판독 프롬프트·정규화·저장·기존 상세 화면 연결. 기존 JSON과 세션 유지.
- [x] 감독: 실제 판독 사진에서 그림 목록/구조화 편집, 이동 저장 후 재열기, 모바일 확인.
- [x] 감독: npm test 및 npm run build, 인계 문서와 화면 저장.

## Review Focus

- 부분 사진이 완성된 전체 판으로 처리되지 않을 것.
- 그림 위치와 원본 영역 좌표가 혼합되지 않을 것.
- 숫자/소유자/수량 미확인이0이나 기본 플레이어가 되지 않을 것.
- 도로는 변, 건물은 꼭짓점, 도둑은 칸에만 구조적으로 배치할 것.
- 기존 임의 JSON은 명시적 호환 처리로 열고 원본 값을 조용히 잃지 않을 것.
