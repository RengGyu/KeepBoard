# 여러 사진의 관측을 실물과 보드에 연결하는 최소 설계

2026-10-29 · 연구 전용 · 제품/팩 변경 0 · 유료/API 판독 0. 기존 6장 병렬·모델·프롬프트·판독 schema는 유지한다. 현재 소스를 읽고 저장된 원응답을 무과금 진단했다. 입력·소스 SHA와 실행 결과는 [evidence.json](evidence.json), [diagnostic.json](diagnostic.json)에 있다.

## 권고

**같은 원본의 관측을 먼저 보존·연결하고, 물체 동일성과 보드 배치를 별도로 결정한다.** 전체 사진에 없다는 이유로 부분 사진 관측을 제외하지 않는다. 확실히 연결된 실물은 기존 그림에 보충하고, 애매한 겹침은 원사진 위치가 있는 **관측 묶음**으로 보여 준다. 이 묶음은 물체 1개나 2개로 확정하지 않는다. 보드 위치는 검증 가능한 사진→보드 정합과 물체의 실제 접점이 있을 때 연결한다. 별도 확인을 마쳐야 저장되는 흐름은 추가하지 않는다.

지금 가장 먼저 고칠 것은 중간 정도 겹침의 표현이다. 다음은 기존 지형·해안 topology를 쓰는 배치 후보 생성이다. **전체 사진 재판독, 새로운 LLM 결합 호출, 120게임 참조 이미지 구축은 선행조건이 아니다.** 다른 시점의 사진 자동 정합은 같은 원본 crop 처리와 분리해 뒤에 붙인다.

## 2. 지형을 이미 읽었는데 항구를 코드로 놓을 수 있는가

**후보를 좁힐 수 있다. 지금 저장 응답만으로 정확한 해안 변을 자동 확정할 근거는 부족하다.**

- 기존 `CATAN_TOPOLOGY`는 19hex/54vertex/72edge와 30개의 해안 변, 각 변의 두 끝점을 이미 갖는다. 지형의 **종류**가 아닌 이 연결 구조를 재사용한다. 해안 30변 모두에 항구가 있다는 뜻은 아니다.
- 원본 crop은 `원본 좌표 = crop offset + crop scale × 입력 좌표`로 복원된다. 여기까지는 기록된 변환이 정답이다. 그 다음 원본→보드의 회전·원근·대응점을 알아야 한다.
- 이번 원문 terrain 1건의 `region.y=28`은 정규화 범위를 벗어나 최종 region이 null이다. 남은 18개 모델 상자 중심과 모델 slot을 대응점으로 시험하면 최소제곱 rank 8이지만, 보드 단위 RMS 0.110604 / 최대 0.313806이며 7점이 기존 0.1 오차 검사를 넘는다. **현재 `photoFrameTransform()`은 이를 거절한다.** 오차 기준을 낮추거나 잘 맞는 점만 골라 통과시키지 않았다.
- 이 진단은 “상자 중심=실제 육각 중심” 및 “모델 slot이 맞다”라는 검증되지 않은 가정을 시험한 것이다. 투영에서 축 정렬 bbox의 중심은 육각 중심의 정확한 영상점이 아니다. 작은 잔차도 잘못 회전된 대응의 정답 증거는 아니다.
- 항구 bbox는 자원 그림/2:1 글자만 둘러쌀 수 있다. **글자 중심, 항구 부두 접점, 해안 변 중점은 다르다.** `harborPoint()`의 바깥쪽 0.72 이동은 UI 그림 간격이며 사진용 보정 상수가 아니다.

자동 배치에 필요한 최소 조건은 (a) 판 전체에 분산된 올바른 평면 대응점과 방향, (b) 해당 원본 SHA/상태에 유효한 정합, (c) 항구의 부두 두 끝점 또는 판본이 맞는 인쇄 프레임 참조, (d) 그 근거가 지지하는 해안 변의 유일성이다. 이때 코드가 두 꼭짓점과 그림 위치를 계산할 수 있다. 단지 가장 가까운 변 하나를 골라 확정하는 것은 부족하다. 검증되지 않은 모델 중심은 **배치 제안용**으로만 쓴다.

현재 사진은 일부 해안이 화면 경계에 걸리고 입체 건물이 경계를 가린다. 공식 판본에 맞는 부두 참조/독립 랜드마크는 이번 자료에 없다. 따라서 **현재 자료의 항구 위치 후보 생성은 가능, 확정 배치 성공은 미검증**으로 남긴다. 이 한계를 항구 종류·비율 관측을 버리는 이유로 삼지 않는다.

## 4. 연결 규칙: 관측, 실물, 배치를 분리

### 같은 원본 crop — 지금 구현할 부분

1. `plan/definitionSHA/scope/owner/epoch`를 고정하고 `sourceEvidenceId+sourceSHA+area`별로 처리한다. 원문 observation ref와 변환을 바꾸지 않는다. 입력 배열·완료 순서는 의미가 없다.
2. 같은 읽기 단위의 중복 receipt는 `(planId, unitId, observationRef)`로 멱등 처리한다. 물체 종류/색/값이 같다는 이유로 별개 물체를 합치지 않는다.
3. 강한 원본 영역 대응은 기존 연결 규칙을 유지한다. IoU/IoS·상호 대응·경쟁 관측 유무는 **동일성 가설의 근거**다. 기존 0.75도 정답 보증이 아니며, 이번 IoS 0.8677에 맞춘 새 자동 합치기 임계값은 만들지 않는다.
4. strong link 밖의 겹침은 버리는 조건 대신 `possible-same-object` 관측 묶음을 만든다. 크기가 다른 상자나 조각 경계에서 잘린 경우는 IoS도 함께 기록한다. A↔B↔C 연결을 곧바로 물체 1개로 전이 결합하지 않는다.
5. anchor가 누락한, 경쟁 없는 crop 실물은 기존처럼 편집 가능한 미배치 구성물로 추가한다. anchor 등록 실패/빈 응답이어도 원본 root가 계획에 있고 scope가 맞으면 보존한다. `baseline` 존재 자체로 신규 실물을 막지 않는다. 기존 실물과 동일성 불명이면 관측 묶음으로 남긴다.
6. 가능한 동일성만 있는 묶음은 기존 보드 아래에 원사진 영역·읽힌 종류/값을 표시하고 물리 수량에 합산하지 않는다. 원본 보기/기존 편집은 선택 사항이며 그대로 저장할 수 있다. 단순히 raw를 깊은 펼치기에 남기는 것에서 한 단계 개선한다.
7. 정체가 연결된 후 속성별로 병합한다. 알려진 기존 수동값은 유지한다. 서로 다른 비-null 값은 대안으로 보존하고 해당 속성만 충돌 처리한다. 위치 충돌 때문에 숫자·종류를 버리거나 항구 비율 충돌 때문에 정상 anchor를 없애지 않는다. null은 모름, 0은 관측값이다.

이번 fixture의 최초 수용 결과는 **기존 6개 항구 후보 + 2관측의 미해결 묶음 1개**다. 이를 “항구 총 7개가 정답”으로 표시하지 않는다. 사람이 원사진에서 같은 항구임을 확인했거나 검증된 인쇄 접점 대응이 생기면 하나의 실물에 두 source ref를 연결한다. 제품에 이 사진의 ref/좌표/개수를 넣지 않는다.

### 보드 배치

- 사진 좌표 overlay는 즉시 사용 가능하다. 배치 실패와 관측 실패를 섞지 않는다.
- 유효한 frame이 있으면 평면 물체의 실제 기준점/윤곽을 보드로 옮겨 대응 가능한 해안 edge/hex/vertex를 구한다. 복수 후보·경계 밖·가림이면 미배치 또는 배치 제안으로 둔다.
- 인쇄 항구는 부두 접점이나 판본에 맞는 프레임 참조가 유일한 edge를 지지할 때 그림에 연결한다. 종류/비율은 실제 관측을 사용한다. 정합만으로 보이지 않는 항구를 생성하지 않는다.
- terrain의 number와 독립 숫자 원판은 같은 계층이 아니다. 같은 실물 원판/hex 대응이 충분하면 원판 한 객체를 대표로 하고 terrain→원판 관계로 표시한다. 값만 같거나 bbox에 포함된다는 이유로 합치지 않는다. 충돌 값은 원문/대안에 보관하고 수동값은 지우지 않는다.
- `confirmedByUser:true` frame에 모델 추정점을 넣어 위장하지 않는다. 자동 정합은 별도 `proposed/validated/rejected` 파생 결과로 기록한다. `validated`는 기하 검사를 통과했다는 뜻이지 전체 판독 정확도 인증이 아니다.

### 다른 시점 사진 — 후속 연결 경로

동일 정지 상태·동일 공개 범위를 먼저 지킨다. epoch나 지형이 같다는 것만으로 게임 진행 상태가 같지는 않다. 이미지 매칭이 성공해도 이동한 말/다른 턴 사진은 합치지 않는다.

정합 가능한 사진은 평면의 인쇄 특징을 맞추고, 이상 대응 제외·넓은 공간 분포·남겨 둔 점의 오차·역변환/방향·반복 무늬의 대안 해를 확인한다. 예제의 픽셀 임계값을 휴대폰 해상도에 그대로 복사하지 않는다. 원본→보드 정합이 있다면 다른 사진→원본→보드로 합성할 수 있다. 평면 상의 인쇄 항구와 카드 면에는 유용하지만 입체 건물은 접지점 또는 별도 대응이 필요하다. 정합 실패 시 관측을 독립 사진 묶음으로 저장한다. 모델 호출을 자동 추가하지 않는다.

## 5. 최소 사전 데이터와 대안 비교

| 방식 | 필요한 데이터 / 효과 | 비용·시간·제한 |
|---|---|---|
| **추천 1단계: 기존 응답의 원본 기준 연결 + 미해결 묶음** | 원본 SHA/crop 변환/ref/기존 topology만. 현재 투영 누락과 중복 위험을 함께 처리 | 추가 모델 토큰·호출 0. CPU 후처리 증가량 미측정. 모델 45.8초 대기는 줄이지 않음 |
| **추천 2단계: 작은 평면 정합 + topology 배치** | 올바른 landmark/윤곽, 방향, 유효 영역. 후보 공간을 줄이고 규칙적인 칸/변/꼭짓점을 코드로 계산 | 새 LLM 호출 불필요. 자동 특징 검출기 런타임과 실제 정확도/지연은 UNKNOWN. 기존 frame을 쓰는 연결부터 가능 |
| **선택 보조: 판본별 프레임/구성물 참조** | 판본 ID, 허용된 이미지 SHA/출처·권리, 이미지 좌표의 landmark·부두 접점·종류. 모듈형 프레임은 조각 ID/로컬 끝점과 실제 조립 방향을 분리 | 확인된 인쇄 부품을 재사용하면 좁은 가림에 도움 가능. 자료 제작/권리 비용 미측정. 기존 SVG는 UI 아트이며 실물 정답 참조로 취급하지 않음. 무작위 지형/말/손패는 채우지 않음 |
| **보류: 전역 VLM 재결합 / 전게임 이미지 사전 / 자동 추가 촬영 판독** | 추가 시각 문맥이나 참조가 필요할 때 선택 가능 | 추가 토큰·요청·사용자 촬영 부담. 이번 부족은 이미 읽힌 관측의 연결 문제도 커서 우선순위 낮음. 성공률·요금 추정하지 않음 |

참조는 게임팩 핵심 상태를 바꾸는 대규모 분류가 아니라 선택적인 sidecar로 충분하다. `referenceId, editionId, topologyId, assetSHA, source/usage, landmark semantics, printed attachment pairs, fixed vs modular`를 명시한다. 실제 판본·조립 방향이 확인되지 않으면 쓰지 않는다. 특정 사진의 지형 순서나 항구 종류/좌표를 템플릿으로 저장하지 않는다. 인쇄 참조의 종류가 현재 관측과 충돌하면 관측을 덮지 않고 판본/가림 문제로 남긴다.

## 6. 속도와 확인 범위

[최신 실서비스 시험 보고](../fastest-live-20261029/README.md)는 격리 로컬 HTTP 앱에서 5요청 병렬, 최초 부분 결과 9.135초, 최종 46.636초, 가장 느린 전체 사진 45.778초, 총 32,837토큰을 기록했다. 이는 **기존 실험 측정값(REPORTED)**이며 이번 연구가 재측정한 값이 아니다. 클라우드/모바일 업로드 시간도 아니다.

이 설계는 이미 지불한 응답을 더 유용하게 쓰는 개선이다. 동일 원본 연결·기하 코드는 추론 토큰을 추가하지 않는다. 특징 정합을 기존 요청과 겹쳐 실행할 수 있지만 추가 CPU/전송/캐시 비용과 정확도는 미측정이다. 현재 가장 느린 요청 자체를 줄이지 않으므로 30초나 특정 절감률을 약속하지 않는다. 원본+crop의 중복 입력을 줄이는 것은 판독 계약/실험을 바꾸는 후속 작업이며 이번 수정에 섞지 않는다.

**이번에 실행한 것:** 원문·저장본·소스 hash, 항구 수/미연결 ref/IoU·IoS 재계산, 기존 linker 역순 입력 의미 비교, 지형 모델 중심의 정합 진단. `node --import tsx …/diagnose.mts` exit 0. 실제 사진 1장과 기존 crop 2개 시각 확인. **실행하지 않은 것:** 제안 구현, 새로운 정합/부두 검출기, 개선판 전체 projector 재생·UI·저장 테스트, 추가 실모델/정확도 시험. 상세 수용 검사는 [implementation-plan.md](implementation-plan.md).
