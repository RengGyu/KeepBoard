# Dice recognition sources checked 2026-11-02

| Primary source | Relevant approach / author report | KeepBoard applicability and action |
|---|---|---|
| [Huang 2008, Sensors, DOI10.3390/s8021212](https://pmc.ncbi.nlm.nih.gov/articles/PMC3927534/) | Threshold/morphology extracts spots, clustering groups spots into dice. Fixed imaging apparatus and lighting; expected die count supplied. | Supports separating spot detection from grouping. Its reported success is not evidence for transparent dice over patterned game boards. Do not reuse expected-die-count grouping to invent hidden dice. |
| [Wimsatt et al. 2021, WKU](https://digitalcommons.wku.edu/seas_faculty_pubs/5/) | CNN face classification; authors report95.10–99.76% on their train/validation images. | Specialist classifiers are feasible; this range does not transfer to our photo. Abstract accessed; full download403, so detailed dataset assumptions not verified. |
| [Kishaan Dice-Detection, author report and notebook](https://github.com/Kishaan/Dice-Detection) | Blob extraction and clustering, including transparent dice videos. Author documents side-face dots and blur as failure sources. | Motivates explicit upper-face pip localisation, not counting every white dot in a die box. Report is an academic project, not a peer-reviewed production benchmark. No source copied into product. |
| [Apple official dice sample](https://developer.apple.com/documentation/coreml/understanding-a-dice-roll-with-vision-and-object-detection?language=objc) | Detects dice tops with a trained model, then stabilises values over video frames. Official documentation says white dice with black pips work best. | Useful detect→read separation. Device/CoreML sample and colour restrictions make it unsuitable as an immediate server replacement. Not executed. |
| [G-G-Games diecamera-models](https://huggingface.co/G-G-Games/diecamera-models) | Offline ONNX dice detector/classifier stack; model card explicitly warns about rig/domain dependence and incomplete held-out comparison. | Downloaded20MB classifier into private venv; tested unchanged weights on saved provider boxes. Reported separately in scores.json. AGPL model card; no product integration or license decision. Referenced runtime source path was404, so execution follows published model-card recipe; equivalence to author application not independently established. |
| [Roboflow public six-sided dice dataset](https://public.roboflow.com/object-detection/dice/1) | Downloadable detection dataset, including annotated dice in Catan settings. | Possible source for training a dedicated pip/upper-face reader; catalogue existence does not establish quality on translucent dice. No training or hosted inference used. |
| [RollSight official product](https://www.rollsight.com/) and [camera guidance](https://www.rollsight.com/guides/webcam) | Camera-based desktop recognition with user correction/training; guidance acknowledges translucent dice are harder. | Existing service confirms deployable specialist workflows, but no verified embeddable KeepBoard inference API or Sagrada accuracy. No account/install/purchase or external message. |

Applied here: reuse existing provider localisation, crop each die with a generic margin, enumerate visible upper-face pip centres and count them programmatically. No game inventory constraints are used to alter die rolls. This is a composite framing/output experiment; it does not isolate the contribution of each part.
