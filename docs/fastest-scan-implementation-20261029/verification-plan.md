# 감독 통합 검증 범위

제품 단일 구현 소유자는 기존 구현솔 High다. 감독은 이 문서 폴더와 통합 검사만 편집한다.

1. 저장된 cap2/cap5 실제 원응답 재생: 각5개 응답120순열, 정상 anchor 관측/inline 숫자 보존, 입력 객체 불변. 순서 변화 실패를 `replay-before.log`로 재현했다. 새로운 실물 정답률 검사가 아니다.
2. 같은 실제 사진5개의 reader 요청 본문을 transport 직전 가로채 비교: `reading-body-before.json`은5개를 구성했고 실제 네트워크0. 수정 후 같은 fixture의 본문 SHA가 같아야 한다.
3. 모델·지시문·판독 schema·게임 정의 경계는 `reading-freeze.json`의 파일 해시로 확인한다. 추가 상태/진행 계약과 판독 출력 계약을 구분한다.
4. 구현 완료 후 직접 영향 테스트와 전체 테스트·Vercel 빌드를 최종 소스로 실행한다. 실패가 남으면 성공으로 보고하지 않는다.
5. 로컬 별도 Store와 지연된 저장 응답 재생 reader로 실제 UI를 검수한다. 네이티브 Chrome 개발자 도구에서390×844 설정을 확인했다. 우선 부분 관측 표시, pending 구분, 최종 편집판, 수정 없이 저장, 재열기/원문 유지. 모의12초를 실제 공급자 속도로 보고하지 않는다.
6. 기존 Vercel 운영 배포는 이번 구현으로 자동 교체하지 않는다. 유료 모델 재호출·실기기 카메라 검증은 이번 무과금 기능 검사와 구분한다.

CUA 브라우저 연결 host는 unavailable이지만 네이티브 Chrome 제어는 가능하다. 완료 시 실제로 수행한 UI 동작과 미검증 범위를 구분한다.
