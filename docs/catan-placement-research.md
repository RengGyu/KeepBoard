**RECOMMENDATION — 점유층과 교환 계약.**

| 자리 | 배타적인 점유층 |
|---|---|
| hex | `terrain`, `number`, `robber`가 각각 독립적이다. 세 종류의 공존은 정상이다. |
| edge | `road` |
| vertex | `building` = `settlement` 또는 `city` |
| area / unplaced / 정확한 id 미상 | 단일 자리로 간주하지 않는다. `unknown`, 일반 `token`도 임의로 특정 점유층에 넣지 않는다. |

1. `resolveSlotId`로 정규화한 위치와 점유층으로 상대를 찾는다. 같은 자리로 놓기는 무변경이다. 호환되지 않는 자리에는 새 편집을 적용하지 않는다.
2. 기존 보드 조각 A를 같은 층의 B 하나가 차지한 자리로 옮기면 **A→B의 자리, B→A의 자리**를 한 번에 적용한다. 두 출발·도착 위치가 모두 유효해야 한다. 마을↔도시도 위치 교환이며 소유자·종류를 바꾸거나 자동 업그레이드하지 않는다.
3. 교환은 `commit` 한 번, Undo 한 번이다. `id`, `ownerId`, `quantity`, `evidenceId`, `region`, `face`, `direction`, `attachedToId`, 메모 등 위치 외 값은 각 조각에 남긴다. 사진 영역은 보드 좌표가 아니다.
4. 같은 층의 상대가 여러 개이거나 수량이 1보다 큰 묶음이면 임의의 하나를 고르지 않는다. 기존 기록을 유지하고 대상 정리가 필요하다고 표시한다. 수량 모름을 자동으로 1로 바꾸지 않는다.
5. 출발지가 목록·공급처·위치 미상인 조각을 점유된 곳에 놓을 때는 자동 교환하지 않는다. 상대를 보낼 확정 보드 자리가 없기 때문이다. 새 배치 실패 시 공급 수량·기록은 그대로다. 빈 자리에 알려진 묶음에서 한 개를 꺼내면 원래 수량만 1 감소하고, 수량 0에서는 꺼내지 않는다. 미상 묶음의 남은 수량은 미상으로 유지한다.
6. 빈 자리로 기존 조각을 옮긴 뒤, 또는 교환한 뒤의 **최종 장면**에 경고를 계산한다. 이동 전 A가 자기 자신을 막거나 교환 중간 상태가 중복으로 판정되지 않게 한다.

**RECOMMENDATION — 지형과 숫자의 이중 표현.** 기본 편집 의미는 “지형층만 맞바꿈”이다. 독립 숫자·도둑·주변 건물과 도로는 그 자리에 둔다. 사막으로 바뀐 자리에 숫자가 남으면 경고하고 삭제하지 않는다.

현재 `terrain.number`도 숫자를 담는다(`shared/scene.ts:100`, `src/SceneEditor.tsx:448`). 이를 그대로 이동하면 별도 `number-token`과 동작이 달라진다. 최소 처리로, 이동에 관련된 칸에서 **알려진 인라인 숫자만** 같은 칸의 독립 숫자 기록으로 분리하고 지형의 인라인 값을 제거한 뒤, 그 전부를 교환과 같은 Undo 단위에 넣는 것을 권한다. 새 숫자 기록은 기존 사진 출처를 이어받되 독립 사진 영역은 만들지 않는다. `null`/미기록 숫자는 토큰 존재를 추정해 만들지 않는다. 인라인 값과 별도 숫자 기록이 이미 함께 있으면 값이 같아도 자동 병합하지 말고 중복 표현 확인을 요청한다. 이 경우 자동 지형 맞바꿈을 보류하고 원본은 유지한다.

**RECOMMENDATION — 강제와 경고의 최소 경계.**

| 상황 | 새로 놓기 | 기존 정정·불러오기 |
|---|---|---|
| 확정된 같은 층 점유 | 겹쳐 추가하지 않음 | 유일한 상대면 위 계약대로 교환. 기존 중복 데이터는 보존·경고 |
| 인접 꼭짓점에 알려진 건물 | 새 마을 배치 차단 | 거리 경고, 저장 허용 |
| 알려진 사막에 숫자 / 보드에 두 번째 도둑 추가 | 새 배치 차단 | 모순 경고, 임의 삭제·재배치 금지 |
| 도로·마을 연결 불충족 | 현재 장면에서는 경고 | 경고만. 이전 건설 순서나 초기배치 여부를 추측하지 않음 |
| 새 도시 | 자기 마을의 명시적 업그레이드라면 같은 자리에서 대체. 빈 자리·타인 마을에 “업그레이드”하지 않음 | 사진에 이미 있는 도시는 마을의 과거 기록 없이 직접 정정 가능. 종류 변경도 분류 정정으로 취급 |
| 위치·소유자·지형·수량 미상 | 판정할 수 없는 조건은 “확인 필요” | 미상 유지. 누락을 위반이나 빈자리로 단정하지 않음 |

여기서 “새로 놓기”도 실제 턴 실행을 뜻하지 않는다. 사진에서 발견한 기존 도시를 입력하는 일까지 업그레이드 절차로 막으면 복원 정보가 손실된다. 일반 새 배치가 막힌 경우에는 명시적인 **“원본대로 기록”** 경로로 경고를 남긴 채 기록할 수 있어야 한다. 비용·턴·승점·전체 공급량 처리는 추가하지 않는다.

거리 검사는 `vertex.edgeIds → edge.vertexIds`의 반대 끝만 확인한다. 해안의 차수가 2일 수도 있으므로 무조건 이웃 세 개를 요구하지 않는다. 도로 연결은 후보 변의 양 끝 중 하나에서 자기 건물, 또는 상대 건물로 막히지 않은 자기 인접 도로가 있는지 확인한다. 알려진 타인 건물은 **그 꼭짓점을 통한 연결만** 막는다. 반대 끝의 유효한 연결은 허용한다. `ownerId: null`을 타인으로 취급하지 않는다. 기존 도로 전체의 단일 연결성이나 모든 도로에서 자기 마을까지의 경로는 요구하지 않는다.

`coverage: full`은 촬영 범위이지, 모든 조각·소유자·플레이 단계가 확정됐다는 표시가 아니다. 따라서 현재 스키마에서는 연결 제약을 강제하기 위한 단계 추론을 넣지 않는다. 초기배치에서는 마을 연결 예외와 그 마을에 붙는 초기 도로를 구분한다. 기존 도시 아래에 마을이 없다는 이유로 오류를 만들지 않는다.

**RECOMMENDATION — 구현솔에게 전달할 최소 인터페이스.** 공통 점유층 함수, `planScenePlacement(scene, componentId, target, intent)`, 확장된 `inspectScene(scene)`의 세 역할로 나눈다. 이동 계획은 `move | swap | blocked | unchanged`, 최종 장면과 관련 조각·사유를 반환하면 충분하다. 드래그·탭·폼이 같은 계획을 적용하고 한 번 커밋한다. 종류·소유자·숫자 정정에도 경고를 재계산한다. `normalizeScene`에 새로운 “합법 배치로 자동 수정”을 넣지 않는다. UI에는 “교환”, “기본판 규칙 확인 필요”, “판정할 정보 부족”을 구분한다.

**RECOMMENDATION — 최소 회귀 사례.** 제품 코드를 수정하지 않았으므로 아래는 실행 결과가 아닌 구현 후 확인 목록이다.

1. 도로↔도로, 마을↔도시의 원자적 교환과 Undo. 소유자·사진 영역·미상 값·구성물 수 보존.
2. 같은 칸의 지형+숫자+도둑은 충돌 아님. 지형 교환 후 독립 숫자·도둑 유지, 인라인 숫자 분리도 Undo로 완전히 복원.
3. 다중 점유 대상·묶음·목록 출발에는 임의 상대 선택 없음. 배치 실패 시 공급 수량 불변, 0 수량에서 생성 없음.
4. 인접 건물은 색과 종류에 관계없이 거리 경고. 새 마을은 차단, 기존 정정은 보존. 두 변 떨어진 자리와 해안은 허용.
5. 상대 건물 경유 연결은 실패하되 반대 끝의 자기 연결은 인정. 이미 끊긴 구간·초기 두 거점은 전역 연결 검사로 거부하지 않음.
6. 자기 마을 업그레이드는 중첩이 아닌 대체. 기록된 도시의 이동·입력에는 과거 마을 증명을 요구하지 않음.
7. 사막+숫자는 경고, 도둑+숫자는 정상. 도둑을 생산 지형에 놓거나 같은 위치로 다시 드롭해도 잘못된 건설 금지·턴 판정을 만들지 않음.
8. 부분 장면·소유자 미상·숫자 중복 표현에서 자동 추정·삭제 없음. 드래그·탭·위치 메뉴의 결과가 같고 경고가 있어도 원본 기록 저장 가능.

**UNCLEAR:** 실제 판본·배치 변형·초기배치 진행 여부·과거 건설 순서는 현재 장면만으로 확인할 수 없다. 연결·도시의 과거 업그레이드·빨간 숫자 배치를 일괄 강제하면 원본 복원을 막는다. 이번 최소안의 강제는 명시적 새 편집의 기하·점유·확정된 국소 충돌에 한정하고, 기록 자체에는 경고를 남기는 것을 권한다.
