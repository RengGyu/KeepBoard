# 관측 결합 구현 및 이전 결과 비교

같은 원본과 부분사진의 저장된 모델 응답을 그대로 재생해 비교했다. 새 모델 요청·배포는 없다. 아래 수치는 동결된 **AI 부분 참조표**에 대한 대응이며 전체 사진 정확도나 독립 평가가 아니다.

| 평가 범위 | 이전 제품 결합 | 수정 제품 결합 |
|---|---:|---:|
| 카스카디아 개별 물체 | 18/39 (46.2%) | 39/39 (100%) |
| 스플렌더 듀얼 개별 물체 | 0/25 | 25/25 (100%) |
| 사그라다 개별 물체 | 21/21 | 21/21 |
| 사그라다 읽을 수 있는 눈값 | 1/19 (5.3%) | 15/19 (78.9%) |

모델이 새로 잘 읽은 효과가 아니라 이미 읽힌 관측의 연결·상세화·속성 선택을 바꾼 효과다. 사그라다 눈값 4건은 여전히 참조와 다르다. 편집 항목 총합은 53→98이지만 참조 밖 13항목이 포함되므로 98개 정답이라고 해석하지 않는다.

## 변경

- 같은 원본 좌표의 서로 다른 사진 단위 사이에서 일대일 물체 대응을 수행한다. 한 사진 안의 이웃 물체는 별개로 유지한다.
- 집합 관측은 개별 관측으로 일부 상세화하되 중복 수량으로 합산하지 않는다. 잔량을 추정하지 않는다.
- 숫자·enum·boolean은 물체 전체를 포함하고 밀도가 낮지 않은 더 좁은 시야의 고유 근거가 있을 때 임시 선택한다. 자유서술은 다른 관측을 보존한다.
- 수동 수정, 명시적 모름·0·false, 배치·삭제를 보호한다. 근거는 선택적 fusion 메타데이터로 저장하고 화면에서는 접힌 설명으로 제공한다.
- 일반 구성물 경로에 한정한다. 카탄·루미큐브 등 기존 native 조립 경로는 유지한다. 다른 시점의 미등록 사진 정합은 이번 범위가 아니다.

## 검증

- 집중 단위/UI 19건, 기존 native·합성 HTTP 16건 통과. 실제 HTTP에서 수정→저장→재열기→다음 작업의 수정값 보호와 늦은 결과 거절 검증.
- 감독 독립 제품 재생: 같은 입력 SHA 3세트·136관측, 순서 역전·중복 전달·원문 불변·JSON 보존 통과. 부분 참조 내 추가 중복·교차 오연결 0건.
- 실제 Chrome에서 사그라다 선택 근거·대안 표시, 수정 없이 저장·새로고침 확인. GET한 snapshot의 값·receipts·fusion이 accepted 기록과 동일. 모바일 크기는 미측정.
- `npm run build:vercel` exit 0 (타입 검사 포함).
- **전체 테스트 827건 중 825 통과, 2 실패**. 수정하지 않은 `tests/splendor-record-ui.test.ts:54,67`이 점수 input을 기대하지만 현재 UI가 stepper/output을 렌더링한다. 이번 결합 범위에서 별도 UI 변경을 하지 않았다.
- 추가 모델 호출·추가 토큰·배포 0. 로컬 결합은 이번 재생에서 약 2~24ms였으나 운영 종단 속도 개선을 증명하지 않는다.

## 읽을 변경

1. `server/observationFusion.ts`의 `projectGenericFusion`: 물체 대응 → 집합 상세화 → 필드별 선택/수동값 보호 → 원관측과 함께 반환.
2. `src/ScanObservationResults.tsx`의 `ScanFusionNotes`: 선택한 값과 다른 관측을 기본 접힘으로 표시.
3. `tests/observation-fusion-http.test.ts`: 저장 후에도 수동 null/0·배치를 유지하고 늦은 작업을 stale 처리하는 실제 HTTP 회귀.

입력 흐름: 저장 응답 → 원본 좌표 대응 → 개별 항목·임시 선택·대안 → 자동 반영 → 수정 없이 저장/재열기.
