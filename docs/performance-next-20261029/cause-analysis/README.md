# 판독 누락 원인 조사와 변경 비교

**VERIFIED:** 모델 응답에 실물 행이 적게 포함된 지점까지 확인했다. **UNKNOWN:** 지시문 축약/출력 필드 선택화/실행별 변동 중 어느 요인이 원인인지, 모델의 시각적 미탐지와 출력 생략·조기 종료 중 무엇인지는 기존 각1회 자료로 확정하지 못했다. 이번 조사는 제품 변경·Gemini 추가 판독·배포 없이 수행했다.

입력은 같은 사진 SHA였다. 실패 실행은 `모델 원문8 → 관측8 → 그림8`이고 충돌 없이8개가 남았다. 따라서 반환된 행을 decoder/병합이 버려49→8이 된 것은 아니다. 원응답은 지형4개에 `coverage:full`을 주장했으며 기존 정규화기는 이를 부분 기록으로 낮춘다. JSON 형식 성공·저장 성공은 사진의 내용 완전성 검증이 아니다.

**추정1 — 지시문 문맥과 강조의 변화:** 게임팩 촬영 계약, 허용 필드 설명, 본문의 전체 scene schema·예시, 상세 변형/소유자/항구/다중시점 설명을 폭넓게 축소했다. 모델의 전수 열거 동작에 영향을 줬을 가능성은 있다. 그러나 작은 실물·도로·마을·도시를 읽고, 값이 안 보여도 물체를 남기며, 19칸 확인 시에만 full이라는 지시는 축약에도 있었다. 해당 지시 삭제를 원인으로 지목할 수 없다.

**추정2 — 출력 규칙 완화의 영향:** 같은 schema에서 variant/ownerId/evidenceId만 필수→선택으로 바꾸었다. component 배열 개수 상한을 추가하거나 도로 kind를 제거하지 않았다. 따라서 의도한 변화는 행마다 반복되는 항목 생략이고 물체 행 제거가 아니다. 모델의 실제 출력 행동에 영향을 줬는지는 지시문 변경과 분리하지 않아 미확정이다.

**미확인 — 종료 상태/반복 편차:** 원래 native 요청 메서드와 준비 함수가 바이트 동일함을 복구한 원배포 소스로 확인했다. 하지만 성공 receipt에는 공급자 종료 사유 finishReason, 사용 토큰, 실제 provider modelVersion과 전체 outbound 요청이 보존돼 있지 않다. native parser는 성공 JSON의 STOP도 강제하지 않는다. 관측 수만으로 응답 조기 종료·요약 생략·미탐지를 구분하지 못하며, 각 조건1회로 실행별 편차도 분리하지 못한다.

다음 최소 원인 분리안은 출력 schema를 기존 필수8개로 고정하고 긴/짧은 설명만 비교하는 것이다. 짧은 설명도 필수8개와 맞게 null·원본 ID 작성 지시를 정렬하고 evidenceId 생략 허용 문구를 제거해야 포맷 충돌이 없다. 이후 같은 설명 아래 schema만 바꿔 비교할 수 있다. 종료 사유/실제 토큰과 반환된 각 종류·원본 위치를 함께 확인하고 반복해야 한다. 각1회로 원인을 확정하지 않는다. 이번 조사에서는 추가 유료 실험을 실행하지 않았다.

현재 운영의 native 모듈 SHA256 `d89caf23705771a6c5113cef83f0ab669f0beb8b82bf3c8d881aa8cbb9b885bf`는 실험 이전과 같다. 사진 묶음/병렬화, 실패 사진 원본 보기, null 수량 보존, 기준점 검증은 독립 수정으로 남아 있다. 현재 버전에서 같은 사진을 새로 판독해49개를 재현한 것은 아니다.
