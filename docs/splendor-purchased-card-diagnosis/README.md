## 데이터 흐름과 확인한 공백

1. **개발 카드 자체는 읽을 수 있는 대상이다.** `componentId=development`, `readout.kind=development`, 카드에 인쇄된 points/bonus/cost를 요구한다(`server/ai/generic.ts:48`, `shared/splendor.ts:6`). 그러나 readout에는 `purchased/reserved/market` 상태나 플레이어 ID가 없다. 구매/예약의 구별은 **어느 필드와 owner에 넣었는가**에 달려 있다(`shared/genericRecord.ts:7`; `player.scene`=플레이어 공개 구매 카드·토큰, `reserve.scene`=소유자만 볼 예약 카드, `market.scene`=공개 시장).
2. **‘구매 카드·토큰’ 촬영 결과도 현재는 미귀속으로 고정된다.** `shared/capture-profiles.json` JSONPointer `/splendor/areas/2/fields`는 `["__photo.public"]`. `shared/recognition.ts:48`도 public 사진에서는 public-scope만, owner 사진에서는 owner-visible player-scope만 허용해 **public-visible player.scene를 어느 사진에서도 직접 출력하지 않는다.** 촬영부분 미지정이어도 이 기본 필터는 남는다. 소유자를 짐작하지 않으려는 제한이므로 자동 확대하면 안 된다.
3. **미귀속은 인식 실패를 뜻하지 않는다.** `__photo.public`의 라벨/설명은 ‘사진에서 확인했지만 원래 기록 영역에 연결되지 않은 실물’이다(`shared/recognition.ts:38`). 합성 카드의 development/파란 보너스/인쇄 숫자를 정확히 준 경우에도 owner 미지정 후보가 된다. 모델이 그 public 필드에 `ownerId=p1`을 보내도 필드 범위 때문에 최종 assertion은 owner 미지정이다(`server/ai/index.ts:121–127`). `__photo.owner`의 owner도 사진 접근 문맥이지 구매 상태 확정이 아니다(`server/ai/generic.ts:45`).
4. **‘이 후보 적용’은 귀속을 해주지 않는다.** `src/GameEssentials.tsx:38`은 원래 `a.field`와 현재 `ownerId`에 그대로 답변을 저장한다. 따라서 미귀속 후보를 적용해도 `__photo.public`의 accepted만 생기며 `player.scene/p1`은 생기지 않는다. 수정 UI(`:95`)는 구성물 종류·숫자·원본·배치 등을 고치지만 플레이어/목표 기록 영역으로 옮기는 입력은 없다. `PhotoCaptureGuide.tsx:14`의 ‘공개 개인물의 주인은 나중에 선택해요’라는 안내를 끝까지 이행할 경로가 없다. **이 후속 연결 누락은 코드로 확정되는 사용자 흐름 공백이다.**
5. **보너스 자동 집계도 현재 범위에 없다.** 해당 팩 `derivedRules=[]`; 영구 보너스는 `record-note.bonus` 수동 확인 메모다(`shared/gameEssentials.ts:45`의 비구조 JSON 보존 대체). 사용자가 `player.scene/p1`에 올바른 카드를 수동 입력하는 것은 엔진이 허용하지만, 그 동작만으로 총 보너스/명성이 계산되지는 않는다. 이는 위의 소유자 연결 공백과 구별되는 현재 지원 범위다.

## 카드 그림·세부값 판독이 별도로 실패하는 조건

- 사진 전체에 구매 카드가 있어도 ‘레벨별 공개 카드’만 선택했다면 시장 필드만 허용된다. ‘구매 카드·토큰’을 선택한 경우와 결과 범위가 다르다(`shared/photoCapture.ts:22`, `server/ai/index.ts:121`). 모델이 보유 카드를 시장이라고 오분류했는지는 원응답/후보가 있어야 판단한다.
- 가림·작은 인쇄는 null로 남기도록 지시한다. 더미/뒷면은 kind=deck으로 구분하며, kind=development인데 라벨이 더미/뒷면이라고 명시하거나 구조값이 유효하지 않으면 세부 readout을 빈 값으로 낮춘다. 실물 piece 자체는 남는다(`server/ai/splendor.ts:13–16`). 합성 음수 점수 예에서 piece는 유지되고 readout.kind=null이 되는 것을 재현했다. 이것을 사용자 사진의 실제 원인이라고 단정하지 않는다.
- `generic.ts:45`의 ‘past purchases를 출력하지 말라’는 문구는 구매 이력을 추정하지 않도록 하는 취지지만, 현재 눈에 보이는 보유 카드와 혼동될 여지는 있다. 실제 모델이 이 문구 때문에 누락했는지는 **미확인 가설**이다. 승인된 후속 수정에서는 ‘현재 보이는 보유 카드 자체는 읽되 과거 구매 사건을 추측하지 말라’고 뜻을 분명히 하는 정도가 가능하다.
