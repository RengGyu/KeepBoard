**독립 실험 평가 · 2026-10-23 · 고정 3사진 / 6요청**

판단은 **운영 `high` 유지, `none` 기본값 전환 보류, 두 형식 교정 반영**이다. `none`의 짧은 응답 시간은 실제 관측됐지만 정해 둔 품질 조건을 통과하지 못했다. `high`에도 오독과 결과 폐기가 있어 정확도 인증으로 해석할 수 없다. 이번 판단은 세 사진에 한정하며 전게임 정확도와 통합 UI의 동작은 검증하지 않았다.

**조건과 성공의 의미**

[고정 카드](experiment-card.json)의 SHA256은 `e4bcde3566aa5e746b6a2dedce60161f76e598ab8a8a99fb8ea8f273d85ee3f6`이다. 원본 세 장을 직접 다시 확인했고 정답·미확인 범위는 바꾸지 않았다. 카드, 원본, 팩, 프롬프트 및 요청 본문을 대조했으며 각 사진의 두 조건에서 동일 입력 바이트를 재구성했다. 실행 순서와 6회 한도, 재시도 0회도 [요청 기록](../photo-read-experiment/requests.json) 및 단일 호출 코드와 일치한다. 원응답·정규화 결과·관련 소스 해시는 [독립 평가 JSON](experiment-review.json)에 고정했다. 원본 사진과 원응답은 재게시하지 않았다.

HTTP 200과 JSON 응답은 **6/6**, 내용이 남은 정규화 결과는 **4/6**, 실제 값이 채워진 구조화 판독 결과는 **2/6**이다. 빈 구조화 값만 가진 후보를 판독 성공으로 계산하지 않았다. 실행 alias `board-vision`에서 모델 `deepseek-flash`, `none` 수용은 3/3이고 보고된 reasoning token은 모두 0이었다. 이는 실제 세 요청에서의 수용 근거이며 모든 모델이나 API의 동일 동작을 뜻하지 않는다. 상류 전체 전송 패킷·과금 기록은 별도 수집되지 않았다.

**고정 정답과 실제 값**

아래는 카드에 이미 있던 항목만 대조한 결과다. Sagrada의 현재 계약으로 담을 수 없는 5항목은 정오답 분모에서 제외했다. 사진과 모델의 대상 연결이 불명확하면 정답으로 인정하지 않았다.

| 사진·조건 | 원응답의 고정 항목 대조 | 실제 정규화 후 |
|---|---|---|
| Splendor high | 정답 11, 누락 1 | 동일 |
| Splendor none | 정답 9, 오답 1, 누락 2 | 동일 |
| Sagrada high | 정답 5, 오답 2; 미지원 5 | 지원 항목 7개 모두 누락 |
| Sagrada none | 정답 1, 누락 6; 미지원 5 | 동일 |
| SCOUT high | 오답 1, 대응 불명 1, 누락 1 | 3개 모두 누락 |
| SCOUT none | 구조화 항목 3개 모두 누락 | 동일 |

Splendor의 아래 가운데 카드에서 `high`가 맞힌 검정 보너스를 `none`은 빨강으로 바꿨고, 파랑 비용 1을 누락했다. 따라서 worker의 품질 조건 `FAILED` 판단에 독립적으로 동의한다. 아래 오른쪽 카드의 빨강 비용 6은 두 조건 모두 누락하고 다른 색으로 배정했다. 잘못 추가된 색 비용은 별도 오류로 기록했으며 고정 정답 항목을 늘리지 않았다.

Sagrada `none`의 정답 1은 **주사위 후보 19개라는 개수**다. 눈·색이 채워진 구조화 판독 성공을 뜻하지 않는다. `high` 원응답은 지정된 두 주사위 눈 4와 6을 각각 2와 4로 오독했다. `none`은 설명 라벨에 일부 숫자를 적었지만 `readout` 자체를 빠뜨렸다. 임의의 라벨 해석으로 이를 구조화 정답으로 승격하지 않았다. 미지원 5항목은 행·열 수, 빈 칸, 인쇄 효과, 이 촬영 범위에 연결되지 않은 투명 돌 수다.

SCOUT의 맨 앞 카드 주황 끝 9/파랑 끝 3에 대해 `high`는 3/6을 반환했다. 숫자 3이 있어도 색 끝 대응이 없어 그 항목은 불명이다. 별 토큰 `[5,10,10,2]` 중 10 하나가 빠졌다. `none`의 라벨도 앞 카드와 토큰에 오독이 있지만 구조화 값은 모두 누락됐다. 다른 카드에서 발견된 3/9를 앞 카드 정답으로 대신 계산하지 않았다. 카드의 활성 끝·손패 순서는 미확인으로 유지했다. 항목별 실제 값과 대응 기준은 [독립 평가 JSON](experiment-review.json)의 `results[].gt_entries`에 있다.

**제품에 필요한 최소 교정**

1. **출처 표기 하나 때문에 필드 전체가 사라지는 문제.** [gameReadouts.ts](../../server/ai/gameReadouts.ts)는 `sources` 값으로 `observation`만 허용하는데, 두 high 응답은 실제 사진 ID를 넣었다. [generic.ts](../../server/ai/generic.ts)의 검증 경로에서 필드 전체가 거부되어 Sagrada 21개와 SCOUT 15개가 0개가 됐다. 새 모델 응답에 한해 값이 해당 조각의 실제 첨부 사진 ID와 정확히 같고 같은 소유 범위임을 확인하면 `observation`으로 정규화한다. `user`, 수동 필드, 외부 사진 ID는 계속 거부하며 기존 저장·가져오기 데이터를 바꾸지 않는다.
2. **구조화 값의 선택/필수 설명과 최종 예시 불일치.** 같은 프롬프트가 판독값을 optional이라고 하면서 요구하고, 마지막 JSON 예시에는 Splendor 외 게임의 `readout` 형태가 없다. 활성 게임·부품에 맞는 `schema/kind/values/sources` 예시를 넣고, 모르는 값은 null, 출처 종류와 `evidenceId`는 별개임을 명시한다. 설명 라벨을 사실값으로 자동 변환하거나 유료 재시도를 추가하지 않는다. 프롬프트가 실제 모델 누락을 얼마나 줄이는지는 이번 기록만으로 측정할 수 없다.

[독립 오프라인 재생](experiment-review.replay.json)은 기존 6결과를 재현했다. 사진 ID 출처 표기만 메모리에서 교정하면 high Sagrada **21개**, SCOUT **15개**가 유지됐다. `user` 출처·다른 출처 ID·다른 조각 사진·수동 값의 네 거부 사례도 통과했다. 원응답 15파일의 해시는 그대로이며, 교정 결과로 기존 품질 점수를 다시 매기지 않았다. 형식 교정은 원래 오독도 보존하므로 인식 정확도 개선과 구별해야 한다.

Sol2의 [교정 코드 오프라인 결과](../game-photo-integration/offline-replay.json)는 같은 원응답 SHA에 대해 21/15개와 구조화 값 60/42개 보존, none의 구조화 누락은 null 유지로 보고한다. 해당 입력 해시는 독립 대조했다. 구현 소스 동결 후 검토는 별도 카드이며 이 보고서가 통합본 검증을 대신하지 않는다. 최소 교정과 수용 예는 Sol2와 감독에게 전달했다.

**소유 범위와 남은 제한**

실험의 Sagrada·SCOUT 혼합 사진은 지정 owner 범위로만 처리됐고, 6응답의 필드·첨부 근거·정규화 소유 범위에서 이탈은 발견하지 못했다. 이 owner는 시험용 접근 범위이며 사진 속 실제 인물의 정체를 뜻하지 않는다. Splendor는 공용 진열/획득 카드 여부가 미확인인데 두 응답이 `market.scene`을 택했다. 사용자 촬영 부분 선택이나 미배정 영역을 유지해야 하며 이것만으로 개인정보 유출이 입증된 것은 아니다. 조명으로 불확실한 Sagrada 전체 색 주장도 정답으로 일괄 인정하지 않았다.

운영 high 불변과 임시 서버 종료는 worker의 전후 메타데이터·실행 코드 근거이며 리뷰어가 운영 설정·키·프로세스를 열람하지 않았다. 이 리뷰의 제품 수정·추가 실호출·GT 변경은 모두 0이다. 기존 정정·명시 적용 흐름을 유지하며 두 형식 문제를 연결하면 된다. 새 전게임 평가를 통합의 선행 조건으로 추가하지 않는다.
