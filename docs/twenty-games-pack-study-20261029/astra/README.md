권고는 **게임별 관측 어휘와 실물 구분 설명을 짧게 추가하고, 계산 가능한 관계는 코드에 남기는 것**이다. 이번에는 실행기·모델·사진·출력 형식을 바꾸지 않는다. 긴 규칙서나 초기 구성 수량을 넣어 보이지 않는 상태를 맞추게 하지 않는다. 개선 여부는 아직 UNKNOWN이다.

## 고정한 입력과 실행 인계

선정은 사진·정답 주석·모델 출력 열람 전에 [selection-freeze.json](selection-freeze.json)에 기록했다. 카스카디아, 킹도미노, 도미니언, 타이니 타운을 구조적 차이로 골랐다. 이 연구에서는 이후에도 해당 시험 사진·주석·출력을 열지 않았다. 현재 팩·공식 구성물 그림은 읽었다.

실행 입력은 [augmentations.json](augmentations.json)의 `augmentations` 배열이다. 네 항목 각각 `gameId`, `areaId`, `photoSHA256`, 판본/팩/정의 SHA, **정확한 `promptAppendix` 문자열과 UTF-8 `sha256`**가 있다. 출력 전에 내용을 동결했다. 설명·규칙 문장을 추가하는 실험이며, 원본 팩이나 학습 가중치를 수정하는 실험은 아니다.

실행자는 이미 고정한 baseline body를 복사해 아래 한 곳만 수정한다.

```text
body.contents[0].parts[0].text = baselineText + "\n\n" + entry.promptAppendix
```

부록을 다시 요약·번역하거나 파일 끝 개행을 덧붙여 해시를 바꾸지 않는다. 삽입은 정확히 한 번. 사진 바이트·전처리·면/영역·model·thinking·resolution·output cap·schema·normalizer는 같은 쌍에서 동일해야 한다. **baseline 20회와 이 중 4종 추가 4회, 각 조건 1회, retry 0**이 감독 실행 범위다. 연구자가 실행하지 않았다. 실패도 기록하고 대체 게임을 사후 선정하지 않는다.

## 현재 코드에서 확인한 차이 — VERIFIED

[buildGeminiGameBody](../../../server/ai/geminiGameReader.ts:17)는 선택된 종류의 이름/physicalType과 속성 id·label·type·options·면 조건을 모델에 보낸다. `PhotoComponentDefinition.properties[].sourceText`, 원명세의 자세한 부품 설명·게임 관계는 보내지 않는다. **이미 있는 설명을 저장하는 것과 실제 프롬프트에 전달하는 것은 다르다.**

기본 프롬프트에도 인쇄물/실물, 수량/인쇄 숫자, unknown·소유자 추정 금지 지시가 있다. 이번 부록은 이 보호가 전혀 없던 것을 새로 만든다는 주장이 아니다. 게임별 구체 어휘·구분과 일반 지시 일부의 재강조가 함께 추가된다. 따라서 결과가 좋아져도 ‘지식 추가만의 순수 효과’ 또는 ‘길이 효과’로 세분 인과를 확정할 수 없다.

[정의 index](../../../game-photo-definitions/index.json)와 선택 게임의 [readout 계약](../../../shared/readouts/contracts/)을 대조했다. 선택 영역 밖 구성물 및 수동 속성(owner/cell/rotation/targetTile 등)은 부록으로 허용하지 않는다. `decodeGeminiGameObservation`의 unknown/면/종류별 속성 검사를 그대로 사용한다. 관측이 존재해도 계약에서 보류된 것과 모델이 못 읽은 것은 분리해야 한다.

특히 **킹도미노 `dominoes.tileNumber.faceOnly=true`**인데 공식 규칙의 식별 번호는 뒷면이다. 앞면에서 번호를 추정하게 하지 않는다. 뒷면에서 실제 번호를 읽어도 현 decoder가 보류할 수 있으므로 이 항목은 계약 제약으로 표시한다. 이번 연구 범위에서 소스·팩을 바꾸지 않았다. 도미니언도 카드 속성이 face/printedName/cardType뿐이어서 비용·승점은 부록만으로 출력·저장할 수 없다.

파일 바이트 SHA와 네 정의 SHA는 JSON `inputInventory`에 있다. 저장된 현재 파일을 검토했으며, 특정 운영 배포와 동일하다는 주장은 하지 않는다.

## 검토한 접근과 지금의 선택

| 방법 | 현재 목적에 도움이 되는 지점 | 이번 선택 및 부담 |
|---|---|---|
| 짧은 시각적 정의·명명 어휘 | 이름만으로 부족한 실물 형태·인쇄 기호 의미를 전달 | **이번 시험**. 팩별 짧은 근거 문장만 필요. 추가 토큰과 잘못된 사전지식 편향도 측정 |
| 판본이 확인된 실물 참조 이미지/유사도 검색 | 인쇄가 작거나 낯선 카드·토큰 정체를 구별할 후보 | 후속 후보. 이미지 권리·판본·앞뒤·대체 부품 정리가 선행돼야 하며, 현재 참조셋이나 이번 정확도 근거로 가장하지 않음 |
| 고정 관계·타입 제약을 코드로 계산 | 확인된 값의 결합·정규화·계산을 반복 모델 추론 없이 수행 | 장기적으로 유용. 지금은 입력/출력 유지 실험이므로 코드 변경 0. 관계가 합법적이어야 한다는 이유로 관측을 바꾸거나 누락을 채우지 않음 |
| 전체 규칙서 RAG/별도 학습 검출기 | 큰 카드 사전이나 특화 탐지에서는 별도 효용 가능 | 현재 4쌍 실험에는 과도함. 우선 게임·영역 ID로 필요한 작은 사실만 선택; 새 검색/학습 시스템은 도입하지 않음 |

[Menon & Vondrick의 classification-by-description](https://arxiv.org/abs/2210.07183)은 class name보다 관측 가능한 특징 설명을 활용하는 접근을 제시한다. 다만 CLIP 분류 연구이며, 이 Gemini 장면 판독의 수량·박스·저장 정확도를 입증하지 않는다. [GLIP 논문](https://arxiv.org/abs/2112.03857)과 [공식 구현](https://github.com/microsoft/GLIP)은 언어 구절과 영역의 연결을 학습한 검출의 다른 경로다. 텍스트 부록만 붙이는 이번 방법과 동일하지 않으며 학습/모델 교체는 하지 않는다. 두 연구에서 KeepBoard 성능 수치를 가져오지 않았다.

## 무엇을 코드로 계산하고, 무엇을 직접 봐야 하나

- 카스카디아: 실제 동물·타일 관계와 인쇄 아이콘이 확인되면 일치 여부를 계산할 수 있다. 토큰 아래 지형·허용 아이콘을 그 규칙으로 복원할 수는 없다.
- 킹도미노: 확인된 실물/방향으로 두 반쪽을 함께 저장하고, 읽힌 왕관 수를 합산할 수 있다. 가린 반쪽·뒷면 번호·완성 왕국은 추정하지 않는다.
- 도미니언: 읽힌 이름·기능 유형을 정규화하고 공개/개인 영역을 보존할 수 있다. 공급 초기 수량으로 남은 수량·손패·플레이 이력을 역산하지 않는다.
- 타이니 타운: 표준 부품/판본과 보이는 색이 확인되면 재료명을 표에서 대응시킬 수 있다. 선택 건물 카드와 관측 칸이 없으면 카드명·효과·소모된 자원·실제 점유를 건축 규칙으로 채우지 않는다.

이는 구현 권고 범위의 분리이며 이번에 코드 계산기를 추가하거나 효과를 실측한 것은 아니다. 읽힌 값/원문/unknown을 보존하고 사용자 정정을 강요하지 않는 기존 흐름을 유지한다.

## 출력 열람 전에 고정한 평가 방법

1. **같은 과제 확인:** 쌍마다 이미지 SHA·MIME·area/owner scope·정의/팩 SHA·generationConfig·schema 동일, body diff는 부록 한 곳만. 비용 실패/잘림/정규화 실패를 성공 판독 분모에서 조용히 제외하지 않는다.
2. **정답 분모:** 감독이 독립적으로 먼저 확정한, 실제 보이고 판독 가능한 참조 항목만 사용한다. 사전 주석이 일부 표본이면 ‘그 표본에서의 정확도’로 표시한다. 미주석 예측을 자동 false positive로 세거나 모든 사진 객체가 주석됐다고 가정하지 않는다.
3. **물체와 값:** 같은 실물에 one-to-one 대응 후 존재/누락, 종류, 개별 속성 값을 각각 센다. known GT에서 누락·unknown은 `맞게 회수한 값 / 판독 가능한 GT 값`의 실패로 포함하고, `맞은 값 / 실제 읽어 낸 채점 가능 값`도 별도 보고한다. GT 자체 unknown은 분모에서 제외한다. 미검토 추가 물체는 ‘추가 미판정’으로 남긴다.
4. **기하:** 실제 객체 바운더리와의 박스 대응·IoU 및 대응 불명 수를 별도로 보고한다. 타일 중심 포함만으로 작은 기호 값 정답을 판정하지 않는다. 부분 주석으로 전체 배치 성공률을 만들지 않는다. 방향 규약이 없는 킹도미노는 raw first/second 비교와, 두 지형-왕관 쌍을 통째로 뒤집을 수 있는 대칭 비교를 구별한다.
5. **저장 경로:** raw 정답→정규화 유지/보류→후보에 남는지를 구별한다. 앞면 전용 제한, 잘못된 필드/형식, 수량 미확인은 각각 기록한다. 뜻이 맞는 관측을 GT로 교정해 앱 성공으로 만들지 않는다.
6. **시간·비용:** 각 호출 elapsed와 input/output/thought/total usage를 기록한다. 실제 요금표와 usage가 있으면 계산 비용, 없으면 UNKNOWN. 시간 30초 초과나 부분 배치만으로 불합격시키지 않는다. 사람 정정 시간/클릭은 이번에 측정하지 않았으면 추정하지 않는다.
7. **해석:** 4개 단일 쌍은 방향을 보는 작은 비교다. 증가·변화 없음·감소를 게임/속성별 분자·분모와 함께 모두 제시한다. 호출 순서·캐시·샘플링 변동, 추가 길이와 의미가 동시에 바뀐 점을 남긴다. 결과를 보고 부록을 고치지 않는다. 다른 사진으로 일반화 검증 전 ‘120게임 팩 강화 성공’이라고 하지 않는다.

baseline 20종의 기술 통계와 부록 4종의 짝 비교는 따로 제시한다. 현재는 **모든 결과 UNKNOWN / 미열람**이다. 결과를 감독이 전달하면 고정 부록과 독립 참조를 그대로 사용해 후속 해석한다.
