# 공식 데이터 부록 4쌍 실험 결과

2026-10-29 · **실험 해석 완료 / 제품 적용 없음**

**권고: 긴 게임 설명을 전 게임 프롬프트에 일괄 추가하지 않는다. 실물 단위·관측 속성의 뜻·판본별 어휘를 작은 데이터로 유지하고, 필요한 항목만 전달하는 방향은 유지한다.** 이번 부록의 명확한 점수 차이는 카스카디아 동물 1개와 속성 2개 추가뿐이다. 다른 3종은 동결 기준에서 같았고, 카스카디아의 전경 타일 묶음 관측은 오히려 사라졌다. 따라서 ‘공식 자료를 넣으면 인식·복원이 전반적으로 개선된다’는 결론은 지지하지 않는다. 반대로 쉬운 표본의 기존 성공률이 높아, 참조 데이터 자체가 불필요하다는 결론도 낼 수 없다.

## 비교가 지킨 조건

- 사진·정답·출력 열람 전에 [선정](selection-freeze.json)과 [4개 부록](augmentations.json)을 고정했다. 부록 파일 SHA256은 `57ade6bec31e9b724859731229a50b86e3e45fa5e67b27f2b3db991bbc6c6e82`이며 변경하지 않았다.
- 연구자가 저장된 실제 요청 8건을 대조했다. 각 쌍은 `baselineText + "\n\n" + promptAppendix` 이외 deep equality, 포함 이미지 SHA, 모델/설정/출력 schema 동일을 확인했다. Gemini 3.8 Flash / LOW / HIGH image resolution / output cap 32768, 4종 각각 기본·보강 1회다.
- 8건 모두 HTTP 200 / STOP / decode 성공. native→parsed JSON 동등성, parsed→decoded 행 수·종류·quantity·속성값·박스 정규화도 직접 대조했으며 이 범위에서 차이 0이었다. 이는 **보존 경로 검사**이지 사진 정답 인증이 아니다.
- 감독이 전체 baseline 20회와 추가 4회를 실행했고 retry 0이다. 연구자는 새 모델 호출을 하지 않았다. 원본·GT·부록·제품 수정 0. 요청·응답 해시와 검사 결과는 [experiment-evidence.json](experiment-evidence.json)에 있다. 원사진/raw는 전달받은 비공개 연구 저장소에서만 읽었고 이 보고서에 복제하지 않았다.

## 고정 기준에서 나온 점수

기준은 두 Sol이 출력 전에 만든 **독립 AI 시각 주석**이다. 사람 검증 정답이 아니다. 아래는 지정 영역/확인 가능한 일부 실물의 점수이며 전체 사진·게임 정확도가 아니다. `속성 회수`는 정답으로 기록된 읽을 수 있는 필드 중 맞게 돌아온 수로, 누락·unknown도 분모에 남는다. face·색 등도 계약 필드 단위로 포함한다. 이 4종에서는 대응된 물체의 kind 점수가 개별 물체 점수와 같았다.

| 게임 | 개별 물체/맞는 종류: 기본 → 보강 | 속성 회수: 기본 → 보강 | 해석 |
|---|---|---|---|
| 카스카디아 | 17/39(43.6%) → 18/39(46.2%) | 34/78(43.6%) → 36/78(46.2%) | 동물 하나 추가. 전경 개별 habitat는 양쪽 0/21 |
| 킹도미노 | 6/7(85.7%) → 6/7(85.7%) | 25/31(80.6%) → 25/31(80.6%) | 동일. 분모 중 도미노 1개의 기준 짝 경계가 의심됨 |
| 도미니언 | 13/13(100%) → 13/13(100%) | 39/39(100%) → 39/39(100%) | 노출된 맨 위 카드의 제목·유형·면만; 더미 수량 제외 |
| 타이니 타운 | 1/1(100%) → 1/1(100%) | 1/1(100%) → 1/1(100%) | 앞쪽 판의 노란 큐브 1개/색 1개만 채점 |

단순 합산은 물체 **37/60→38/60(61.7%→63.3%)**, 속성 **99/149→101/149(66.4%→67.8%)**다. 이는 카스카디아 비중이 큰 서로 다른 분모의 산술 요약이다. 20종 전체 성적이나 120게임 예상 정확도로 확장할 수 없다.

점수 근거: [Sol1 기본](../scores-sol1.json), [Sol1 보강](../scores-sol1-augmented.json), [Sol2 기본](../scores-sol2.json), [Sol2 보강](../scores-sol2-augmented.json). 연구자는 선택 4종의 원사진·기준·8개 원문/정규화 값을 직접 대조했다.

### 점수만으로 놓치기 쉬운 부분

**카스카디아:** 기본 응답에는 전경 habitat를 큰 박스 하나와 quantity 16으로 묶은 행이 있고, 보강에는 전경 habitat 행 자체가 없다. 이 묶음은 개별 위치·지형을 제공하지 않아 양쪽 모두 개별 타일 회수 0으로 평가됐다. 보강이 원래 빠진 파란 새 토큰 하나를 더 찾았지만, **동물 개선과 타일 관측 범위 축소가 함께 일어났다.** 공용 제안 영역의 네 타일에는 보강 후 지형/동물 아이콘 값이 생겼으나 고정 전경 기준 밖이므로 개선 점수로 가져오지 않았다. 정상화가 전경 타일을 버린 사례가 아니라 provider raw 단계의 차이다.

**킹도미노:** `domino-top-yellow`의 노란 두 칸을 가로 도미노 하나로 묶은 기준은 의심스럽다. 두 조건 모두 각각 아래 지형과 연결한 세로 도미노로 반환한다. 원사진에서 경계가 애매하므로 어느 쪽도 정답으로 강제하지 않는다. 동결 7개/31속성 분모는 유지했다. 그 의심 항목만 제외하는 **민감도 표시**는 양쪽 모두 6/6 물체·25/26 속성으로 동일하다. 남은 속성 차이는 성을 ‘파랑’이라고만 읽어 기준의 노랑 벽 색을 포함하지 않은 부분이다. 새 부록이 이를 개선하지 않았다. 앞면의 `tileNumber`를 양쪽 모두 unknown으로 두었으며, 사전 발견한 뒷면 번호/faceOnly 계약 문제는 이번 사진에서 실측되지 않았다.

**도미니언:** 두 조건 모두 13개 노출 앞면의 제목/유형/면이 같고, quantity는 모두 null을 유지했다. 기본부터 이 채점 범위에서 천장이어서 부록의 추가 이득을 보이기 어려운 표본이다. 사진에는 기본판 부록에서 열거하지 않은 카드들도 있어, 특정 기본판 인쇄물 전체에 대한 검증으로 부르지 않는다. 카드 효과·비용·숨은 카드·잔여 수량은 평가하지 않았다.

**타이니 타운:** 기본·보강 모두 다섯 플레이어 판의 노란 큐브 다섯 개를 반환하고 같은 yellow/wheat 값을 냈다. 고정 평가는 앞쪽 판 큐브 하나의 **색만** 포함한다. resourceType은 사전 기준이 색에서 추론하지 않아 분모에서 제외돼 있다. 후에 공식 색 대응을 확인했다고 정답 항목을 추가해 보강 점수를 만들지 않는다. 이 표본에서는 기본도 이미 wheat를 반환하므로, 재료 범례의 필요성을 강하게 시험하지 못했다.

**평가 영역과 모델 입력의 차이:** 이번 whole-image 요청은 `ecosystem`/`town`이라는 의미 영역과 허용 종류를 보내며, ‘앞쪽 플레이어 판만’이라는 실제 ROI 경계는 보내지 않았다. 따라서 기준 밖 예측은 **off-assessed-region**으로 분리한다. 타이니 타운의 다른 판 큐브 네 개를 모두 모델의 영역 위반/환각으로 확정하지 않는다. 데이터 팩의 종류 설명만으로 사진 속 어느 개인판이 목표인지 결정할 수 없다. 이 연구는 소유자를 추정하거나 임의 ROI를 제품에 추가하지 않았다.

입력 +879, 출력 -800, 보고된 총 토큰 +79다. 이 8건에서 `thoughtsTokenCount` 필드는 미보고이며 ‘내부 추론을 전혀 하지 않았다’는 뜻으로 쓰지 않는다. 실제 청구액은 이 연구에서 확인하지 않아 UNKNOWN이다. 토큰 총합을 사진당 비용으로 곧바로 환산하지 않는다.

각 조건 1회이며 실행 시점·배치가 다르다(전체 baseline 최고 동시 5, 보강 4). 출력 길이/포맷·범위도 변했다. 따라서 세 게임의 시간 감소를 부록의 속도 효과라고 확정하거나, 20종 batch wall과 보강 4종 batch wall을 비교하지 않는다. 업로드·사용자 정정·저장·복원 시간은 포함하지 않은 **provider 응답 시간**이다. 30초 기준으로 합격/불합격을 만들지 않았다. 근거는 [baseline ledger](../baseline-ledger.json)와 [augmented ledger](../augmented-ledger.json)다.

## 최소 데이터 팩 권고 — RECOMMENDATION

추가 설명은 **아래 다섯 항목을 갖춘 작은 관측 사전**이면 충분하다. 현재 팩의 id·허용 속성·sourceText를 재사용하는 설계이며 새 120게임 규칙 엔진/참조 이미지 수집 사업을 뜻하지 않는다.

| 최소 항목 | 담을 내용 | 넣지 않을 내용 |
|---|---|---|
| 판본과 근거 | gameId/edition, 공식 URL·절, 확인 범위 | 사진을 보지 않고 확정한 인쇄 판본 |
| 실물 단위 | 분리 가능한 말/타일/카드, 한 실물의 여러 구획, 인쇄 그림과 실물의 차이 | 초기 재고나 법적 최대 수로 현재 물체 개수 채우기 |
| 관측 속성 | 읽는 면, 값 어휘·동의어, 종류별 구별 특징, 표준 색 범례의 적용 조건 | 가린 면·덱 속·소유·현재 턴·선택 카드 정체 |
| 고정 관계/계산 경계 | 이미 확인한 두 반쪽의 결합, 관측값 합계, 검증된 표의 대응 등 조건부 계산 | 규칙에 맞도록 관측을 고치거나 점유/이력 역산 |
| 불확실성과 표현 범위 | unknown, 그룹 관측의 수량 불명, 어떤 값은 계약에 없는지 | 미확인을 0/없음으로 바꾸거나 개별 배치 가능으로 과장 |

우선순위는 **(1) 설명·관측면·실물 단위가 실제 요청 계약과 맞는지 정리 → (2) 필요한 짧은 특징만 선택 전달 → (3) 판본/관측이 확인된 계산만 코드로 처리**다. `buildGeminiGameBody`가 현재 sourceText를 전부 보내지는 않으므로, 팩에 문서를 늘리는 것과 모델이 이용할 정보가 늘어나는 것은 별도다. 반대로 일반 규칙 전체를 전달해도 실제 물체 분해가 자동 해결되지는 않았다. 킹도미노 번호의 면 정보처럼 명백한 계약 불일치는 프롬프트 문장으로 우회할 문제가 아니다.

이번 동결 부록 네 개는 실험 자료로 보존한다. 그대로 전 게임 기본 프롬프트로 적용하는 것은 권고하지 않는다. 참조 이미지·추가 모델 학습·전체 규칙 RAG의 효과는 이번에 비교하지 않았으므로 채택/폐기 판단도 하지 않는다. **자동 배치·그림 편집·저장 복원 성공률, 사람 정정 시간의 개선은 모두 미측정**이다.

독립 사진에서 재검증한다면, 기존에 이미 잘 읽는 표본을 반복하기보다 실제 실물 구분/속성 어휘가 어려운 작은 사례에서 같은 조건의 부록 유무를 비교하고, `개별 회수 + 그룹/누락 범위 + 추가 오인`을 함께 보아야 한다. 이번 결과를 맞추도록 부록·정답을 수정하지 않으며 추가 호출은 실행하지 않았다.

공식 규칙·논문과 이전 동결 설계는 [README](README.md)의 근거 링크를 따른다. 4쌍의 작은 결과와 기준의 한계를 넘는 보편 개선 주장을 하지 않는다. 연구 산출물 인계 후 편집권을 반환한다.
