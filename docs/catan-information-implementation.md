# 카탄 핵심 정보·자산·항구·교역 구현

기준: [승인 연구 명세](catan-information-priority-research.md). 기본판 3–4인 기록·확인·보관·재개에 적용했습니다. 전체 자동 플레이 엔진은 포함하지 않습니다.

## 연결한 제품 흐름

- 현재 차례·단계·실제로 남은 처리 → 바다/항구 포함 기준판 → 플레이어 공개 행 → 지금 필요한 질문. 전체 구성물·근거·원시 기록·범위 정정·완료한 포장/복원은 기본 닫힌 더 보기로 접근합니다. 조각을 선택하면 필요한 종류/소유/위치 정정이 열립니다.
- `SceneWorkspace`는 확정 `board.layout`을 우선합니다. 새 후보는 명시적으로 선택해 정정 미리보기로 열며 기준판·부분 관측·카탈로그를 합산하지 않습니다.
- 자원·개발 카드에는 그림과 정수 입력을 제공합니다. 빈 칸은 null, 확인한 없음은 0. 부분 합계는 정확한 총수로 승격하지 않습니다. 별도 공개 총수와 완전한 종류별 합계가 다르면 conflict를 표시합니다.
- 공개 행에는 확인한 자원 총수·설치물·공개 점수·타이틀·기사·최장 길이·자원별 비율을 표시합니다. 개인 화면에만 개발 카드 정체·비공개 승점·개인 총점을 표시합니다. 기본 공급량−관측량을 남은 재고로 확정하지 않습니다. 실제 재고를 먼저 쓰고, 기본 공급량과 층 전체를 명시 확인했을 때만 계산 재고를 제공합니다.
- 공용의 브리핑/차이/사진 대상은 같은 visibility 선택자를 사용합니다. 공개 가능한 플레이어 총수라도 타인의 개인 사진·crop·판독 이유는 공용 대상 상세에 복제하지 않습니다. 공용 교역 도우미는 타인의 비공개 종류별 손패를 읽어 부족 여부를 공개하지 않습니다.

## 항구·장면

장면 v2는 harbor, ratio, 층별 coverage를 추가합니다. 지형/숫자/건물/도로/항구의 완전 확인은 독립입니다. v1은 계속 읽고 항구 확인 범위는 미상입니다. 기존 token.variant=harbor는 종류·비율을 모르는 항구로 읽습니다.

해안 30변/30꼭짓점 중 실제 항구를 기록합니다. 두 이용 접점은 edge.vertexIds에서 도출하며 중복 저장하지 않습니다. 바다 쪽 표식과 두 접점 연결선이 그림판에 표시됩니다. 같은 해안 변의 도로와 항구는 독립층입니다. 항구 이동은 드래그/탭/위치 목록이 같은 순수 helper를 사용하며, 점유되면 두 항구 위치만 한 번의 undo 트랜잭션으로 교환합니다. 건물·손패·지형·숫자·사진 출처는 옮기지 않습니다.

내륙 신규 배치는 거절합니다. 이미 기록된 실제 위반/비율 불일치는 삭제·자동 수리하지 않고 경고합니다. 전체 항구를 확인했다고 표시했을 때만 기본 9곳(일반4·자원별 각1)과의 구성 불일치를 검사합니다. 기록 3곳에서 나머지 6곳을 만들지 않으며, 모순된 전체 확인 표시는 최선 비율의 확정 근거로 쓰지 않습니다.

모델 schema/prompt, normalization, legacy bridge, 저장, 비교가 같은 harbor/ratio/coverage 계약을 유지합니다. 프롬프트는 관측되지 않은 항구·표준 지도·소유자를 만들지 않도록 지시합니다. 실모델 항구 인식 성능은 이번 작업에서 측정하지 않았습니다.

## 교역과 카드 수명

항구의 두 접점 중 하나에 확정한 자기 마을/도시가 있을 때만 접근합니다. 도로만 닿는 경우는 제외합니다. 은행4/일반3/해당 내는 자원2 중 최소 확인 비율을 제시하며 도시가 1:1을 만들지 않습니다. 같은 자원을 양쪽에 넣거나 자원을 섞어 은행 비율을 맞추지 않습니다. 여러 항구는 곱하지 않습니다.

교역 화면은 주고받을 종류/수량, 해당 항구 강조 지도, 차례·단계·남은 처리·실제 손패/은행 미확인 사유, 실제 전달량을 기록합니다. 계산·기록·저장·복원은 손패/은행을 자동 차감하지 않습니다. 진행 중 전달을 보존하고 계획 밖·초과 전달도 지우지 않고 확인 사유로 남깁니다. 완료/취소 거래를 재실행하지 않습니다.

신규 팩의 handCounts는 이번 턴 구매분을 포함한 미사용 전체입니다. purchaseBatches는 그 부분집합이며 다시 더하지 않습니다. 종류 미상의 실물 구매 묶음도 기록/보관할 수 있습니다. 전체 손패보다 현재 구매 부분집합이 크면 확인 경고를 표시합니다. 다음 턴에는 사용 제한만 만료하며 카드 수량·종류·구매 묶음은 남습니다. 사용한 기사는 별도 공개 수량입니다. 구분 종료는 전체 손패에 포함됨을 사용자가 확인하고 묶음을 정리하는 명시 동작입니다.

## 판본·조건·호환

신규 기본 팩은 2.0.0이며 새 일반 세션의 기본값은 6판/통합입니다. 기존 분리/통합과 build/action은 사용자 입력대로 유지합니다. 명시된 예시 방은 원래 2020 예시 프로필로 생성합니다. 기존 저장본의 pinned pack, edition, handCounts 의미를 로드 시 바꾸지 않습니다.

구 판본에 없는 turn.trade/구매배치 입력은 참고 모드와 이유를 표시합니다. 기록 버튼은 비활성입니다. 기존 board.layout은 v1/v2를 읽을 수 있어 항구 정정·보존은 가능합니다. 기존 팩에 새 필드를 조용히 추가하는 마이그레이션은 하지 않았습니다. 기존 카드 기록도 임의로 신규 구매분과 더하지 않으며, 과거 group=turn이던 구매 정체는 다음 턴에도 삭제하지 않습니다.

초기 배치 차수/다음 말/실제 좌석 순서/시작 자원 완료를 입력합니다. 서로 떨어진 두 초기 거점을 연결 위반으로 차단하지 않습니다. 굴리기 전 행동 개발 카드 여부, 기사/7 원인, 효과 후 복귀 단계를 보존합니다. 기사는 버리기를 요구하지 않습니다. 남은 버리기는 명시 수량을 사용하고 현재 손패를 다시 절반으로 계산하지 않습니다. 완료한 생산 뒤의 과거 주사위를 필수 질문으로 반복하지 않습니다. 본인 차례의 확인된 10점 이상에서만 명시 승리/종료 기록 버튼을 제공하며 숨은 승점을 추정하거나 자동 종료하지 않습니다.
