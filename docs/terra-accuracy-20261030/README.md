# Terra 정확도 실측: Quacks 원인과 남은 8게임

`gpt-6.1-terra`를 24회 호출했다(승인 한도 30, 재시도 0, 최대 동시 3). 24회 모두 HTTP 200·completed였고, 반환 모델은 같았다. 상자 계약 위반과 디코더 거절은 0건이었다.

**디코드 성공은 정확도 성공이 아니다.** 아래 수치는 응답을 받기 전에 고정한 **AI 부분 기준**과의 대응률이다. 사람이 인증한 정답이 아니며, 게임 전체의 정확도도 아니다. Terra는 앱 판독 경로에 연결하지 않았고 제품 코드도 바꾸지 않았다.

## 1. Quacks 낮은 속성 점수의 원인 (개발 표본: 이미 본 C crop)

같은 요청 본문(terra-fix의 named-box 요청을 바이트 그대로)을 반복하고, 변형 두 가지를 각각 2회씩 보냈다. 기준 `6b7dc260…`는 변경하지 않았다.

| 요청 | 칩 개별 대응 | 속성 16개 중 정답 | chipNumber 원응답 상태(칩 19행 기준) |
|---|---:|---:|---|
| 이전 named 실행 (terra-fix) | 8/8 | 5 | chipColor 행 **누락** 19/19 |
| 같은 본문 반복 r1 / r2 | 8 / 8 | 13 / 14 | 판독 5–6, unreadable 9–10, occluded 4 |
| + 속성 행 채우기 문장 r1 / r2 | 8 / 8 | 14 / 13 | 판독 5–6, unreadable 9–10 |
| + 채우기 + 2배 Lanczos 확대 r1 / r2 | **0** / 8 | 0 / **16** | r2: 판독 13, unreadable 2 · r1: 묶음 1행으로 붕괴 |

- **VERIFIED: 5/16은 속성 행 누락 때문이었다.** 같은 본문을 세 번 보내 5, 13, 14가 나왔다. 5/16 회차는 chipColor 행을 통째로 빼서, 디코더가 not-present-unconfirmed로 채웠다. 다른 회차에서는 observedColor 행이 빠지기도 했다. 정답·채점 오류가 아니라 응답이 회차마다 필드를 빠뜨린 것이다.
- **VERIFIED: 채우기 문장은 숫자 판독을 바꾸지 않았다.** 2회 모두 기존과 같은 범위였다. 누락을 줄이는지는 이 표본 2회만으로는 판정할 수 없다.
- **추정: 숫자 unknown은 원본 해상도 한계로 보인다.** crop은 670×300이라 32px 패치가 210개뿐이다. 2배 확대한 r2는 숫자를 13/19 읽어 8/8을 모두 맞혔다. 하지만 같은 요청인 r1은 칩 전체를 한 행으로 묶어 붕괴했다. 개선 가능성과 불안정성을 함께 확인했으며, 1회 성공으로 확정할 수 없다.
- 이 표는 개발 표본이다. 같은 사진을 보며 고친 결과이므로 검증으로 쓰지 않았다.

## 2. 미사용 사진 9장 검증 (Quacks 냄비 사진 + 남은 8게임)

- **사진과 기준:** 각 게임에 실제 사진 한 장씩을 썼다(W/D 쌍을 요구하지 않았다). Terra에 처음 보낸 사진이다. 기준은 20게임 연구에서 응답 전에 고정한 `references-sol1/sol2`이며, 이번에 SHA가 그대로임을 확인했다. Gemini는 같은 연구의 기존 응답을 썼다.
- **요청 두 가지:**
  - base: Gemini 기준 요청을 Terra 전송 형식으로 옮기고, 이름 붙은 상자만 적용했다.
  - improved: base에 채우기 문장과 Lanczos 확대를 더했다. 확대는 최대 2배이고, 문서에 적힌 high 처리 한도(2048px, 패치 2500개) 안으로 맞췄다. 실제 사진 픽셀만 다시 샘플했고 생성 이미지는 쓰지 않았다.
- **채점:** 세 응답 모두 같은 자동 채점기(`score_refs.py`)로 매겼다.
  - 실물 대응은 상호 유일 최대 IoU≥.25이고, 묶음 행은 개별 대응으로 세지 않는다.
  - 이 채점기는 Gemini에 대해 이전 수동 대응을 9/9게임에서 그대로 재현했다.
  - 값은 정확히 같을 때만 정답으로 본다.
  - 자유 텍스트 필드(색 묘사, 한국어·영어 표기)는 동의어를 자동으로 판정할 수 없다. 그래서 "정확 일치"와 "관측했지만 판정 안 함"으로 따로 표시했다.

| 게임 | 기준 실물 | Gemini 개별 | Terra base | Terra improved | 값 필드 정답 (G / base / imp) |
|---|---:|---:|---:|---:|---|
| Quacks(냄비) | 11 | 1 | 10 | 11 | 0 / 0 / 5 (오답 1) · 8 |
| Blokus | 2 | 0 (빈 응답) | 2 | 2 | 값 필드 없음 |
| Bohnanza | 4 | 0 (빈 응답) | 3 | 4 | 0 / 0 / 4 · 4 |
| Calico | 24 | 11 | 24 | 24 | 0 / 0 / 13 · 13 |
| Carcassonne | 31 | 17 | 17 | 17 | 16 / 5 / 13 · 44 |
| Cascadia | 39 | 17 | 18 | 18 | 0 / 0 / 0 · 21 |
| Sagrada | 21 | 21 | 21 | 21 | 0 / 0 / 15 (오답 4) · 19 |
| Splendor Duel | 25 | 0 (빈 응답) | 24 | 25 | 값 필드 없음 |
| Ticket to Ride | 78 | 1 | 4 | 6 | 값 필드 없음 |
| **합계** | **235** | **68** | **123** | **128** | **16 / 5 / 50 · 109** (오답 0 / 0 / 5) |

- **텍스트 필드(총 361개):** 정확 일치는 Gemini 88, base 144, improved 162였다. 관측했지만 판정하지 않은 값은 각각 22, 22, 33이다.
- **실물 찾기:** Terra는 Gemini보다 개별 실물을 많이 찾았다(68 → 123/128). 특히 Gemini가 빈 응답을 낸 Blokus·Bohnanza·Splendor Duel과, 개별 분리가 부족했던 Calico·Quacks에서 차이가 컸다. Ticket to Ride(78량)는 Terra도 6개뿐이다. 나머지는 묶음 행으로 반환해 개별 회수가 낮다.
- **base의 값 필드가 낮은 원인 (VERIFIED, 원응답 확인):**
  - Bohnanza·Calico·Carcassonne의 `face`, `city`, `road` 행을 **아예 빼먹었다**. 각각 9/9, 20/20, 4/4 누락이었다.
  - Sagrada `dieValue`와 Quacks `chipNumber`는 행은 있었지만 전부 unreadable로 답했다.
- **improved에서 달라진 점:**
  - 누락됐던 행이 채워졌다. face가 Bohnanza 10, Calico 19, Carcassonne 4개 관측됐다.
  - 숫자도 읽기 시작했다. Sagrada는 20개 관측(15 정답·4 오답), Quacks는 7개 관측(5 정답·1 오답)이었다.
- **두 변경의 효과는 분리하지 않았다.**
  - 누락 해소는 채우기 문장의 직접 효과로 보는 것이 자연스럽다. 이 문장은 행 존재만 요구하고 값은 지시하지 않는다.
  - 숫자 판독 개선은 확대의 효과로 추정한다. 개발 표본에서 채우기만으로는 숫자가 늘지 않았다.
- **오독도 생겼다.** 정답이 늘면서 Sagrada 4개, Quacks 1개처럼 틀린 값도 처음 나타났다.
- **Cascadia 값 21개는 세 응답 모두 0이다.** 타일 face/종류 필드가 기준과 같은 값으로 나오지 않았다. 원인은 따로 분석하지 않았다.

## 3. 시간과 사용량

| | 평균 초 | 중앙 | 최소 | 최대 | 입력 토큰 합 |
|---|---:|---:|---:|---:|---:|
| Gemini 기존(9장) | 13.22 | 11.67 | 3.25 | 24.08 | — |
| Terra base(9) | 22.41 | 24.04 | 9.87 | 31.51 | 14,987 |
| Terra improved(9) | 30.40 | 32.08 | 12.69 | 45.54 | 32,240 |

- **24회 합계 토큰:** 입력 55,733(캐시 write 51,417, read 4,244), 출력 47,229(reasoning 1,587).
- **비용:** 공식 Standard 단가로 환산하면 **$0.3007**이다. 무료 크레딧 차감이나 실제 청구는 확인하지 않았다.
- **확대의 비용:** 확대하면 입력 토큰이 약 2.2배, 시간이 약 8초 늘었다.
- **측정 조건:** 시간은 동시 3회 실행 조건이고 네트워크 시간을 포함한다. Gemini는 다른 날 최대 동시 5회 배치에서 잰 값이다.

## 4. Terra를 계속 쓴다면 개선 방향 (앱 연결은 이번 범위 밖)

1. 이름 붙은 상자 계약을 유지한다. 6+24회 모두 위반이 0이었다.
2. 속성 행을 빠짐없이 강제한다. 문장보다 강한 방법은 kind별 필수 속성 키를 스키마로 고정하는 것이다. 이번에 확인한 누락 원인(face 행 생략, 회차별 색 행 누락)에 직접 대응한다.
3. 작은 글자나 숫자가 있는 사진은 해상도를 확보한다. 원본을 고해상도로 촬영하거나 대상 영역을 크게 담는다. 확대는 효과가 있었지만 Quacks 개발 표본에서 한 번 붕괴했으므로 반복 검증이 필요하다.
4. 묶음 출력 대책: Ticket to Ride처럼 같은 실물이 많은 판은 Terra도 묶음으로 낸다. 영역 분할 촬영이 필요하다.
5. 숫자 오독이 생기므로, 앱에서는 읽은 값을 사용자가 고칠 수 있게 유지해야 한다.

## 5. 한계

- 조건마다 1회만 실행했다(Quacks 개발 표본만 2회). 반복 안정성은 확인하지 않았다.
- 기준은 AI가 만든 부분 기준이고 일부 이의 항목이 있다(20게임 연구 README 참조). 자유 텍스트는 자동으로 판정하지 않았다.
- improved는 채우기 문장과 확대를 결합한 변형이라, 두 효과는 원응답 필드 상태로만 구분했다.
- Gemini 응답은 이전 날짜에 받은 것이다. Gemini에 같은 개선을 적용하지는 않았다.
