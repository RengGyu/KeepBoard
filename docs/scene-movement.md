# 카탄 구성물 자리 이동

그림 보드는 사진이나 실물에 맞게 저장할 구성물을 편집합니다. 턴·비용을 처리하는 플레이 엔진은 아닙니다. 사진 출처(`evidenceId`)와 사진 영역(`region`)은 논리적 위치와 별개이며, 기존 구성물의 출처·영역은 이동·교환으로 바뀌지 않습니다.

## 교환과 수량

순수 이동 함수는 `shared/sceneMoves.ts`의 `moveSceneComponent`입니다. 드래그, 강조된 목적지 탭, 위치 드롭다운, 빈 타일에서 새 구성물 추가가 같은 함수를 사용합니다.

- 도로는 같은 변의 도로와, 정착지·도시는 같은 꼭짓점의 건물과 자리를 교환합니다. 지형과 별도 숫자 토큰도 각각 같은 종류끼리 교환합니다.
- 교환은 기본적으로 두 구성물의 `location`만 바꾸는 한 번의 장면 변경입니다. ID·소유자·수량·그림 종류·방향·연결·사진 출처·사진 영역·메모를 보존합니다. 지형의 내장 숫자는 아래의 표현 분리 예외가 있습니다. 되돌리기 한 번으로 표현 분리와 교환 전부가 원위치로 돌아갑니다.
- 지형·별도 숫자 토큰·도둑은 같은 타일에 공존합니다. 서로 다른 레이어는 점유 충돌로 보지 않습니다. 지형을 옮길 때 관련된 원래 칸의 **알려진 `terrain.number`만 독립 숫자 토큰으로 먼저 분리하여 그 칸에 남깁니다.** 지형에서 내장 숫자 속성을 제거하고, 새 숫자 기록에는 기존 사진 ID만 이어받으며 독립 영역은 `null`로 둡니다. 별도 숫자 토큰·도둑·도로·건물은 따라 움직이지 않습니다.
- 내장 숫자가 `null`이거나 없으면 토큰을 추정해 만들지 않습니다. 내장 숫자와 독립 토큰이 이미 혼용되면 값이 같아도 자동 병합하지 않고 지형 이동을 보류합니다. 사용자가 원본을 보고 표현을 정리해야 합니다. 출발 칸이 미상인 지형의 숫자 위치도 추정하지 않습니다.
- 독립 숫자 토큰을 옮길 때도 알려진 `terrain.number`는 같은 숫자층의 점유입니다. 확정된 보드 출발지가 있으면 목적지의 내장 숫자를 먼저 독립 토큰으로 분리하고 두 숫자를 원자적으로 교환합니다. 새 토큰·출발 미상은 점유 안내로 거절합니다. 출발지나 목적지에 내장·독립 숫자가 이미 혼용되어 있으면 자동 병합 없이 보류합니다. 종류 정정으로도 내장 숫자 위에 독립 숫자를 추가하지 않습니다.
- 같은 자리(인접 타일 기준 별칭 포함)로 옮기면 변경 및 되돌리기 항목을 만들지 않습니다.
- 목적지가 비어 있으면 보드 밖 묶음에서 한 개만 분리해 놓습니다. 원래 묶음의 ID를 유지하고 수량을 한 개 줄이며, 새 조각은 사진 출처를 포함한 원래 속성을 이어받습니다. 묶음 수량이 1이면 기존 ID 그대로 이동합니다.
- 수량 0인 항목은 보드에 놓거나 복제할 수 없습니다. 수량을 모르는 보드 밖 묶음은 먼저 수량을 확인해야 합니다.
- 출발 자리가 없는 묶음·새 조각은 점유된 목적지에 놓지 않습니다. 기존 구성물을 먼저 빈 자리나 보드 밖으로 옮기라는 안내를 표시하며, 기존 것을 지우거나 임의로 공급처에 돌려보내지 않습니다.
- 같은 레이어의 출발지·목적지에 이미 여러 항목이 있거나 한 슬롯 수량이 2 이상이면 임의로 교환 대상을 고르지 않고 중복 정리를 안내합니다. 명시적인 ‘보드에서 빼기’는 중복 장면을 정리할 수 있도록 허용합니다.
- 종류 변경도 점유를 검사합니다. 이미 건물이 있는 꼭짓점의 다른 표식을 정착지·도시로 바꾸어 겹치게 만들 수 없습니다.

## 편집 화면

보드나 목록에서 구성물을 선택하면 ‘자리 옮기기’ 상태가 표시됩니다. 목적지 표시는 조각보다 위에 있어 점유된 자리도 누를 수 있습니다. 출발지 자체는 덮지 않아 선택한 조각을 바로 끌 수도 있습니다. ‘이동 마치기’를 누르면 다시 다른 구성물을 선택할 수 있습니다. 위치 드롭다운과 ‘보드에서 빼기’도 같은 이동 함수를 거칩니다.

목적지 표시는 교환·배치 제한·규칙 확인 필요를 구분합니다. 드래그 미리보기와 위치 메뉴도 같은 이동 결과를 사용합니다. 제한된 목적지는 안내를 열 수 있도록 클릭 가능하며, 적용하기 전까지 원본과 공급 수량은 그대로입니다.

## 기본판 규칙과 원본 보존

규칙 검사는 `shared/catanPlacement.ts`에서 **최종 장면**을 기준으로 계산합니다. `shared/scene.ts`의 기하 호환성·정규화 계약은 그대로입니다. 경고 때문에 저장을 차단하거나 불러온 구성물을 자동 수정하지 않습니다.

| 조건 | 보드 밖·미상 자리에서 새로 놓기 | 기존 보드 위치·종류·값 정정 |
| --- | --- | --- |
| 한 변만큼 인접한 알려진 건물 | 새 건물 배치 제한 | 거리 경고와 함께 보존 |
| 알려진 사막에 숫자 | 새 배치 제한 | 숫자를 삭제하지 않고 경고 |
| 보드 위 두 번째 도둑 | 새 배치 제한 | 중복 경고와 함께 보존 |
| 도로·정착지 연결 불확실 | 확인 필요 경고 | 확인 필요 경고 |
| 6·8 숫자 인접 | 판본·배치 방식 확인 경고 | 같은 경고 |
| 자기 마을의 과거 기록이 없는 도시 | 도시 자체 입력 가능 | 종류 정정 가능 |

새 배치가 위 세 가지 확정 충돌로 제한되면 **‘원본대로 기록’**을 명시적으로 선택할 수 있습니다. 이는 사진에 이미 존재하는 상태를 기록하는 경로이며 경고를 없애지는 않습니다. 기하 불일치·수량 0·임의의 교환 대상 선택·숫자 이중 표현 자동 병합은 이 경로로 우회하지 않습니다. 변경된 장면에 낡은 원본 기록 요청을 재사용하지 않도록 장면 일치도 확인합니다.

거리 검사는 해안을 포함해 실제 위상의 한 변 양끝만 검사합니다. 도로는 양 끝 중 하나에서 자기 건물 또는 막히지 않은 자기 도로와 연결되는지 봅니다. 알려진 상대 건물은 그 꼭짓점을 통한 연결만 막고, 반대 끝의 유효한 연결은 인정합니다. 소유자 미상은 상대라고 단정하지 않습니다. 기존 도로 전체가 하나의 연결망이거나 자기 정착지까지 이어지는지는 요구하지 않습니다.

`coverage: full`은 촬영 범위입니다. 조각·소유자·초기배치 단계·과거 건설 이력의 완전성을 뜻하지 않으므로 연결 실패를 확정 위반으로 강제하지 않습니다. 종류를 도시로 바꾸는 것은 분류 정정이며 도시 업그레이드·마을 반납·비용·턴을 실행하지 않습니다.

## 도둑 위치와 질문·재개 동기화

`SceneWorkspace`와 사진 대상 상세의 `SceneEditor` 저장은 `sceneAnswers`를 공유합니다. 공용 `board.layout` 저장 시 게임팩에 공용 `robber.hexAnchor`가 있으면 **같은 PATCH의 answers**에 함께 보냅니다. 수량 1의 도둑 기록이 유일하고 유효한 hex가 확인될 때만 그 위치로 갱신합니다. 도둑 없음·중복·수량 미상·정확한 위치 미상은 `null`로 보내 낡은 별도 사실을 지우고 다시 질문하도록 합니다. 다른 게임팩·개인 장면에는 이 동기화를 적용하지 않습니다.

테스트: `tests/scene-moves.test.ts`, `tests/catan-placement.test.ts`, `tests/scene-answers.test.ts`. 교환·Undo용 불변 원본, 숫자 분리와 이중 표현, 새 배치 제한과 원본 기록, 거리·연결·미상 정보, 별도 도둑 답변 동기화를 검사합니다.

공식 근거와 적용 범위는 [배치 연구](./catan-placement-research.md)에 정리되어 있습니다. 주요 근거: [CATAN 6판 규칙 8–9·11–12쪽](https://www.catan.com/sites/default/files/2025-03/CN3081%20CATAN%E2%80%93The%20Game%20Rulebook%20secure%20%281%29.pdf), [기본판 공식 FAQ](https://www.catan.com/faq/basegame), [구판 기본판 규칙 13쪽](https://www.catan.com/sites/default/files/2021-06/catan_base_rules_2020_200707.pdf). 이번 구현은 기본판의 국소 배치 확인이며 전체 게임 합법성 판정이 아닙니다.
