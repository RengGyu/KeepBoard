# KeepBoard 보드 중심 UI 시안

**완성한 것:** 한 가지 디자인 방향의 독립 HTML 시제품, 모바일390×844 / 데스크톱1440×1000 실제 브라우저 화면 PNG18개, 텍스트·기존 아트를 벡터로 나눈 SVG18개. 제품 소스는 변경하지 않았다.

서버가 꺼져 있으면 프로젝트 루트에서 다음 명령으로 **이 시안 폴더만** 연다. 제품 서버와 별개이며 외부에 공개하지 않는다.

```sh
python3 -m http.server 4368 --bind 127.0.0.1 --directory docs/design/boardgame-companion
```

`index.html`을 브라우저에서 직접 열어도 화면을 볼 수 있다. 저장 지속성은 브라우저의 file URL 정책에 따라 달라지므로 위 로컬 주소를 권장한다.

## 확인할 흐름

1. **내 보드 → 새 보드:** 촬영 예시에서 사진을 담거나 뺀 뒤 그림 확인. 실제 카메라·AI는 실행하지 않는다.
2. **그림 확인 → 고치기:** 부품을 눌러 소유자 변경, 자리 옮기기, 도시/마을 변경, 삭제. 가까운 부품의 선택 영역이 겹치면 대상을 고르는 작은 목록을 띄운다. 전체 부품 목록도 별도로 제공한다.
3. **선택:** 여러 부품 선택/해제, 전체 해제, 공통 소유색 변경, 한 번에 삭제. 수정·이동·교환·삭제를 되돌릴 수 있다.
4. **추가:** `말 / 타일·숫자 / 카드·기타` 세 탭 → 종류 → 해당 설정 → 자리 → 놓기. 카드 추가는 내 보유로 연결한다.
5. **내 보유:** 처음에는 가림. 명시적으로 연 뒤 자원 카드를 눌러 수량을 수정한다. 공용 보드로 돌아오면 다시 가린다.
6. **차례·메모 → 저장 → 내 보드 → 재열기:** 보드·다음 차례·메모·카드 수량을 유지한다. 열기만으로 차례를 진행하지 않는다. 모르는 맥락은 나중에로 남길 수 있다.

390px에서는 선택 중에만 보드를 조금 줄이고 하단 조작면을 붙였다. 저장 버튼은 항상 하단에 남는다. 1440px에서는 보드 옆에 선택 설정을 두고 저장을 상단에 둔다. 보드게임의 느낌은 기존 타일·말 그림에서 얻으며 나무 배경·장식 대시보드·큰 홍보 문구는 사용하지 않았다.

## 파일과 편집

- `index.html`, `style.css`, `app.js`: 외부 라이브러리/CDN 없이 동작하는 시제품. 새 의존성 없음.
- `assets/`: 기존 `src/ComponentArt.tsx`, `public/carcassonne-art/*.svg`에서 정적 출력·복사한 아트와 합성 예시 보드.
- `screens/*.png`: 실제 CUA 캡처. CUA가 반환한 JPEG를 시각적 변경 없이 PNG로 변환했다. 원 캡처 JPG도 보관했다.
- `design-files/*.svg`: 브라우저에서 관측한 요소 좌표·글자·색과 기존 벡터 아트로 만든 편집 참고 파일. 글자는 `<text>`, 그림은 벡터 경로다. PNG를 통째로 넣은 SVG가 아니다.
- `design-files/*.layout.json`, `render-to-svg.mjs`: 관측한 배치와 SVG 재생성 도구. [tokens.json](design-files/tokens.json)에 색·간격·크기 기준이 있다.
- `?still=1`: 캡처용으로 진입 애니메이션만 끈다. 화면과 기능은 동일하다. 일반 시제품은160ms 전환 및 reduced-motion을 지원한다.

SVG는 기본 레이어를 편집하는 참고 파일이며 Figma의 Auto Layout/컴포넌트 라이브러리는 아니다. HTML/CSS가 상호작용과 반응형 배치의 기준이다.

## 시안의 경계

모든 인물·카드·보드는 합성 예시다. 사진 자리는 기존 보드 그림으로 대체했으며 실제 사진의 인식 결과를 주장하지 않는다. 촬영·읽기 시간도 예시 전환일 뿐 실제 스캔 성능이 아니다. 개인 가림은 화면 흐름 시연이며 인증·접근제어 구현이 아니다. 예시 저장은 이 로컬 시안의 `keepboard-design-saved-v1` 항목만 쓴다.

내 보드의 작은 미리보기는 대표 예시이며, 실제 수정된 부품 상태는 재열기 본문에서 유지한다. 조작 연결은 카탄 중심이다. 도로·건물·소유자·개인 수량·저장/재열기를 실제 예시 상태로 조작할 수 있다. 타일·숫자·항구 등의 탭/설정 화면도 있으나 판본별 배치, 전체 점유층, 항구 연결, 규칙 검증을 완성한 제품 엔진은 아니다. 배치 후보는 시연용 일부 자리다. 카르카손은 내 보드와 저장판 보기의 아트·레이아웃 예시이며 전용 편집 흐름은 이번 범위에 포함하지 않았다. 기존 제품에 옮길 때 기존 장면/게임팩 계약을 연결한다.

## 후속 구현에 넘길 결정

- 기존 저장/AI/장면 계약을 유지하고 화면의 정보 순서와 조작 위치부터 옮긴다.
- 공용/개인 탭, 그림/원본 전환, 기존 부품 수정과 새 부품 추가를 분리한다.
- 다중선택에서 공통 수정만 보여준다. 이동/교환은 단일선택에서 유지한다.
- 사용자에게 슬롯ID·규칙진단·원시JSON을 노출하지 않는다. 본인 카드 수량은 눌렀을 때만 편집한다.
- 보드가 덜 정리되어도 저장할 수 있고, 차례·메모를 나중에 채울 수 있다.
