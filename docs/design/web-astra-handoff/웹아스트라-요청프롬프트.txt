KeepBoard 모바일 앱·웹 UI 디자인 요청

역할
당신은 보드게임 도우미 제품의 UX/UI 디자이너입니다. 첨부 코드와 아트를 확인하고, 실제로 사용할 수 있는 모바일·데스크톱 시안을 만들어주세요. 기존 화면을 그대로 꾸미는 것보다 사용 목적에 맞게 재구성하세요.

제품 목표
실물 보드게임을 사진/카메라로 기록 → 인식한 판을 그림으로 표시 → 빠진 부품과 틀린 위치를 빠르게 수정 → 저장 → 같은 화면 그대로 다시 열기. 완전한 룰 판정이나 디지털 게임 실행기는 아닙니다.

디자인 방향
보드게임을 좋아하는 사람이 편하게 쓰는 도우미. 현재 UI는 AI가 만든 대시보드처럼 보여 바꾸고 싶습니다. Aftergame/BG Stats/Dized도 그대로 따라 하지 마세요. 기존 카탄·카르카손 구성물 그림은 마음에 듭니다. 게임판·말·타일 자체가 시각적 중심이면 좋겠습니다. 과한 나무 질감, 판타지 장식, 배지·카드 박스 남발, 거대한 홍보 문구, 과도한 여백과 작은 글씨는 피하세요. 색상 자체를 고정하지 않고 읽기 쉬움과 게임 분위기를 함께 설계하세요.

현재 기능과 유지할 계약
1. 내 보드: 검색·최근 기록·저장 여부, 새 기록, 개별/전체 삭제, 삭제 목록·복원. 샘플 데이터만 사용하세요.
2. 기록 시작: 게임 선택, 이름, 플레이어 이름·색상. 120종은 연구명세 초안만 있으며 제품 지원 완료가 아닙니다. 시안에 지원 완료120개라고 표시하지 마세요.
3. 촬영: 카메라/사진 선택. 촬영과 전송은 겹쳐 진행하며 최대6장. 전송·분석 진행 표시, 실패 사진 재시도/제외. 분석 결과는 확인·수정 가능한 후보입니다.
4. 공용 게임판은 하나입니다. 플레이어마다 같은 판을 복제하면 안 됩니다.
5. 수정: 보드 위 부품 선택·이동·교환, 별도 다중 선택 모드, 소유색 변경·삭제·undo. 부품 추가는 추가→종류와 필요한 설정→보드 탭 즉시 반영. 자리 선택/여기에 추가 같은 별도 확정 버튼 금지. 배치가 필요 없는 개인 카드는 수량으로 추가합니다.
6. 목록은 종류·소유색·변형별 수량 묶음. 모바일3열. 지형 안 숫자와 숫자 토큰을 중복으로 세지 않습니다. 선택한 묶음 안의 개별 부품을 편집할 수 있어야 합니다.
7. 소유색 선택과 플레이어·다음 차례 선택에는 실제 색칩과 이름을 함께 표시합니다. 이름·색상 편집은 소유자ID를 바꾸지 않습니다. 사진의 관측색과 연결이 불명확하면 사용자가 연결/정정할 수 있습니다.
8. 개인 보유는 자원·개발 카드·비공개 승점 등 수량·카드·메모·개인 사진 중심. 공용 화면에 개인 카드 종류를 노출하지 않습니다. 실제 인증/보안 기능은 시안에서 새로 약속하지 마세요.
9. 저장 후 편집 화면에 머뭅니다. 저장/이어하기를 별도 탭으로 나누지 않습니다. 다시 열 때 같은 판·메모·차례를 보여줍니다. 새 차례 시작은 명시적 동작이며 단순히 플레이어 탭을 바꿔도 턴이 넘어가면 안 됩니다.
10. JSON·AI/API 설정·전문 규칙 질문·긴 설명·정리보관 체크리스트는 사용자 화면에서 제외합니다. 꼭 필요한 차례와 선택 메모 등만 받습니다. 원본 사진 비교는 쉽게 접근할 수 있어야 합니다.

카탄 예시
육각형19칸/도로/마을·도시/숫자/도둑/항구, 플레이어 소유색과 개인 자원·개발카드. 공용판1개+개인보유. 항구는 해안 접점과 교역비율이 필요합니다. 모르는 수량을0으로 바꾸지 마세요. 충돌은 간단히 표시하고 고칠 수 있게 합니다.
카르카손 그림은 시제품이며 앱에 아직 연결되지 않았습니다. 다른 게임을 카탄 고정19칸에 억지로 맞추지 마세요.

접근성과 조작
모바일390px/데스크톱1440px를 모두 설계하세요. 터치 영역44px 이상, 본문은 편하게 읽히는 크기, 충분한 대비, 색만으로 구별하지 않기, 명확한 선택/초점 상태, 키보드 조작·화면읽기용 이름. 하단 고정 도구가 판이나 입력을 가리지 않게 하세요. 잘못 수정해도 undo로 쉽게 돌아가게 하세요. 설명보다 눈에 보이는 조작을 우선합니다.

원하는 산출물
한 일관된 디자인 방향으로 다음 화면을 실제 시안으로 만들어주세요:
- 모바일: 내 보드 / 촬영·분석 / 공용판 수정 / 부품 추가·다중선택 / 개인 보유 / 저장 완료
- 웹: 내 보드 / 원본과 그림판을 비교하며 수정하는 작업 화면
각 플랫폼에 맞는 배치로 만드세요. 모바일 화면을 단순 확대하지 마세요.
가능하면 클릭 가능한 HTML/CSS/React 프로토타입과 편집 가능한 Figma 레이어·링크, 핵심 PNG를 제공하세요. Figma 도구가 없다면 사용했다고 하지 말고 실행 가능한 코드와 이미지로 주세요. 기능이 구현된 것과 시연만 되는 부분을 구분해주세요.

코드 안내
첨부 sources/는 현재 UI 및 상태 계약을 이해하기 위한 스냅샷입니다. 백엔드·런타임 설정·개인 기록·API 키·node_modules는 포함하지 않았으므로 완전한 앱 실행용 저장소는 아닙니다. 필요하면 합성 fixture를 만들어 시안만 독립 실행하세요. 제품 API를 호출하거나 실제 사용자 기록을 읽지 마세요. 현재 UI 구조는 참고이며 그대로 유지할 의무는 없습니다.
주요 파일: App.tsx(내보드), SessionWorkspace.tsx(기록흐름), SceneWorkspace.tsx/SceneEditor.tsx(부품수정), CatanOverview.tsx(보유), Capture.tsx(촬영), ComponentArt.tsx/CarcassonneArt.tsx(그림), shared/types.ts(상태계약).

완료 시
처음 화면과 가장 중요한 편집 화면 이미지를 먼저 보여주세요. 디자인 이유는 짧게 설명하고, 실제 렌더로390px/1440px 잘림과 주요 동작을 확인하세요. 단순 디자인 설명서로 끝내지 마세요.
