## 달라진 행동

- 기존에는 일반 group에 격자/슬롯 힌트가 없으면 일자 행을 사용했다. 이제 유효한 저장 위치·정식 칸·typed map·관계/추정 표시기를 먼저 사용하고, 정보가 부족한 bbox 관측에는 기존 사진 배열 표시기를 연결한다.
- 요청한 영역과 실제 관측 역할을 분리했다. 같은 허용 출처의 현재 실물만 관계로 연결하며, 명시 순서는 사진의 좌우 정렬에 덮이지 않는다.
- 구조 입력·프로젝터 버전이 달라지면 파생 장면을 갱신한다. 자산 로딩은 표시만 바꾸며 semantic ID·명령 대상은 유지한다. 같은 팩/판본/원명세의 현재 프로필만 선택한다.
- 구조 갱신 때 경쟁 수동 역할을 마지막 값으로 덮지 않고 원결정·대상 ID와 충돌/미적용 사유를 보존한다. 수동 split/merge의 회원은 유지하되 관측 순서는 최신 근거로 다시 만들며, 명시 수동 순서는 유지한다.
- 검증된 `same-visible-stack` 회원을 같은 가시 더미로 구분한다. 각 관측을 한 번씩 선택할 수 있고, 사슬·불완전/경쟁 관계를 임의의 더미로 합치지 않는다. 내부 순서·숨은 총수는 미확정이다.
- 하나비의 표시 격자/더미, 아줄의 가변 패턴 줄·벽·바닥, 카르카손 지도/점수 트랙, 도미니언 공급 더미 단위를 프로필 데이터로 구분했다. 기존 생성기를 재사용했고 다른 116종 생성 프로필은 그대로다.

408은 정확한 위치 수가 아니라 **원 관측을 누락·중복 없이 표시한 수**다. 실제 createApp/Vite/격리 Store에서 Chrome 844×390·390×844를 확인했다. 비교 이미지는 mounted 작업면의 기존 좌표·내용을 그대로 캡처했고 내보내기용 clipping만 해제했다. 충분한 브라우저 viewport를 사용해 이전 비교의 아줄 픽셀 누락·LC 상단 잘림을 반복하지 않았다.

별도 격리 사본에서는 하나비의 실물 선택→같은 assertion/piece 기존 상세→값을 바꾸지 않고 완료→저장→재열기를 확인했다. 검증된 더미+독립 singleton 합성 입력도 실제 앱에서 2회원 더미/독립 1개로 구분하고 같은 원 ID의 상세를 열었다. 합성 입력은 실제 사진 정답이 아니다.

## 남는 정보 부족

새 사진 일반화·판독 품질·실제 iPhone Safari는 이번 작업에서 측정하지 않았다. 옛 응답에 없는 역할·판·칸·방향 인접·더미 경계는 표시 연결만으로 정답이 되지 않는다. 기존 큰 251-snapshot 기록의 성능 회귀도 이번 범위 밖으로 유지한다.

Astra의 `N1-source-mismatch`는 receipt sourceImageSHA만 요청 pin과 어긋나게 바꾼 negative cache probe다. 정상 지원 전이인지 미확정이며 이번 material 3건과 분리해 원 결과를 보존했다. 이 불일치 상황의 후속 개선까지 완료했다고 주장하지 않는다.

새 provider 호출·판독 기본값 변경·운영 Store 접근·Sites/운영 배포는 없다. GitHub에는 승인된 진행 코드와 이 근거만 반영하며 기존 unrelated untracked 자료는 제외한다.
