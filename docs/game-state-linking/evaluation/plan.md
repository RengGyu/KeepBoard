## 같은 조건과 측정

- `deepseek-flash`, reasoning `high`, detail `high`, **max_output_tokens 32768** 유지. 현재 제품의 typed schema/정규화·같은 game/edition/sourceSHA·같은 허용 field/component/owner context를 사용한다. prompt/instruction/evidence ID는 쌍 안에서 동일하며 GT는 prompt에 넣지 않는다. 원본 대 crop 이미지 bytes만 바꾼다. A/B 처리 순서를 Splendor A→B, Sagrada B→A, SCOUT A→B로 교차한다.
- A는 기존 원본 그대로, B는 회전·보정·선명화·확대 없는 lossless crop. crop transform으로 원본 좌표에 대응시키며 새 게임 배치좌표를 만들지 않는다. 사진의 색/문자를 다시 그리지 않는다. Sagrada/SCOUT은 기존 **합성 owner 접근 문맥**을 유지한다. 비밀 앞면이 섞인 전체 원본을 public로 올리지 않고 `__photo.owner` 등 기존 허용 교집합만 사용한다. owner가 실제 사진 속 누구인지는 판단하지 않는다.
- 공식 [Vision](https://api-docs.deepseek.com/guides/vision/)은 이미지당 최대1024토큰 및 대략1300×1300 총픽셀 리사이즈를 설명한다(2026-10-23 열람). 이 원본들은 이미 긴 변1024 이하이므로 **해상도 상한 때문에 실패했다고 단정할 수 없다.** crop이 없던 원본 세부를 복구하지는 않는다. 이번은 좁은 입력/주변 문맥 감소의 실제 효과를 측정한다.
- 원문 JSON과 현재 normalizer 이후 앱에서 사용 가능한 typed 값은 별도로 채점한다. 동일 실물 대응 후 **정답 / 명시 오독 / 실물 누락 / 속성 null·미기재 / 대응 불명 / schema상 표현불가**를 분리한다. null을0, quantity를비용으로 바꾸지 않는다. confidence 문구나 label만 읽힌 값을 typed 정답으로 세지 않는다. GT 불명 항목은 분모 제외·UNKNOWN에 남긴다.
- 각 요청의 입력/출력/추론/캐시 토큰(반환된 항목만), HTTP·완료시간, 앱의 prepare/provider/normalize/commit 시간을 가능한 실제 계측값으로 기록한다. 미노출 provider 큐/첫토큰시간은 UNKNOWN. ROI 준비시간·bytes도 별도. 기존 파일 읽기/원본 업로드 시간과 분석시간을 혼합하지 않는다. **쌍별 ms 차이**를 보고하며 3쌍으로 p95/통계 유의성·120게임 정확도를 주장하지 않는다.

## 비용·중단 상한

[공식 가격](https://api-docs.deepseek.com/quick_start/pricing/), 2026-10-23: Flash 피크 기준 입력 cache miss **$0.30/백만**, 출력 **$1.20/백만**(추론 포함 provider usage 기준). off-peak 할인·캐시 할인을 계산에 기대지 않는다. **입력≤32768 / 출력≤32768 토큰**의 보수적 사전 한도를 적용하면 요청당 `$0.049152`, **6회 `$0.294912` → 총 승인 요청 상한 US$0.30**이다. 세금/환전 수수료는 별도다. 사전 입력 텍스트 UTF-8 bytes≤30000, 한 장 이미지≤1024토큰, 프로토콜 여유1024를 확인하며 tokenizer가 이 보수적 상한을 보장하지 않으면 호출 전 재산정/보류한다. 응답 토큰 상한에는 reasoning을 포함한다.

기존 high 3회는 입력1933/2810/2493, 출력14044/14645/17168토큰·완료약79/71/90초였다. 이를 단순 참고치로 복제하면 6회 약 **$0.1144**, 확정 견적은 아니다. 새 prompt/모델의 토큰과 시간이 달라질 수 있으므로 실제 비용은 반환 usage로 다시 계산한다. 현재 서비스 무료 한도나 월 AI 잔액을 읽거나 보장하지 않는다.

**실패·timeout 포함 총6요청, 자동 retry0, 추가 모델/none 실험0.** 가격·허용 scope·사진 SHA가 바뀌거나 입력 한도를 넘으면 그 요청은 보내지 않는다. scope 위반/키 노출/해석 불가능 GT/비용 상한 초과 예상이면 즉시 중단. 실패 후 임의 재호출하지 않는다. 사전 source/GT/ROI/prompt/가격/claim을 고정한 뒤 감독 범위 확인을 받아 실행하며, production 기록·후보는 변경하지 않는다.

연결 품질(120행·747합성 조합 통과)과 이 실사진 파일럿은 서로 다른 근거다. ROI가 정확도를 개선하지 않으면 그대로 실패·한계를 보고하며 자동 기능 확대나 모델 하향 변경을 하지 않는다.
