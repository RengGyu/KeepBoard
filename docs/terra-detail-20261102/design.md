# 세부 판독·자료형 수정 사전 계획

- 사용자 승인 범위: 모름/없음 공통 편집 표시, 작은 숫자·형태 판독(원인1), 자료형 계약(원인3) 수정과 재비교. 게임별 답/재고/오답 목록을 제품 지시문에 넣지 않는다.
- 후보 v4: 기존 v2 명명 좌표·전체 항목·모델 low·원본 사진 high·출력한도 유지. 개별 작은 표식 계수/방향/격자형태 확인 지침과 정의에서 생성한 속성별 JSON 문법 추가. 짧은 v3는 미수정.
- 자료형은 marks에 한해 손실 없는 symbol→value 사전을 symbol/value 행 배열로 변환. 문자열 숫자/음수/중첩 자료를 추측 변환하지 않는다. 원응답과 원문 items는 그대로 보존. v1/v2 기존 요청/해독은 유지.
- 이번 최소 시도는 픽셀을 추가하는 크롭 구현이 아니다. 같은 사진에서 세부 확인 지침이 도움이 되는지 검사한다. 결과가 나쁘면 향상으로 발표하거나 지시문을 사진에 맞춰 반복 튜닝하지 않는다.
- 기존 10장: 새 후보 10회; 이전 v2 역사적 결과와 비교하므로 1회 샘플 변동 한계가 있다. 이전 원응답을 새 decoder로만 재생해 계약 수정 효과도 분리한다(추가 호출0).
- 독립 보류 사진 1~3장: 구현을 보지 않은 별도 주석자가 새 사진과 기준표를 호출 전에 동결. 각 v2/v4 1회, 최대6회. 총 신규 최대16회/재시도0. 코드 동결 후 기준표를 소비한다. 후보 출력 확인 뒤 같은 사진에 맞춘 변경은 하지 않는다.
- 원래 채점의 기하 대응·문자 동의어·기준 감사 적용을 그대로 재사용. 모름/없음 표시를 통일해도 실제 false/0/null의 정답 구분은 유지한다. UI 표기가 같다는 이유로 모름을 정답 처리하지 않는다.
- 정상 처리/물체 누락/값 오독/모름/형식/시간/저장재개를 구분하며 숫자별 수정 전후와 새 오답을 보고. 임의 정확도 합격선은 추가하지 않는다. 새 사용자 기기 촬영·카탄 native 경로의 정확도는 이번 일반 사진 판독 비교로 보장하지 않는다.

## 실측 후 적용 범위 분리

기존 10장 후보 v4는 정답과 오독이 함께 늘어 기본값으로 적용하지 않는다. 제품 기본은 v5(자료형의 손실 없는 정규화만)이며, 모델 요청 body는 v2와 byte-identical이다. 새 세부 판독 지침 v4는 명시 선택형 비교 후보로 남긴다. 후보 자체를 출력에 맞춰 재튜닝하지 않았다. v1/v2 고정 프로필은 기존 해독을 유지한다. v4의 요청 body SHA와 helper SHA는 동결 후 그대로인지 확인한다. v5 효과는 같은 이전 원응답의 decoder-only 재생으로 분리하며, 새 인식 정확도나 속도 향상으로 부르지 않는다.
