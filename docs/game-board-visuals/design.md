# 게임별 기록 한눈보기 · 설계 제안

상태: **제품 구현 전 / root 계약 확인용**. 요구된 원본·아트·현재 저장기록은 읽기만 했다. 이 파일만 작성했다.

## 목표와 관찰

119게임(rummikub 제외)의 실제 저장 구성물을 판·개인매트·카드줄 위에 보여 주고, 선택→짧게 수정→상단 저장→그대로 재열기를 공통 UI로 연결한다. 기존 Catan canonical 보드와 Rummikub 전용 편집기는 유지한다. 자동인식/자동생산/규칙판정·상업 보드 인쇄 복제는 추가하지 않는다.

직접 전수 읽기 결과 119게임/522영역: zone282, stack80, track60, grid40, graph35, hex23, free2. area confidence는 recommendation518/reported4이고, fixed_slot_count가 채워진 것은 Catan19뿐이다. 따라서 형상 타입은 선택할 수 있으나 나머지 게임의 인쇄 슬롯/정확 연결/칸수/세부 회전을 이 데이터만으로 확정할 수 없다. 명세의 권고 anchor_contract 문장을 검증된 기하로 승격하지 않는다.

현재 GenericRecord는 실물 id/componentId/variant/quantity/label/anchor/evidenceId/region을 보존한다. 좌표·부착관계는 구조화되어 있지 않다. 기존 아트의 areas.art_reference는 canonical_layout:false인 대표형이다. **카르카손은 기존 타일·미플 아트/점수말은 있으나 현재 제품에 정확한 전체지도 편집기가 있는 것은 아니다.** 타일 아트를 새 정정 캔버스에 재사용한다.

## 선택할 접근

1. 배경119장을 개별 제작: 중복이 크고 사진·기록과 무관한 그림으로 끝남 → 제외.
2. 게임마다 정확한 기하/슬롯 엔진 작성: 현 근거로 불가하며 서버/팩 확대 필요 → 제외.
3. **명세 영역별 매핑 + 적은 공통 표면 + 실제 저장 실물 레이어**(제안): 기존 게임별 구성물 그림·판 대표형을 재사용하고, 격자/타일자유배치/개인매트/카드/트랙/네트워크를 기록용 표면으로 연결한다. 원본확정 기하는 별도 source-pending으로 남긴다.

## 시각 계약

- 새 SVG는 public/game-art/boards/ 아래 **최대6개 공통 넓은 표면**: free-table, square-mat, hex-mat, personal-tray, card-lanes, track-mat. 먼저 기존 공통 도형/board 자산으로 충분한지 대조해 불필요한 것은 만들지 않는다. 네트워크는 중립 표면을 사용하고 가짜 도시·간선은 그리지 않는다. grid/hex는 스냅 없는 조용한 가이드이며 유한칸수/실물판 전체를 뜻하지 않는다.
- game별 별도 mapping에 gameId/editionId/sourceSHA/areaId/fieldKey/componentIds/template/artRefs/status/geometryStatus/visibility를 둔다. 기존437분류 mapping/assets/SVG는 재생성·수정하지 않는다. 공통영역 frames에 기존 tile/card/marker 그림을 **실제 기록 수만큼만** 얹는다. variant 미상은 unknown, 수량null은 `?`, 0은 `0`이며 장식 스택 수를 실물수로 계산하지 않는다.
- reuse: Catan native 그대로; Carcassonne 기존 tiles/followers/score adapter; 다른 게임의 board 대표형은 확정 세부기하가 아닌 보조표현으로 재사용. source-pending: 고정 지형/노선 연결 근거가 부족한 경우, 기록용 중립 표면은 사용하되 정확게임판 완료로 표시하지 않는다.
- not-needed: hidden/own-hidden/role-limited/shared-secret 영역에 내용 그림을 만들지 않는다. 기존 실물보관 절차만 유지. owner는 해당 플레이어 화면에서만 표시하고 실제 설정PIN 잠금 상태를 그대로 따른다. 공용개요에는 공개영역만, 타인의 owner 기록/이미지/근거는 포함하지 않는다.
- 원본 이미지와 보드 표면은 별도: source crop은 증거영역, placement는 사용자가 정정한 기록 배치. background를 실제 사용자 사진 위에 덮어쓰거나 사진좌표로 변환하지 않는다. UI 표기는 짧게 `기록 배치`/`크게 보기`/`미배치` 정도만 사용한다.

## 저장·호환 최소 계약 (승인 요청)

기존 `game-component-record-v1` 유지. GenericPiece에 optional `placement?: {areaId:string;x:number;y:number;rotation:number}`만 추가 제안. x/y는0..1의 **기록 표면상 사용자 지정 위치**, rotation은0/90/180/270(미설정은속성없음). 컴포넌트 ID/순서/수량/label/anchor/근거는 그대로다. 좌표는 board canonical/사진좌표가 아니며 연결·부착·합법판정을 나타내지 않는다.

- shared/genericRecord.ts 검증이 placement 존재 시 바인딩의 areaId·유한값·범위를 검사하고 그대로 반환한다. server/engine은 이미 이 validator를 호출하므로 서버 파일/스키마·팩 변경 없이 저장/스냅샷/복원 가능. 새 버전 migration/자동 생성 없음.
- placement 없는 예전 실물은 `미배치` 트레이에 **배열순서 그대로** 표시한다. 보기 좋게 정렬한 위치를 실제 저장된 위치로 표시하거나 anchor문자열에서 좌표를 추정하지 않는다. 사용자가 놓을 때만 placement 생성. 배열순서/같은 외형의 별도ID/수량의미는 보존한다. 묶음quantity는 펼쳐 여러타일로 복제하지 않는다.
- component/variant 미상은 첫variant를 선택하지 않는다. public 실물의 소유자를 그림 색이나 라벨에서 추정하지 않는다. 기존 GenericPiece에 소유색 자체의 구조화값이 없으므로 **해당 field owner의 확인된 표시색만** owner_color_supported에 적용하고, 공용 실물별 미확인 소유색은 중립색. 공용말 개별소유 추가는 별도 계약이 필요하므로 이번에 임의로 만들지 않는다.
- 새 매핑은 frozen sourceSHA/edition과 필드·분류 ID를 고정한다. 세션 runtime.source와 불일치면 현재 명세로 저장팩을 바꾸지 않고, 일치하는 기존 field/component만 중립 표면으로 표시한다. 모르는/opaque 구조는 원본을 유지하고 기존 보관안내로 연결한다. native Catan/Rummikub 값은 이 validator나 generic에 통과시키지 않는다.

## 실제 UI 연결·파일 소유권

- GenericComponents를 작게 추출/공통 BoardRecordView에 연결: 기본은 한눈보기(미배치 트레이 포함), 실물 탭→기존 종류/변형/수량/메모·원본 도구, 표면 탭으로 선택 실물 놓기, 90도 회전/다시 미배치/undo, 크게보기100~300%+pan. 이동/편집은 local draft이며 기존 onReadyToSave→GameEssentials saves→상단저장 흐름을 사용한다. 별도 저장 단계 강요 없음.
- 개인 화면은 허용된 공용개요＋선택 owner 영역만. 공개인 개인매트와 owner 비밀자료를 같은 범위로 합치지 않으며, 렌더는 현재 session 응답에 허용된 assertion만 사용한다.
- 신규: src/GameBoardRecord.tsx/.css, src/boardVisuals.ts(또는 loader/resolver 분리), tools/game-board-visuals/generate.ts·validate.ts, public/game-art/boards/*와 mapping.json, docs/game-board-visuals/*, tests/game-board-visuals*.test.ts.
- 기존 수정: src/GameEssentials.tsx(GenericComponents 연결/기존 flush), 필요최소 src/SessionWorkspace.tsx(owner공용개요에 필요한props), shared/genericRecord.ts(optional placement검증/타입). Catan SceneWorkspace·RummikubWorkspace·backend/AI/gamepacks/원명세/기존아트는 수정하지 않는다. 기존공통아트loader/renderer를 import 재사용한다.

## 집중 검증 / 구현 완료 기준

1. 전수119 sourceID/edition/hash·522area→field→component 참조 검사. 같은 입력의 재생성 bytes 동일, 기존437 assets 바이트 불변. 숨김영역은그림/입력할 수 없음. source-pending은 정확기하 완성으로 집계하지 않음.
2. pure: placement optional/범위·area검증, 예전v1 roundtrip/중복ID·null/0·evidence/순서보존, source mismatch fallback, unknown 유지, owner 분리.
3. fresh 키없는합성 API→제품 UI에서 6대표: Blokus(격자), Carcassonne(타일자유배치), Wingspan(개인매트), Splendor(카드진열), Monopoly(트랙), Pandemic(연결근거미확정/중립판) 각각 실제값 추가·자리정정→상단저장→reload. Native Catan/Rummikub 기존회귀 유지. 한게임의성공을119모두정확판지원으로 확대하지 않음.
4. 390확대/수정·320overflow0·PIN잠금/타owner비밀 DOM부재·원본근거 유지. 전체suite/typecheck/build는 최종통합1회; source쓰기 freeze 후 새tempStore/newport만 사용. 기존프로세스/Store/모델/배포 불변.
