## 같은 사진의 단회 비교

물체 수는 **출력 전 선택한 부분 기준에 대한 대응 수**다. 전체 사진 정확도·전체 출력 precision·완전한 배치 복원을 뜻하지 않는다. A/B는 같은 전체 사진, C는 그 사진의 정해 둔 부분이다.

| 게임 | A 전체-low | B 전체-high | C crop-low | provider 시간 A / B / C | 환산 달러 A / B / C |
|---|---|---|---|---|---|
| 카르카손 | 개별 10/16 | 개별 16/16 | 개별 10/16 | 24.00 / 174.38 / 17.26초 | .010814 / .079789 / .007887 |
| 사그라다 | 개별 20/21; 숫자 정19·오1 | 개별 21/21; 숫자 정17·오1·모름2 | 개별 21/21; 숫자 정16·오4 | 32.91 / 79.07 / 27.79초 | .014936 / .036036 / .012299 |
| 티켓 투 라이드 | 개별 25/25, 색25/25 | 개별 25/25, 색25/25 | 개별 25/25, 색25/25 | 70.66 / 82.24 / 35.22초 | .029008 / .037808 / .013878 |

해석과 유보:

1. **카르카손:** high의 추가 6개는 중간 신뢰의 타일 경계 기준이다. low가 큰 집합으로 표현했던 영역을 high가 개별 타일로 표현했다. 선택한 미플 10개는 세 조건 모두 대응했다. high 71관측 모두의 정체·타일 연결·정밀 위치가 맞았다는 뜻은 아니다. 엄격 색 점수 A/B 7/10, C 10/10의 차이는 3개의 `red`/`pink` 표현 차이다. 원사진에서도 붉은색과 분홍색 구분이 단정적이지 않아 **3개 확정 오독 또는 crop 개선으로 세지 않는다**. 동결 점수·기준은 수정하지 않았다.
2. **사그라다:** 숫자 고신뢰 18개만 비교하면 A/B 모두 정17·오1, C 정14·오4다. high의 추가 모름 2개는 원래 중간 신뢰 기준이다. 따라서 high가 확실한 숫자를 더 틀렸다고 해석하지 않으며, 모름을 오독으로 세지도 않는다. 반면 세 조건에 공통인 고신뢰 오독 1개와 C의 추가 오독 3개는 원사진 및 기존 확대 보기와 다시 대조했다. 입력 사진의 정보를 새로 얻은 실험은 아니므로 사진 해상도와 모델 내부 처리의 인과 전체를 분리하지는 못한다.
3. **티켓 투 라이드:** 선택 기물 25개와 색은 모두 대응했다. `groupSurface 0/8`은 별도 누락 8건이 아니다. 이 묶음 기준은 이미 개별로 회수된 기물들의 대체 표현이다. 판 밖·선택 밖·전체 노선 연결은 미평가다.
4. high의 `spatialDuplicateCandidates 7`도 실중복 7개가 아니다. 3개는 타일 위 미플이라는 정상 층 겹침이고, 나머지 4개는 인접 타일 박스와 거친 부분 기준이 함께 걸린 경고다. 독립 물체의 실중복/오연결로 확정하지 않았다. 해당 지표는 조사 후보로만 유지한다.

세 조건의 고정 개별 대응 합계는 A 55/62, B 62/62, C 56/62다. 이 값으로 서비스 정확도나 합격률을 만들지 않는다. high의 추가 회수는 중간 신뢰 타일 6개와 창문판 1개이며, 고신뢰 숫자 정확도의 추가 이득은 없었다. A 3회 비용 합 .054758달러, B .153633달러. 입력 토큰은 같고 B 출력은 9,586→29,361, reasoning은 330→10,379로 늘었다. 각 요청 시간이 늘었으나 샘플 1쌍/게임이고 순서·서버 부하·캐시쓰기의 일반 효과를 분리하지 못했다. 9회 실행기 전체 287.09초는 실제 사용자 한 스캔 대기 시간도, 세 요청의 동시 실행 시간도 아니다.

## 모델 판독과 제품 결합을 구분한 실패

**VERIFIED — 판독:** 사그라다의 오독과 high의 모름은 이미 provider 원문에 있다. normalizer가 숫자를 잘못 바꾼 사례는 이번 9응답에서 발견하지 않았다. 카르카손 low의 개별 타일 부족도 provider의 큰 집합 표현에서 시작한다. 출력 형태와 물체 세분화의 문제를 모두 사라진 데이터로 세지 않는다.

**VERIFIED — 결합:** [focused()](../../server/observationFusion.ts#L27)는 ROI가 작고 원본 대비 픽셀 밀도가 같아도 우선 후보로 인정한다. [projectGenericFusion()의 속성 선택](../../server/observationFusion.ts#L127)은 정수·불리언·enum에 이 우선순위를 적용한다. 이번 C는 외부 확대 없는 같은 원본 crop으로, 자체 밀도는 원본보다 높지 않다. 사그라다 A+C/B+C에서 모두 충돌 3개를 `focused-provisional`로 선택해, 전체의 맞는 숫자를 크롭의 잘못된 숫자로 교체했다.

| 최종 편집 가능한 결합 | 카르카손 개별 | 사그라다 개별 / 숫자 정답 | 티켓 개별 |
|---|---|---|---|
| A+C | 10/16 | 20/21 · 16/20 (고신뢰14/18) | 25/25 |
| B+C | 16/16 | 21/21 · 16/20 (고신뢰14/18) | 25/25 |

현재 delta3와 이전 preimage는 이번 3사진에서 동일 점수다. 따라서 새 묶음 퇴역 수정이 만든 퇴행이라고 보고하지 않는다. 기존의 crop 우선 규칙이 새 독립 사진에서도 불리하게 작동한 사례다. 사그라다 C의 창문판은 crop 경계에 걸려 미연결로 보존된다. 이는 원관측 소실이 아니라 배치 보류이며, 고신뢰 숫자 교체와 다른 문제다.

6개 결합을 현재 코드로 직접 재생했다. 원문·scope·원본 변환 보존, 완료 순서 역전, 반복 재전달, JSON 저장 왕복이 같았다. 선택 기준으로 평가 가능한 연결의 오연결은 0이나, 전체 출력 precision 검증은 아니다. **원문 보존 성공이 편집값의 정확성을 보장하지 않는다는 것이 이번 핵심 실패다.** [독립 재생 결과](independent-high-replay.json). 새 HTTP/UI 저장·재개·수정 시간은 이번 연구에서 측정하지 않았다.

## 가장 작은 다음 수정 계약 — 제안, 이번에 구현하지 않음

소유 후보는 기존 구현솔의 `server/observationFusion.ts` 속성 선택과 직접 회귀다. 판독 모델·팩·단위/좌표 계약·기하 동일성 임계값은 바꾸지 않는다.

- **같은 실물의 상충하지 않는 속성**은 계속 자동 보충하고, 개별화·crop-only 추가·묶음 퇴역은 기존 범위를 유지한다. 전체 관측이나 물체를 충돌 때문에 통째로 보류하지 않는다.
- **서로 다른 알려진 값**에서는 작은 ROI만으로 신뢰 우위를 부여하지 않는다. 사용자 정정은 최우선 보존. 그 외 기존 편집 선택 또는 결정적인 anchor 값을 *잠정값*으로 유지하고, 양쪽 원관측·출처·필드 충돌을 남긴다. anchor도 정답으로 승격하지 않는다. 이 정책은 맞는 crop으로 잘못된 anchor를 자동 정정할 기회를 일부 잃으므로 그 손해도 기존 회귀에서 함께 기록해야 한다.
- **모름/부재와 충돌은 구별:** 기존 값이 모름이고 대응된 새 관측만 값을 가질 때는 보충 가능. `0`, `false`를 모름으로 취급하지 않는다. 모름·수동 삭제·수동 모름을 덮지 않는 기존 보호를 유지한다.
- 필수 확인 단계·새 대시보드는 추가하지 않는다. 기존 [ScanFusionNotes](../../src/ScanObservationResults.tsx#L73)의 선택/대안 표시와 수정 없이 저장하는 흐름을 재사용한다. 더 선명한 새 근접 사진의 우선권은 이번 동일 원본 crop 결과로 정당화하지 않는다.

수용 검사: 게임명·정답값·고정 좌표 없이 **두 알려진 값 충돌/같은 값/한쪽 모름/0·false/수동값/응답 역순·재전달**을 합성 검증하고, 이번 6결합 및 기존 20응답을 오프라인 재생한다. 이번 사그라다의 3개 자동 교체가 사라지는지, 원관측과 정상 물체가 남는지 확인하되 이것만으로 품질 합격이라 하지 않는다. 새 정책 적용 후 이 3사진은 개발 회귀로 재분류한다. 독립 사진의 추가 호출은 이 보고서에서 발행하거나 승인하지 않는다.
