# 120종 게임팩 실사진 테스트 준비도 검토

검토일: 2026-10-26. **115종은 실테스트 진행 가능, 5종은 간단 보완 후 가능, 중요한 보완 필요로 판정한 게임은 0종**이다. 이는 현재 파일에서 입력·정정·저장·실물 보존 경로가 마련됐다는 판단이다. 사진 판독 정확도나 모든 규칙의 완성 인증은 아니다.

먼저 **스플렌더·카르카손·아줄·티켓 투 라이드·사그라다·스카우트·루미큐브**부터 시험할 수 있다. 공용판, 개인 공개판, 숨은 패, 순서 있는 패, 숫자와 색, 가변 타일을 서로 다른 사례로 볼 수 있다. 카탄도 판독 시험 자체는 가능하나, 보관 항목 중복을 먼저 고친 뒤 저장·재개 반복 시험에 넣는 것을 권한다. 이 보완 때문에 다른 게임의 시험까지 기다릴 필요는 없다.

## 무엇을 확인했나

- 실제 작업트리: `handoff/claude-gamepacks-ui-20261026`, HEAD `993bc4461baff9708b92c5a209ee8a7ac957f9cf` 위 로컬 수정 포함. [입력 목록·SHA](inventory.json)의 285개 파일을 고정했고 종료 시 변경 0개였다.
- 120개 정본의 영역·상태·보존 절차, 생성 팩의 편집 바인딩, 120개 촬영/사진 정의·비전 계약을 교차 확인했다. 게임별 실제 필드/영역/보관 ID와 관측 속성은 [review.json](review.json)의 `games`에 있다.
- 일반 상세 양식 117개와 생성 팩의 판본/원명세 핀이 일치한다. 카탄·루미큐브·스플렌더는 native/전용 예외다. 일반 보드 매핑은 119개이며 루미큐브 누락은 전용 화면 때문이어서 결함으로 세지 않았다.
- **VERIFIED_STATIC**: 파일 내용·소비 경로·참조/SHA 대조. **REPORTED**: 기존 명세에 인용된 규칙 사실. **UNKNOWN**: 실제 사진 성능, 모든 판본/카드 예외, 실제 기기 재개 경험. 원명세 최상위 confidence는 120개 모두 `reported`다. 이번에 공식 규칙서 전수 대조·브라우저·제품 테스트·실사진 호출을 실행하지 않았다.
- 생성물/해시 일치만으로 승인하지 않았다. 각 게임의 실제 구획과 중단 상태를 읽고, 같은 공통 소비 경로는 한 번 추적해 재사용했다. 앞선 post-review 보고의 통과 판정은 그대로 물려받지 않았다.

## 먼저 고칠 두 가지

**F01 — 네 게임의 새 기록 5개가 편집 화면에 연결되지 않았다.**

| 게임 | 필드 |
|---|---|
| 아컴호러 3판 | `event-discard.scene` |
| 듄 임페리움: 업라이징 | `intrigue-discard.scene` |
| 자이푸르 | `discard.scene`, `herd-private.scene` |
| 세븐 원더스 대결 | `discard.scene` |

정본과 생성 바인딩에서 이 필드들의 `component_ids/componentIds`와 `area_ids/areaIds`가 모두 빈 배열이다. [boardAreas](../../src/boardVisuals.ts)는 빈 영역 목록을 반환하고, [GameBoardRecord](../../src/GameBoardRecord.tsx)는 `if(!area)return null`로 끝난다. 부품 추가·선택·정정 UI도 그 안에 있어 항목명과 기록 버튼만 남는다. 이는 규칙 미확인이 아니라 코드로 확인한 구체적인 연결 누락이다.

최소 보완: 기존 카드 종류와 실제 버림/낙타 보유 영역만 정본에 연결하고 기존 생성 절차로 관련 팩·촬영·양식을 맞춘다. 임의 고정 슬롯이나 별도 엔진은 필요 없다. 자이푸르 비공개 낙타는 `player/owner`를 유지한다. **수용 예:** 각 5개 영역에서 부품 추가→정정→저장→재열기 가능, 비공개 낙타가 공용에 나오지 않음. 기존 다른 영역의 기록은 자동 이주시키지 않는다. 이번 검토는 제품 수정/재생성 없이 권고만 남겼다.

**F02 — 카탄 간편 모드에서 같은 보관 ID가 누적된다.**

[recompute](../../server/engine.ts)의 간편 모드는 기존 `session.preservations` 배열을 결과로 그대로 잡고 `spec.*` 항목을 다시 `push`한다. [현재 API](../../src/api.ts)는 생성·저장에 간편 모드를 사용한다. 무조건 적용되는 spec 템플릿은 공용 4개+플레이어당 4개여서, 4인 세션에서는 recompute 한 번마다 같은 ID 20개가 추가되는 구조다. [restoreOrder](../../src/Packing.tsx)가 화면의 중복 ID를 숨겨도 저장 배열의 중복은 남는다. 실제 사용자 데이터나 실행 세션을 열어 확인한 것은 아니다.

최소 보완: 유지할 비-spec 항목과 다시 만든 spec 항목을 ID당 하나로 합치고 기존 보관 위치/포장/복원 값을 이어받는다. **수용 예:** 정정·저장·재열기를 반복해도 동일 보관 ID는 하나이며 체크와 위치가 유지된다. 데이터 손실·비밀 유출로 확대 판단하지 않는다.

## 공통 흐름은 시험에 사용할 수 있다

[FieldEditor](../../src/Fields.tsx)는 빈 입력을 null로 처리하고, [상태 입력](../../server/engine.ts)은 null을 0으로 확정하지 않는다. [상세 판독 검증](../../shared/readouts/registry.ts)은 값과 근거의 null을 구분하며 실물 수량과 인쇄 속성을 별도로 보존한다. [사진 계약](../../shared/photoCapture.ts)과 [인식 구획](../../shared/recognition.ts)은 공개·개인 사진을 구별하고 공용 사진에서 개인 소유자를 자동 확정하지 않는다. `__photo.public`은 실행 시 추가되는 미귀속 트레이여서 원 생성 팩에 없다는 것 자체는 누락이 아니다.

[GameEssentials](../../src/GameEssentials.tsx)는 사진 후보와 확정 기록을 구별하고 사용자가 정정·적용한다. 복잡한 상태는 `record-note.*` 메모와 실물 보존 항목으로 넘긴다. [SessionWorkspace](../../src/SessionWorkspace.tsx)는 초안을 저장한 뒤 미완료 저장을 허용하고, [저장/재개](../../server/index.ts)는 상태·사진 근거·메모·보관 항목을 스냅샷에 남긴다. 이 공통 경로가 있다는 것이 판단 근거이며 실제 120게임 사진을 시험했다는 뜻은 아니다.

하나비의 자기 손패, 코드네임의 키, 진영별 비밀 계획은 일반 손패 입력으로 억지 변환하지 않고 `physical-only`로 남긴다. [개인정보 필터](../../shared/privacy.ts)와 [방 소비 경로](../../server/rooms.ts)도 읽었다. 로컬 공유기기의 PIN은 선택 기능이므로 여기서 전면 보안 인증을 주장하지 않는다. 검토 범위에서는 공개/개인 경계를 새로 넓혀야 하는 차단 결함을 찾지 못했다.

## 테스트하면서 다듬을 사항

- **루미큐브:** `timer`, `score`, `record-note.manipulation-baseline`, spec 보관 항목은 [전용 화면 분기](../../src/SessionWorkspace.tsx) 때문에 직접 노출되지 않는다. 그러나 [타일판·최초 등록·재배열 메모](../../src/RummikubWorkspace.tsx)와 개인 보관 메모가 있어 시험은 가능하다. 선언된 추가 필드를 모두 지원한다고 설명하지 말고 필요한 항목만 후속 연결한다.
- **방향·겹침·기하:** [일반 placement](../../shared/genericRecord.ts)의 회전은 90도 단위다. 60도/임의각·반사·층이 중요한 캐스캐디아·이클립스·루드비히·퍼즐 게임·세티 등은 원본 사진/위치·방향 메모/실물 묶음도 함께 확인한다. 대표 그림을 실물의 정확한 복원도로 보지 않는다. 이것만으로 모든 해당 게임의 사진/수동 기록 시험을 막지는 않는다.
- **외부 앱 게임:** 디센트 어둠의 전설·가운데땅 여정·광기의 저택 2판의 `external-save`는 원래 앱 저장 참조다. 그 앱의 저장을 함께 유지해야 한다. KeepBoard가 외부 앱 내부 상태를 복원하는 기능은 아니다.
- **판본·공개 관례 미확인:** 예를 들어 칼리코 손 타일, 일부 가린 보유·진행 정보는 현재 정의의 보수적인 소유자/실물 경로로 시험한다. 글룸헤이븐 등 판본 차이가 큰 게임은 실제 판본을 먼저 맞춘다. 전 카드 효과·점수 예외 검증은 초기 진입 조건으로 늘리지 않는다.
- **첫 실테스트의 확인점:** 사진 후보가 틀리거나 없어도 수동으로 고칠 수 있는지, 모름과 0이 다른지, 개인 패가 공용에 보이지 않는지, 정리 후 원본·메모·묶음으로 이어갈 수 있는지를 본다. 정확한 자동 판독률과 교정 소요 시간은 그때 측정한다.

## 감독 대조

보고서 수신 후 120개 ID의 누락·중복과 285개 입력 해시를 다시 확인했다. 입력 변경은 없었다. 지적된 다섯 필드의 `boardAreas` 결과가 모두 빈 배열인 것을 실제 호출로 확인했다. 임시 메모리의 4인 카탄 간편 세션에서 `recompute` 3회 후 보관 항목은 20→40→60개, 고유 ID는 계속 20개여서 중복 누적도 재현했다. 실제 사용자 저장소나 제품 파일은 변경하지 않았다. 위 115/5 판정은 실테스트 진입에 대한 검토 의견이며 실사진 인식 정확도나 전체 규칙 검증을 뜻하지 않는다.
