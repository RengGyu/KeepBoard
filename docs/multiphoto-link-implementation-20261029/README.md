# 여러 사진 관측 연결 수정과 재시험

## 최종 결과

아스트라 P0 설계를 구현했다. 원본 사진 누락을 부분 관측으로 보충하며, 불확실한 겹침은 물리 구성물 수량 대신 별도 관측 묶음으로 보존한다. 그림 아래 종류·핵심값·관측 건수 요약을 표시하고, 원문·원사진은 선택적으로 펼친다. 필수 확인 단계 없이 저장한다. 모델·지시문·출력 schema·게임팩·동시 실행 수는 바꾸지 않았다. 배포하지 않았다.

실제 재시험에서 발견한 추가 결함도 수정했다. anchor에 같은 종류가 있으나 원사진 상자가 없으면 crop이 별개 실물임을 증명할 수 없다. 이때 강제로 합치거나 새 실물로 추가하지 않고, 기존 항목을 유지하며 읽힌 부분 관측과 관련 실물 ID를 미해결 관계로 보관한다. 확실히 분리되는 crop 및 anchor가 해당 종류를 누락한 경우의 보충은 유지한다.

## 실제 API 재시험

원본1+동일 고정crop4, 실제 Gemini3.8 Flash LOW/HIGH/32768, 5요청 즉시 병렬·peak5·retry0. 실제 입력은 이전 시험과 SHA 동일이며 private 보존본을 사용했다. 모두 HTTP200/STOP.

| 항목 | 재시험 |
|---|---:|
| 최초 부분 결과 | 9.189초 |
| job 완료 관측 | 50.909초 |
| 업로드→저장·재열기 | **51.228초** |
| 전체 사진 API | 49.873초 |
| 부분 사진 API | 8.041 / 16.664 / 33.755 / 35.982초 |
| 입력 / 출력 / 사고 / 총 토큰 | 14,273 / 19,640 / 837 / **34,750** |

**30초 목표 미달.** 이전 실제 시험46.6초·32,837토큰 대비 이번51.2초·34,750토큰이다. 두 번 모두 단일 실행이고 반환 내용도 달라 코드 수정의 속도 악화율로 해석하지 않는다. 가장 느린 전체 사진 모델 요청이 여전히 병목이다. 미해결 묶음 생성 자체는 추가 모델 호출을 쓰지 않는다.

이 실제 재시험에서 숫자/도둑 중복 후보 문제가 발견됐다. 이후 일반 코드 guard를 고쳤으며, 최종 guard는 같은 실제 응답 재생으로 격리 검증했다. 공급자를 다시 호출해 다른 응답과 비교하지 않았다. 따라서 위51.2초는 최종 guard 적용 후 새 provider 호출의 측정값은 아니다. 모델 요청은 그대로이며 최종 로컬 보존·저장 동작은 별도 검수했다.

로컬 임시 Store이므로 Vercel/Supabase·실기기 카메라 종단 시간이나 배포 실행 한도 검증이 아니다. 실제 원응답·사진·최종 라이브 기록은 사용자 Library/Application Support/KeepBoard/research/multiphoto-link-live-20261029/에 비공개 보관했다. 자체 preview 프로세스만 종료했다.

## 남은 범위

항구 종류·비율 관측의 보존과 보드 위치 자동 확정은 다르다. 검증된 보드 정합·항구 접점이 없는 상황에서 해안 변을 억지로 확정하지 않는다. P1/P2 자동 정합·판본 참조 및 다른 시점 사진 연결은 이번 수정에 포함하지 않았다. 숫자·건물 등 모델 오분류/잘못된 제안 위치도 이 관측 보존 변경만으로 해결됐다고 주장하지 않는다.

정확한 변경은 `sol/implementation.patch`, 후속 중복 guard는 `sol/duplicate/implementation.patch`, 최종 파일 SHA·검증 집계는 `completion.json`에 있다. 읽을 핵심은 `server/scanObservation.ts`의 투영/미해결 보존, `shared/scanObservation.ts`의 가능한 관계와 확정 동일성 구분, `src/ScanObservationResults.tsx`의 요약·원사진 연결이다.
