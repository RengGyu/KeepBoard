## 사진에서 확인한 현재 차이

1. 사그라다 전경 18개 주사위의 36색·눈 속성: high 32일치/2오독/2모름, medium 35/0/1, low 34/2/0. 값과 위치를 별도로 기록한다. 이 한 사진으로 강도 일반 우열을 확정하지 않는다.
2. 로스트 시티 가까운 노랑 줄은 3·4·5·9·10이다. high의 6은 9 오독. 추가8은 겹친 상자 때문에 유보한다. medium의 세로 좌표 배율은 미확정 진단으로만 남기고 원bbox는 보정하지 않는다.
3. 세븐 원더스 수정 전 117관측은 74소속 일치/15다른 판/12사진 소속은 보이나 미분류/16유보다. 실제 판 무리5개에 응답의 기준판은4개다. 없는 판을 만들어 소속을 채우지 않는다.

위 숫자는 전체 실물 수·전체 사진 정확도·120종 정확도·5~10% 달성률이 아니다. 모름·대응 불가·가림·누락·역할·위치 오류를 분리한 원장은 `photo-audit/`에 있다.

## 통합 확인

감독 산출물은 `supervisor/`에 둔다. `replay-current.mts`는 기존9사례를 현재 제품 estimator와 실제 필드 renderer로 재생해 모든 실물의 표시 경로·단일 선택·입력 불변을 확인한다. `compare-current-anchors.py`는 동결된 사진 소속 판정을 새 구조에 다시 대응하며 새 정답을 만들지 않는다. `probe-manual-window.mts`는 실제 입체 주사위 bbox에서 수동 판 기준이 작동하는지 확인하는 예시이며 사진 정답표가 아니다.

최종 검사·화면·배포 상태는 작업 동결 뒤 아래에 기록한다. 기존 동결 자료의 수치를 새 코드의 정확도로 인용하지 않는다.

## 남은 실제 문제

1. 7W의 누락 기준판·관계 없는 카드 자동 연결, LC baseline의 경쟁하는 판 영역을 해결해야 한다. 현재는 가상판/강제 최근접 소속 없이 미연결을 드러내며 판·묶음 정정으로 처리한다. 원정/버림/색줄의 알려진 역할을 잃지 않는다.
2. LC medium의 y좌표 단위 가설과 추가8/넓은 low 상자는 유보 상태다. 원좌표나 원값을 정답에 맞춰 보정하지 않았다.
3. 카드명·작은 글자·가려진 값의 읽기 부족, 전체120종 정확도와 실제 iPhone Safari 종단 확인은 남았다. 사그라다 한 사진에서 medium이 좋았다는 근거를 전체 모델 기본값 결정으로 확대하지 않았다. 30초를 선행 기준으로 두지 않았다.
