# 전체 사진 판독과 영상형 스캔: 다음 최소 방향

확인일: 2026-11-01. **제품 변경·새 모델 호출 0회.** 현 소스, 동결된 Terra 응답 9개, 공개 영상 2개의 선별기 재생 및 1차 문헌을 대조했다. 현재 배포 상태·계정 설정은 조회하지 않았다.

**권고는 ‘전체 low의 물체별 판독을 먼저 공정하게 시험하고, 스캔은 비슷한 사진을 계속 추가하기보다 더 선명한 사진으로 교체하는 것’이다.** OCR·검출기·추가 high 호출을 기본 선행 단계로 두지 않는다. 코드에는 좌표 변환·형식 검사·근거가 있는 결합을 맡기고, 실제로 보지 못한 종류·숫자·가린 물체는 채워 넣지 않는다.

## 이번에 직접 확인한 것

- **현재 프롬프트에도 개별 물체·작은 물체·겹침·가장자리를 읽으라는 지시가 있다.** 따라서 “빠짐없이 읽어라” 한 문장을 더하는 것만으로 개선된다는 근거는 없다. 반면 모든 속성의 모름 행까지 출력하는 부담은 분리해 시험할 가치가 있다. [현재 지시](../../server/ai/geminiGameReader.ts#L20), [Terra 추가 지시](../../server/ai/terraGameReader.ts#L10)
- 저장 응답 9개의 **원출력 353행→정규화 353행**, 모두 완료 응답이었다. 이 표본의 누락을 파서 손실이나 출력 한도 초과로 설명할 수 없다. 카르카손 low는 묶음을 포함한 19행, high는 개별 71행이었다. **개별화 차이는 보이지만 전체 사진 정답 수는 모른다.** [새 원응답 감사](raw-audit.json)
- 사그라다는 전체 low가 선택된 숫자 20개 중 19개를 맞혔지만, crop-low 결합 뒤 16개로 감소한 기존 결과가 있다. 현재 `focused` 우선순위는 작은 ROI를 더 좋은 값의 근거로 쓰므로, **알려진 값끼리 충돌할 때 crop이라는 이유만으로 교체하는 규칙은 별도 보완 대상**이다. [기존 독립 검토](../terra-quality-iteration-20261030/independent-high-review.md), [실제 선택 코드](../../server/observationFusion.ts#L127)
- 기존 선별기를 공개 영상 첫 5초에 무과금 재생했다. Risk는 **20프레임 중 0장**(19프레임이 움직임으로 제외), 체스는 **2장**을 골랐다. 합성 경계검사에서는 같은 구도가 나중에 더 선명해져도 중복으로 제외됐다. 이는 선별 동작의 증거이며, 선택된 사진의 판독 정확도 검증은 아니다. [재생 결과](selector-replay.json)

## 먼저 실행할 작은 묶음

1. **촬영:** 같은 구도의 후보 중 좋은 한 장을 유지·교체하고, 작은 분석 영상의 전역 선명도와 원본 부분의 선명도를 구분한다. 최대 6장은 상한으로 유지하며 완성 판정으로 쓰지 않는다. 최초 단계에서 새로운 3D 추적기는 넣지 않는다.
2. **판독 시험:** 같은 전체 사진·low·출력 한도에서 현재 지시 / 물체별 열거 지시 / 모름 속성 행을 생략하는 지시를 비교한다. 현재 일반 decoder는 생략 속성을 모름으로 채울 수 있다. 카탄은 별도의 native 배치 경로이므로 같은 형식이라고 가장하지 않는다.
3. **결합:** 관측된 값은 보존하고 모름만 보완한다. 값 충돌은 기존 값과 대안을 함께 남기며, 수동값은 보호한다. 서로 다른 촬영 사진의 입력·병렬 처리는 이미 있으나, 자동 물체 정합은 검증되지 않았다.

**아직 모르는 것:** whole-low의 전체 장면 recall/precision, 새 지시의 효과, 저사양 폰의 선별 비용, 진짜 다른 시점의 추가 가독 정보, 사용자가 복원까지 고치는 시간. 과거 선택된 62물체와 AI 부분 기준으로 이 항목들을 확정할 수 없다. 다음 비교는 새 정지 상태 3개를 사람이 출력 전에 주석화하고 **최대 12회**로 제한하는 제안이며, 이번에는 실행하지 않았다.
