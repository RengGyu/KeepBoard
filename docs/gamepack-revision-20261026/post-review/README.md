# 993bc44 후속 검토와 반영

대상 커밋: `993bc4461baff9708b92c5a209ee8a7ac957f9cf`.
기존 인계 브랜치에서 해당 커밋까지 fast-forward했고, 아래 수정은 그 위의 로컬 변경으로 반영했다. 새 커밋·푸시·배포는 하지 않았다. 실제 사용자 저장소 대신 격리 복사본과 합성 세션으로 검증했다.

## 근거와 남은 범위

- [UI 독립 검토](ui-review.md), [데이터/호환성 독립 검토](data-review.md)는 **수정 전** 발견 기록이다. 위 표와 최종 검증을 함께 읽는다. ‘은퇴 일반 팩’과 기존 네이티브 API 호환은 별개다.
- [네 게임의 규칙 대조](four-game-rules.md), [세 게임 수정 근거](rules-evidence.json), [프로필 동기화](profile-sync.json).
- [120종 검토 현황](coverage.json): 개정된 명세는 누적 **20종**이다. 이번에 코드네임을 포함해 4종을 추가로 부분 대조했으며, Cloud의 미검토 91종 중 **87종은 여전히 이번 규칙 대조 미완료**다. 전체 규칙서·모든 예외까지 검증 완료한 것으로 표시하지 않는다.
- 코드네임은 출판사 게임 설명에서 공개 단어판/스파이마스터 키 구분을 확인했으나 정확한 2025판 규칙서를 열지 못했다. SETI의 아래 끼운 수입 카드 전체 정체가 공개인지는 현재 인용 근거만으로 확정하지 못했다. 가려진 정체를 추정하지 않는다.
- 실사진 인식 정확도는 새로 측정하지 않았다. 이전 카탄의 6/9 수동 참조 오판 지적도 유지한다. 이 검토는 그 수치를 새로운 정확도 확정값으로 사용하지 않는다.
- 실제 기기, 실제 개인 저장본 전체, 라이브 Gemini, 배포는 미검증이다. 합성 Gemini/관측 응답은 데이터 흐름 검증에만 썼다.

## 읽어볼 변경 세 곳

1. `src/SessionWorkspace.tsx`의 `cw-mobile-photo-tools`: 저장된 보드를 먼저 보여주고 촬영 설정은 한 번 눌러 연다.
2. `shared/readouts/registry.ts`의 `readoutDefinition`: 게임·판본·원명세가 모두 같은 양식을 찾아야 기존 값의 의미가 보존된다. `src/photoDefinitions.ts`, `shared/photoCapture.ts`, `server/photoDefinitions.ts`도 같은 원칙이다.
3. `tools/game-runtime/revision-ledger.ts`의 `buildLedger`: 검토한 정확한 파일만 생성한다. 같은 게임의 오래된 영수증이 새 변경까지 승인하지 않는다.

흐름: 저장본 판본 → 일치하는 촬영·상세 정의 → 관측 후보 → 사용자 정정·명시 반영 → 저장. 가려진 값은 미상으로 유지한다.

영어: **revision** 개정, **compatibility** 호환성, **preserve** 보존.
“The old save keeps its version.” “Unknown values stay unknown.”
확인 질문: 예전 저장본을 최신 입력 양식으로 자동 변경하면 어떤 값의 의미가 달라질 수 있을까?

최종 실행 결과와 범위는 `verification.json`에 기록한다.
