## 4. 결합·저장: 확인한 이득과 남은 실제 문제

- whole 대비 최종 **+4개**: Carcassonne +3, Splendor Duel +1. 숫자 일치 수는 늘지 않았다. 341개 원관측은 모두 남았고 완료 순서 역전·동일 단위 재전달은 10게임 모두 같은 의미 결과였다.
- **Carcassonne 결합 보류:** ROI `item-23`은 개별 타일인데 whole `item-1` 묶음과 부분 겹침이라는 이유로 보류된다. 해당 묶음은 이미 refinement로 편집 그림에서 빠졌으나 `aggregateCandidates`의 `partialParent` 경쟁자로 남는다. 원본 환산 child 아래끝 453.66px와 parent 453.12px의 0.54px 차이가 strict containment를 실패시킨다. 관련 ID는 편집 그림에 없는 parent를 가리킨다. [`server/observationFusion.ts`](../../server/observationFusion.ts), [원응답/투영 locator](case-audit.json)
- **Quacks 중복:** whole은 노란 물방울을 `goods`, ROI는 같은 물방울을 `pot`으로 읽었다. 같은 종류만 연결하는 현재 결합에서 둘 다 편집물로 남는다. 실제 중복 1개다. 이 사실로 판과 말처럼 정상적으로 포개지는 모든 다른 종류를 자동 합치면 안 된다.
- 중복 후보는 총 2개였다. 다른 하나인 SCOUT는 거의 가려진 초록 카드가 실제 있어 **미확정**으로 남겼다. 기준 내 오연결 확정은 0이나, 모든 멤버를 기준에 대응하지 못한 연결 3개와 표본 밖 출력은 인증하지 않았다.
- **저장 재생 10/10:** 별도 private Store에서 현재 HTTP `evidence → analysis-jobs → commit → resume`를 실제 실행했다. 외부 호출 대신 동결된 native 응답을 주입했고, 제품이 만든 body SHA 20개가 실제 요청과 같음을 확인했다. 10게임의 편집물 의미가 오프라인 결합과 같고, 저장 재개 후 값·관측 원문·crop 연결·소유 범위가 보존됐다. SCOUT 수동 `null`과 `quantity=0`도 보존했다. 이는 저장 기능 검사이며 실물 복원 성공이나 UI 정정 시간 측정이 아니다. [HTTP 결과](http-replay.json), [검사 코드](http-replay.mts)

첫 HTTP 시험 스크립트는 개인 job 조회에서 `ownerId`를 빠뜨려 timeout이 났다. 격리 저장된 실제 job은 completed였다. 이 시험 코드만 수정해 최종 10게임을 통과시켰고 첫 시도 기록도 보존했다. [첫 시험 기록](http-replay-attempt1.json) 두 번 모두 모델 호출 0이었다.

1. **관측이 이미 있는 결합 손실부터:** Carcassonne의 refined aggregate가 후속 child를 막는 경우를 저장된 응답으로 재현하고, 잔여 관측 보존과 실제 편집 경쟁자를 분리하는 좁은 수정부터 검토한다. Quacks는 cross-kind 충돌을 보존하면서 같은 물체를 두 번 만든 사례로 남긴다. 사진별 좌표·정답 수량이나 무조건 합치기를 제품 규칙으로 넣지 않는다.
2. **반환 속성 행 강화만 반복하지 않기:** 이번 341개 원관측은 속성 행 누락이 0인데 숫자 unknown·오독이 남았다. Q1 형식 요구는 연결의 전제이며 판독력 해결책이 아니다. 기존 원사진·수동 입력·미배치 관측을 유지한다.
3. **무조건 whole+ROI 2회보다 필요한 부분을 구분:** 토큰처럼 작지만 분리되는 물체는 이득이 있었고, Quacks·SCOUT는 누락이 늘었다. 사진이 흐린 값은 더 선명한 실제 근접 사진, 선명한데 잘못 읽은 Sagrada/SCOUT 값은 모델 판독 문제로 따로 시험해야 한다. 이 보고서에서 추가 호출은 하지 않았다.
4. **묶음과 기준을 바로잡아 평가하기:** Dominion은 더미 표면의 이름·종류 보존을 인정하되 숨은 수량을 추정하지 않는다. Ticket의 개별 차량 위치 미회수는 별개다. SCOUT/Codenames 의심 기준은 사람이 원사진을 먼저 확인해야 한다. 현재 기준을 결과에 맞춰 고치거나 새 전체 정확도를 산출하지 않는다.
