# 카탄 게임 과제 비교 결과

같은 사용자 사진 1장으로 **지형 hex·숫자 원판·도둑**을 읽었다. 새로운 실험은 총 **4/6회**를 사용했다: 유효 결과3회와 DeepSeek 스키마 오류1회다. 남은2회는 쓰지 않았고 자동 재시도는 없었다. 기존 일반 OCR 비교와 별도 실험이다.

|---|---:|---:|---:|---:|---:|---:|
| D1 Gemini3.8 LOW·사진-only | 19/19 | 18/18 | 1/1 | **38/38** | **13.59초** | $0.007014 |
| D2 Gemini3.8 LOW+필드 문맥 | 18/19 | 17/18 | 1/1 | **36/38** | **18.98초** | $0.01161825 |
| D3 DeepSeek Flash LOW+동일 문맥 | 14/19 | 9/18 | 0/1 | **23/38** | **89.28초** | $0.0211419 |

종류/값을 보지 않고 실제 물체 영역의 reciprocal unique maximum IoU>=0.25로 대응한 후 속성을 채점했다. D1·D2는 38개 모두 위치 대응됐고 D2의 두 오류는 밭을 목초지로, 숫자4를2로 읽은 값 오류다. D3는 **속성 오독10개 + 위치 미대응5개**(원판4·도둑1)이며 미상/모호0개다. D3의 미대응 출력5개를 별도로 남겼고 숫자값으로 재매칭하거나 재고 수에 맞춰 채우지 않았다. 모델별 원관측은 각각38개였으며 개수를 프롬프트로 주거나 결과에 강제하지 않았다.

GT v2는 새 응답 이전에 실제 원판·hex·도둑 영역38개를 독립 주석했다. **수작업 근사 경계이며 정밀 마스크가 아니고 가림이 있다.** 0.25는 사전 대응 정책이지 서비스 합격선이 아니다. 구버전 타일 중심 점수를 재사용하지 않았다. 원 IoU/중심 오차는 [집계 JSON](results.json)에 보존했다.

D1 입력/출력은1267/1617토큰, D2는2266/2645토큰이다. D3는입력1741/출력17183토큰이며 reasoning15973토큰이 포함됐다. 두 제공자의 LOW가 같은 계산량이라는 뜻은 아니다. 시간 표는 실제 `result.wallMs`를 사용했다. Gemini 가격 helper의 중첩 `usageAndCost.wallMs=0`은 placeholder이며 측정 시간으로 쓰지 않았다. 성공3회 list 추정 합계는 **$0.03977415**, 실제 청구·계정 tier·할인·offpeak 적용은 UNKNOWN이다. 실패 요청도 무료라고 주장하지 않는다. 모델 응답은 Gemini `gemini-3.8-flash`, DeepSeek `deepseek-flash` alias다. DeepSeek-V4.1-Flash-1017은 공식 문서의 alias 연결이며 실제 응답에서 weight revision을 따로 확인한 것은 아니다.

DeepSeek 첫 요청은 nullable 배열 스키마 `type:[array,null]`를 네이티브 API가 거절해 HTTP400으로 중단됐다. 모델 품질 실패가 아닌 요청 호환 문제다. 원문·실패 장부는 그대로 두고 **감독이 명시 승인한 복구1회**에서 해당 표현만 `anyOf(array,null)`로 바꿨다. 사진·문맥·과제·스키마 의미·LOW·출력32768·detail original·timeout180초는 유지했다. 복구 후 completed와 client schema 검증을 통과했다. Gemini 요청 본문은 변하지 않았다.

원문→정규화38개→오프라인 literal 필드 투영38개에서 세 결과 모두 **값·bbox·원출처가 보존됐다**. 이번 오독은 모델 원응답에서 이미 있었고 투영 중 새 값 오류는 없었다. `variant`/`number` 이름으로 투영 가능한지만 확인했으며, 실제 제품의 hosted ReaderIdentity·APIjob·assembly 검증 연결이나 기본 모델 교체를 수행하지 않았다. 기존 UI·저장·재개는 변경하지 않았다.

이 사진에서는 D1이 가장 좋은 결과였지만 **이전에 평가한 개발사진 한 장**이므로 모델 우열·문맥 효과를 일반화하지 않는다. D2가 이번에 나빴다는 이유로 문맥 전체가 해롭다고 결론내리지 않는다. 건물·도로·항구·손패·전체 게임 상태는 과제 밖이다. source-bound 확인 frame과 독립 새 사진이 없어 D4·holdout은 NOT_RUN이다. 추가 호출 없이 마감했다.
