## 제품 목표

사진으로 보드게임의 진행 상태를 기록하고, 나중에 읽기 쉬운 평면 그림·사진·차례·메모를 보며 실물을 다시 펼칠 수 있게 한다. 단순 사진 보관이나 색 아이콘 나열만으로 완료하지 않는다. 장기 대상은 현재 120종과 향후 확장이다. 현재 고쳐야 할 것은 3종에서 드러난 구조·위치·판독 문제이며 새 게임 수를 늘리는 작업이 아니다.

**최신 사용자 결정: 30초에 집착하지 않는다.** 구조·위치·필요한 값·누락 방지를 먼저 다룬다. 5~10%는 오답에 대한 사용자 방향이지 현재 달성한 수치가 아니다.

## 기존 응답과 재현

[manifest.json](manifest.json)은 모든 전달 파일의 SHA256과 출처를 기록한다. 원사진은 리사이즈하지 않았다. 모델 요청의 base64 이미지·키·운영 설정·전체 세션 snapshot은 전달하지 않는다.

- `data/cases/`: 3종 기존 저장본 + 사그라다/로스트 시티 high·medium·low 총 9사례. 현재 실물 값·ID·bbox·출처와 중복 제거한 receipt를 포함한다. `observationReceiptRefs`는 같은 파일의 `receipts` 인덱스다.
- `data/packs/`: 해당 사례에서 사용한 3개 팩. 현재 catalog를 억지로 대입하지 않는다.
- `data/structures/`: 이 커밋의 실제 공통 투영/추정 함수를 적용한 결과. 사람 정답이 아니다.
- `data/effort-metrics.json`: 기존 6응답 수치. **70/80 미대응을 70개 오독으로 해석하지 않는다.** 오푸스가 채점 대응 결함 가능성을 지적했다.
- `data/provisional-answer-key.json`, `data/answer-key-amendments.json`: 사진만 보고 만든 **AI 정답 초안 및 답 노출 후 수정 이력**. 독립 사람 정답으로 사용하지 않는다. 우선 대상 3종만 담았다.
- `evidence/`: 기존 기능 검사 기록·사진 위치 대응·과거 독립 검토 및 감독 판단. 과거 결정과 이번 사용자 결정을 구별한다.

키 없이 오프라인 구조를 다시 계산할 수 있다. 기존 저장소 의존성을 설치한 뒤 실행한다. 새 모델 요청·저장소 서버·포트를 사용하지 않는다.

```sh
npx tsx docs/pro-review-20261113/replay.mts
```

이 명령은 기존 사진을 다시 판독하지 않으며 `data/structures/`와 현재 코드의 계산이 같은지만 확인한다. 사진상 정답 여부는 별도 대조가 필요하다.

## Pro에게 필요한 결과

단순 조언보다 **직접 코드 추적·사진 대조·정답/대응 표 작성·원인 분석·범용 구조 설계·구현 작업 카드**를 요청한다. 어려운 시각 판단과 알고리즘/판독 전략 연구는 Pro가 직접 담당하고, 로컬 구현자는 정확한 계약과 검증 사례를 받아 구현한다. 전체 요청은 [PRO_PROMPT.md](PRO_PROMPT.md)에 있다.

비공개 GitHub 접근이 안 되면 저장소를 공개로 바꾸지 않는다. GitHub 연결로 이 브랜치를 선택하거나 `git archive`로 만든 이 커밋의 ZIP을 첨부한다. 읽지 못한 파일을 검토한 것처럼 답하지 않도록 요청한다.
