# 현재 결과와 근거

2026-11-13. 검토 패킷 작성 단계에서는 제품 수정·새 판독·새 Astra 호출을 하지 않았다. 기존 제품 코드의 함수로 전달9사례를 오프라인 계산했고, 원 입력이 바뀌지 않는지 확인했다. 사람의 새 사진 채점은 하지 않았다.

## 상태를 섞지 않는다

- **VERIFIED / 확인:** 코드·파일·직접 실행으로 확인한 동작 또는 특정 사진/표본의 대조.
- **REPORTED / 전달:** 사용자가 오푸스 결과로 제공한 평가. 검토 출발점이지 모든 항목의 감독 재검증은 아님.
- **INFERRED / 추정:** bbox·역할·반복행 등에서 계산한 위치/묶음. 실제 게임 정답·사람 소유 확정 아님.
- **UNKNOWN / 미확인:** 전체 정확도, 새 사진 일반화, 실제 iPhone Safari 종단 등.

오푸스 최신 평가의 의미: 3종이 판 형태로 보이게 된 개선은 인정하지만, 7W 묶음 정답과 공정한 강도 비교는 아직 남았다. medium의 '70/80 미대응'은 채점기 실패일 수 있으므로 오독으로 해석하거나 high 우승 근거로 쓰지 않는다. [오푸스 원문](OPUS_REVIEW.md).

## 값 오독과 강도 선택 — 아직 결론 내리지 않는다

기존 6회는 같은 두 사진을 각 강도1회, 고정 순서, retry0으로 실행했다. 새로운 고성능/연구 호출을 이 의뢰에서 실행한 것은 아니다.

HTTP preview는 모델/runner의 수신이며 실제 폰에 필요한 색/숫자가 뜨는 시각이 아니다. LC는 face=back만 있는 첫 관측도 옛 지표에 들어간다. 제품은 이후 `firstUsefulValueAt`을 별도로 기록하도록 수정했지만, 과거 첫 poll payload가 없어 이6회의 실제 필요한 첫 값 시각은 복구할 수 없다. 속도 수치를 주목표로 삼지 않는다.

감독의 이전 부분 사진 대조: S high에서 한 주사위를 보라6 대신 노랑4, S low에서 녹색1 대신2, LC high에서 노랑9 대신6으로 읽은 사례가 있다. 전체 오답 분모/완전 정답표는 없다. 오푸스는 S medium 창문18칸 오독0/노랑1개 미상, LC 모든 강도9→6 및 medium/low 추가8을 지적했다. **서로 다른 값 오류·추가 실물·짝짓기 오류를 직접 분리해 다시 판단해야 한다.**

원사진 정답 초안은 Astra가 앱 답을 보기 전에 만든 AI 초안이며 답 노출 후 철회/수정도 있다. 패킷의 `provisional-answer-key.json`과 `answer-key-amendments.json`을 같이 읽는다. 독립 사람 정답으로 승격하지 않는다.

현재 소스 기본값은 `gpt-6.1-terra / high / image detail high / max_output_tokens32768`다. 유지한 과거 결정은 [당시 판단](evidence/prior-effort-decision.md)에 보존했다. 이번에는 그 결정을 방어하는 것이 아니라 더 공정한 대응/위치 비교로 재검토를 요청한다. 이 패킷 작성 시 기본값 변경0.

## 기능 검사와 화면 확인

- 이전 통합 전체 타입 검사 PASS, 전체 테스트 **1389/1389**. 그 뒤 LC/7W JSX 표시 순서의 최소 후속은 관련9/9·범위 타입 검사 PASS. 최종 Vite/Nitro 빌드 PASS. [당시 기록](evidence/verification-before-handoff.json).
- 이번 커밋 전 기존 최종 검증 기록의 제품/직접 테스트16파일 SHA가 현재 파일과 전부 같은지 확인했다. 새 전체 테스트를 반복하지 않았다.
- 현재 화면은 기존 제품 보드/아트/정정 UI를 사용한다. Chrome의844×390/390×844 에뮬레이션에서 값·가로 pan·셀 선택·slot20 정정을 확인했던 스크린샷을 전달한다. [당시 브라우저 기록](evidence/browser-evidence.json).
- 수동 override의 저장/재개 보존은 기존 격리 Store/createApp의 HTTP 재생 근거다. 공유 Site의 정정은 브라우저 내 임시값이며 서버에 저장하지 않는다.
- 실제 iPhone Safari의 촬영→저장→판독→정정→재개, 새로운 사진, 전120종 위치/전체 오답률은 **미확인**.

## 이번 전달에서 확보한 것

실제 코드 커밋, 오푸스 원문, 최신 사용자 우선순위, 정확한 읽기 순서, 원본3사진, 화면5장, 기존9사례의 원 ID/값/geometry/역할/receipt/모델 출력 텍스트, 팩3개, 같은 코드로 계산한 구조9개, 기존6회 수치, AI 정답 초안/수정 이력, SHA manifest와 키 없는 오프라인 재현 명령을 포함했다.

원 운영 세션·API 설정·키·요청 base64·개인 저장소를 넣지 않았다. `providerResponse`의 계정/실행 메타데이터와 중복 scanBundle은 제외하고, 모델 출력 텍스트는 `providerOutputText`로 보존했다. 원본 파일 자체를 수정하지 않았다.

새 연구가 필요한 영역은 **직접 사진 대조한 위치 정답, 공정한 실물 대응, 구조 추론의 범용성/실패 경계, 필요한 판독 범위, 모델 강도 선택**이다. 이를 로컬 구현자에게 다시 미루지 않고 Pro에게 직접 결과물로 요청한다.
